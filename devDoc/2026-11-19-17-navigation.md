## 控制者的决定（Ruling，均待需求方确认或已注明）

台账中的 Ruling 与各任务的决定：

1. **显式刷新越过 P0 去重**（T1）：按钮 / F5 的 `vfs.refresh` 必须绕过扫描进程 2 秒内的 P0 去重，否则列出后立即 F5 会被静默丢弃（用户可见）；代价：每次显式刷新多一次列出。
2. **目录视图 / 工作区总览：单击只选中，双击 / Enter 打开**（T3）：简报第 1 项与第 4 项冲突；设计 2.8 的「目录视图中双击……」是更具体的规则，且列表中单击就导航会使选中无法实现。代价：一行行为改动。
3. **失效链接图标颜色**（T4 → T5）：字符串拼接与 `text-muted-foreground` 冲突，作为 M1-2 的行为回退在 T5 顺手修复，无代价。
4. **抽屉标题单击开合、不选中**（T5）：与「目录单击 = 选中 / 打开」不一致，但符合手风琴习惯；先选中再收起会破坏「用鼠标恢复被挡住的选中」。代价小。
5. **最终修复波的范围**：按用户可见的影响重新分级，四条都修（抽屉重新展开丢选中、后退清空 viewState、同步找不到目标选中祖先、对话框背后的快捷键），代价是少量额外工作。
6. 打开规则（需求方 2026-11-20 已确认，写入设计 2.8）：单击 = 当前标签、中键 / Ctrl+单击 = 新标签、目录双击展开 / 收起、↑↓ 防抖打开并入历史（200ms → 400ms）、取消预览标签、目录视图双击文件 = 当前标签。

各任务的实现决定：

- T1：条目之外的位置同样以工作区段开头（盘符 / 共享根的上一级 = 总览）；后退 / 前进推进（promote）并清除 viewState（最终修复波后改为恢复）；导航到相同 URI 不记入历史；文件条目的上一级 = 总览。
- T2：工作区下拉直接调用 `data/workspace` 的 `activate`；刷新 = tabs-store 的 `refreshSeq` + `host.tabs.onRefresh`，文件标签重新 stat，总览重新取条目；资源树获得焦点时 F5 只刷新树；侧键 `mouseup` 同时 `preventDefault`；路径段隐藏滚动条、滚轮换成横向滚动并滚到末尾。
- T3：设置 `singleClickPreview` 关闭时 ↑↓ 只选中；400ms 防抖对所有键盘选中移动生效（含 → ← 到子 / 父）；同步请求由 `navigation-store` 订阅 tabs-store 发出；目录视图的行没有「在新标签页打开」右键项（中键 / Ctrl+单击 / Ctrl+Enter）。
- T4：`iconFor` 放在 `lib/file-icon-map.ts`（避免 react-refresh lint）；演示文稿用 `PresentationIcon`，`js` 归入代码类；总览用真实文件名而非别名。
- T5：被挡住的选中显示最近的可见祖先（store 不改）；定位按钮在无标签 / 总览 / 条目之外时禁用；根下拖放吸附到最近的同类条目（未分组条目始终在分组之上）；`explorer.spec` 的拖放用例改成两步、目标 README.md、计数 5 → 6。
- 最终修复波：「出错」状态行同样视为尚未加载；folder 插件把选中与滚动位置也写入 viewState（原来只有排序）；快捷键的模态判断用 `OPEN_MODAL_SELECTOR`（依据 Base UI 1.9.0 `DialogPopup` 的 role 与 `hidden`）。

## 记录的问题（延后）

- 标签标题是打开时的快照，条目 / 工作区改名与语言切换后不更新；`host.fs.rootOf` 已不使用。
- `PluginView` 宿主在条目变化时重建；`toResourceInfo` 的 kind 改写。
- `refreshSeq` 在关闭标签时不清理。
- 条目尚未加载时，地址栏短暂显示绝对路径段。
- 资源树按 `sortOrder` 混排分组的子项，工作区总览是「先项后子分组」，两者顺序可能不一致，是否统一待需求方决定。
- 树行 `FS_KIND` 有未使用的 `group` / `folder` 键。
- 切换工作区时的防抖计时器（窗口极短）。
- 慢速共享上：进行中的同步定位不会被用户自己的选中取消（选中会被拉回）；右键选中不取消防抖。
- 抽屉：标题单击不选中；被禁用的工具栏按钮没有悬停提示；「拖进收起分组」没有 e2e；`menu-items` 测试不是先失败后通过。
- `OPEN_MODAL_SELECTOR` 也匹配非模态的 `role=dialog`（应用内目前没有 Popover）。
- 滚动位置保存有 150ms 防抖（切走瞬间的滚动可能丢失）；一直读取失败的目录让选中停留在祖先上；每次选中写入 tabs-store（额外渲染，未测量）。
- 抽屉重新展开时，被选中节点的目录仍在加载，选中可能被抽屉本身覆盖（依赖缓存，最终修复波已缓解，未单独验证）。
