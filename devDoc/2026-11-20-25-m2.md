## 3. 控制者的决定

以下是执行中由控制者（不是需求方）作出的裁定，带理由与出错时的代价；需求方需要确认的在第 4 节。

### 3.1 Task 1 之后推翻 / 修正的裁定

- **Office 启动方式**：设计与计划原写 `Start-Process -LiteralPath`。实测 PowerShell 5.1 的 `Start-Process` 没有 `-LiteralPath`，`-FilePath` 把 `[]` 当通配符（打开了错误的文件）。改用 `ProcessStartInfo`（`UseShellExecute = $true`，`Verb = $env:PCH_VERB`，`FileName = $env:PCH_TARGET`，路径经环境变量传入）。
- **模式表**：去掉 `readOnly ← OpenAsReadOnly`（本机实测以编辑模式打开并产生 `~$` 所有者文件，显示「只读」会误导用户）；`protectedView ← ViewProtected` 改为无条件显示（实测只读），文案如实写「保護ビュー」。依据：「能力以检测为准、不模拟」的原则加实测证据。
- **Excel 的 `/r`**：`readOnly` 只对 `EXCEL.EXE` 经文档记载的 `/r` 开关提供（`LaunchOption.via = 'switch'`），仅当实测确为只读才加入。Task 9 实测成立（标题 Read-Only、无 `~$` 文件）后加入。Word / PowerPoint 不提供只读。
- **开关方式改走 ShellExecute**：Task 9 审查复现了问题——开关方式最初用 `UseShellExecute = $false`，.NET Framework 以继承句柄创建进程，Excel 继承了 Node 给 powershell 建的管道，`execFile` 每次阻塞到 15 秒超时（超时还被当作成功）。推翻原裁定，开关方式也用 `UseShellExecute = $true`（`FileName = exe`、`Arguments`、无 Verb），`/r` 重新实测仍只读（1569 ms 返回）。doc 10.2 / 10.3 同次修正。
- **Excel 的按钮数**：面板为 4 个按钮（編集 / 読み取り専用 / 保護ビュー / 新規作成），因 `protectedView` 无条件显示；任务简报的「三个按钮」以裁定为准。
- **`readOnly` 缺失时的处理**：不模拟、不提供；同事机器上若 `OpenAsReadOnly` 正常，损失只是少一个按钮（见 Q11）。

### 3.2 pch-web 与浏览器视图

- **范围编号**：`s` + `sha256(范围根 URI)` 前 16 个十六进制字符（17 个字符）。偏离全局约束的纯数字写法，因为纯数字主机名会被 Chromium 当 IPv4 解析；代价只是编号形式。
- **范围判定为字符串比较，不做 realpath**：范围内指向范围外的符号链接 / 联接点可被读到。原型阶段接受（创建符号链接需权限，联接点需本机写权限；Edge 打开 `file://` 时同样可读任意文件；做 realpath 校验在映射盘 / 重定向目录下有误判风险）。见 Q13。
- **`file:` 链接被 Chromium 拦截**：`pch-web` 页面中的 `file:` 绝对链接（范围内外）在渲染进程即被拦截，不触发 `will-navigate` / `setWindowOpenHandler`，静默无反应。安全上更严，代价是范围内的 `file:` 绝对链接打不开、范围外也没有提示。e2e 改为断言「视图不离开、无 `file:` 内容加载」；`web.notice outOfScope` 改用其他范围的 `pch-web://` 链接触发。见 Q14。
- **剪贴板权限**：设计 5.3.3 明确把「剪贴板写入是否放行」留给实现者核实后决定。实测拒绝全部权限时 `navigator.clipboard.writeText` 失败，放行 `clipboard-sanitized-write`（请求与检查），其余一律拒绝。审查者的「一律拒绝」摘要漏了这句例外，Important 不成立。见 Q15。
- **PDF 查看器的打印**：打印按钮打开系统打印对话框，期间主进程阻塞（用户主动操作、关闭即恢复），原型接受（打印本为非目标）。见 Q17。
- **视图历史**：每次主框架提交后 `navigationHistory.clear()`；标签历史由应用管理。
- **窗口生命周期**：`bindWebViewOwner` 用 `did-navigate`（不用 `did-start-navigation`，后者在被阻止的导航上也触发，会误销毁全部视图）。
- **网页之间导航复用同一视图**（Task 7 审查）：偏离会丢失 `sessionStorage`，已修；不同查看器之间（如 HTML → Markdown）仍新建视图，`sessionStorage` 不延续。
- **焦点**：`hide` / `release` / `freeze` 时视图持有键盘焦点则交回应用渲染端；`unfreeze` 是否还给视图由渲染端判断（只因 toast 截图且截图时交回过焦点）。

### 3.3 Markdown

- **CSP**：设计 5.4 原值，另在 `img-src` / `style-src` 追加 `http:`（内网系统常为 http；与浏览器视图外部链接白名单含 `http:` 一致）；`script-src` 只允许 `pch-asset:`。
- **frame 封锁**：审查发现 Markdown 中的 `<iframe src="./x.html">` 会加载同源本地 HTML（无 CSP）并执行脚本、改动外壳，违反「Markdown 中的脚本不执行」。提升为 Important 并修复：`frame-src 'none'`、`base-uri 'none'`、`form-action 'none'`。
- **依赖放在 devDependencies**：查看脚本由 vite 打包，运行时不 require；打包后的 asar 中确认没有 mermaid / unified。
- **HTML → Markdown 不复用视图**：按「所有者不同 → release」规则接受。
- **`pch-asset` 的 CORS 头**：外壳是 `pch-web` 源，module 脚本与动态分块按 CORS 请求，响应带 `Access-Control-Allow-Origin: *`（去掉后的对照未做）。

### 3.4 其他

- **Task 6–Task 7 的 `pch-asset` 注册顺序**：Task 6 只注册 `pch-web` 处理器（`pch-asset` 只登记 privileged scheme），Task 8 实现并注册。
- **SDK 重新声明类型**：`WebViewKind` / `WebNotice` / `LaunchCapabilities` 在 SDK 中按结构重新声明（SDK 不依赖 shared，与 `FileStat` 做法相同）。
- **`notify` 放在 `stores/messages-store.ts`**：lint 分层规则不允许 `lib` 依赖 store；i18n 用 `common` 命名空间（项目没有 `shell` 命名空间）。
- **`web.release` 由 `features/preview` 发出**：store 不能调用 IPC。
- **单元测试没有 jsdom**：仓库未安装 jsdom，以注入环境的假 DOM 代替（`createOverlayTracker`、`WebHostEnv`），真实 DOM 由 e2e 覆盖。
- **viewer=null 时同样清除 viewState**：切回自动选择也可能换插件，viewState 不兼容；错了只是丢一次滚动位置。
- **设置残留旧键**：`resolveSettings` 对库中残留的 `launcher.officeDefaultAction` / `launcher.officeExtensions` 直接跳过，不报错、不清理。
- **`<script>` 测试**：Markdown 管线测试断言原始 HTML 中的 `<script>` 元素原样保留，不执行由 e2e 验证。
