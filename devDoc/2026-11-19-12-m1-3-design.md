# M1-3 标签页与目录视图（最低可用原型）：设计

- 日期：2026-11-19
- 状态：需求方指示「尽量优先推进，实现一个最低可用的 prototype；必须要做的按控制者建议推进；所有决定、待确定事项、发现的问题都记录下来」。本文的决定均为控制者按此授权做出，**待需求方事后确认**（第 6 节集中列出）。
- 依据：`doc/` v1.14 第 9 节（插件体系）、第 11 节（标签页）、第 12 节（渲染端）、路线图 M1-3「单窗口 layoutReducer、标签栏与预览模式、最小插件体系与 folder 插件」。

## 1. 目的

在主区域用标签页打开目录与文件，目录以详细信息列表显示（名称、大小、修改时间），完成「资源树导航 → 打开 → 查看」的最小闭环。对文件的操作（用系统应用打开等）只放在预览窗口中（需求方 2026-11-19 的决定）。

## 2. 范围

**做（MVP）**

- 标签：单窗口；打开 / 激活 / 关闭（× 按钮、中键、`Ctrl+W`）；**预览模式**（单击打开时复用当前预览标签，标签标题斜体；双击标签头、或插件调用宿主动作后转为常驻；在标签内滚动、点击、按键不转常驻——控制者 2026-11-19 裁定，取代原「在标签内交互转常驻」的说法，理由：否则在预览标签里浏览文件夹会使其变常驻，预览复用失去意义）；同一 URI 已打开则激活；没有标签时显示欢迎页。
- 资源树：单击 = 预览打开（遵守设置 `explorer.singleClickPreview`，关闭时单击只选中）；双击 / Enter = 常驻打开。条目根、真实目录、文件都可打开；分组、状态行不可。
- 插件体系（最小）：`plugin-sdk` 契约补全到 MVP 需要的部分；渲染端 `PreviewRegistry`（按 kinds / 扩展名 / priority 计分，无匹配落到 fallback）；`PreviewContainer`（每个标签一层 ErrorBoundary + Suspense，插件崩溃只影响自己）；插件懒加载。
- 内置插件（`plugins/builtin` 单个包，doc 5.1）：
  - **folder**：详细信息列表（图标、名称、大小、修改时间、类型），列头点击排序（目录优先），虚拟滚动；面包屑与「上一级」；双击目录在**同一标签内**导航（标签 URI 与标题随之变化），双击文件以常驻标签打开；遵守「显示隐藏文件」；显示「基于缓存 / 已断开」状态；外部变化随 `vfs.changed` 更新。
  - **fallback**：文件信息（名称、路径、大小、修改时间）与动作：在资源管理器中显示、复制路径、**用系统应用打开**（对可执行类扩展名先弹确认）。
- 扫描联动：激活标签中显示的目录按「关注点」处理（每次完整读取，因为目录视图显示大小与时间）。

**不做（推迟，见第 5 节）**：多窗口与弹出、会话保存 / 恢复、标签拖拽排序 / 固定 / 溢出菜单、标签内前进 / 后退历史、列表以外的视图模式（网格）、筛选、text / image / pdf 等其他插件（M2）、第三方插件加载、viewState 持久化。

## 3. 方案（控制者决定）

1. **布局状态**：`TabState` / `layoutReducer`（单窗口子集：`tab/open`（含 `preview` 标志与「复用预览标签」逻辑）、`tab/close`、`tab/activate`、`tab/promote`（预览转常驻）、`tab/navigate`（同标签改 URI）、`tab/viewState`）放在 `packages/shared`（纯函数、单元测试）。M1-3 **由渲染端 zustand store 持有**，不经主进程；M3 多窗口时移到主进程 `LayoutService`（doc 2.5「主进程是唯一事实来源」届时落实）。理由：单窗口没有跨窗口同步需求，省去 IPC 与主进程状态。
2. **插件宿主**：`PreviewHost.fs` 增加 `list(uri)`（返回 `DirectoryListing`，即缓存优先的结果）与 `stat(uri)`；`tabs.open(uri, { preview? })` 与 `tabs.navigate(uri)`；`system.revealInOs` / `copyPath` / `openWithSystem`；`i18n`、`settings.get`（只读需要的键，例如显示隐藏文件）。宿主实现在渲染端（`features/preview`），插件包只依赖 `plugin-sdk` 与 `ui`。
3. **`system.openPath` 恢复为 IPC**（v1.12 删除时注明「将来的预览窗口另行设计」）：只由 fallback 插件调用；渲染端对可执行类扩展名（`.exe .com .bat .cmd .ps1 .vbs .vbe .js .jse .wsf .wsh .msi .msc .scr .lnk .reg .hta .cpl`）先弹确认对话框。
4. **扫描联动**：`vfs.interest` 增加 `tabs: string[]`（当前窗口激活标签中显示的目录 URI，最多 1 个），调度器按「关注点」层处理（每次完整读取、关注点间隔）。
5. **资源描述**：标签保存 `uri` 与 `kind`；打开文件时 `ResourceInfo` 由 `vfs.stat` 取得（大小、时间）；`mime` 暂按扩展名推断或为 null。

## 4. 验证

- 单元：`layoutReducer`（预览复用 / 转常驻 / 去重 / 关闭后激活相邻 / navigate）、`PreviewRegistry` 计分、可执行扩展名判断、folder 的排序与面包屑纯函数。
- e2e：单击预览（复用）、双击常驻、关闭与 `Ctrl+W`、目录视图列出并显示大小 / 时间、双击目录在同标签导航、面包屑返回、双击文件打开 fallback、外部新建文件后目录视图更新。
- 外观：页面级整窗截图（ja 浅色、zh-CN 深色、en 浅色）。
- 测试范围按改动判断（CLAUDE.md）；全量检查在 M1-3 收尾时兜底。

## 5. 推迟事项（记录）

多窗口 / 弹出 / 合并（M3）；会话快照与恢复（M3）；标签拖拽、固定、溢出菜单、右键菜单；前进 / 后退；网格视图、筛选、列宽调整；text / markdown / image / pdf / media / office 插件（M2）；`pcfs://` 协议（M2）；第三方插件（后续）；viewState 持久化（M3）；状态栏显示当前资源路径（如工作量小可随手做）。

## 6. 待需求方确认（控制者的决定）

1. 预览模式与单击 / 双击的行为（第 2 节）。
2. 布局状态 M1-3 放在渲染端、M3 再移到主进程（第 3.1）。
3. 恢复 `system.openPath`，只在 fallback 插件中提供，对可执行类扩展名先确认（第 3.3；扩展名列表）。
4. 目录视图内双击目录在同一标签导航（而不是新开标签）。
5. 激活标签中的目录按关注点处理（每 5 秒 / 10 秒完整读取）。
6. M1-3 只有 folder 与 fallback 两个插件；文本预览（日志查看）等放到 M2——如果原型阶段日志查看很重要，可把 text 插件提前到 M1-3 之后立即做。
