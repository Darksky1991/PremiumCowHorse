## 控制者的全部决定（均待需求方确认）

来自设计第 6 节与各任务的裁定：

1. 预览模式与单击 / 双击：单击 = 预览打开（遵守 `explorer.singleClickPreview`），双击 / Enter = 常驻；键盘 ↑↓ 只移动选中、不打开，Enter 才打开（避免用键盘浏览时预览标签不停更换）。待需求方确认。
2. 布局状态 M1-3 放在渲染端 zustand，M3 多窗口时移到主进程 `LayoutService`。待需求方确认。
3. 恢复 `system.openPath`，只在 fallback 插件（经宿主）提供；对可执行类扩展名先确认。待需求方确认。
4. 目录视图内双击目录在同一标签内导航（不新开标签）。待需求方确认。
5. 激活标签中的目录按关注点处理（每 5 秒完整读取）。待需求方确认。
6. M1-3 只有 folder 与 fallback 两个插件，文本预览放 M2。待需求方确认（见下「待需求方决定」）。
7. **预览转常驻规则（2026-11-19 裁定）**：只有双击标签头、插件调用宿主动作（`tabs.*` / `system.*`）与从树双击 / Enter 打开同一资源才转常驻；在标签内滚动、点击、按键不转常驻（类似 VS Code；否则在预览标签里浏览文件夹就变常驻，预览复用失去意义）。代价：用户想保留预览标签必须双击标签头。设计第 2 节旧说法已更正。待需求方确认。
8. 可执行类扩展名追加 `.pif .scf .msp .jar .appref-ms`（安全相关、代价小）。待需求方确认。
9. 内置插件允许依赖 `lucide-react`（图标）与 `@tanstack/react-virtual`（与渲染端同版本）。待需求方确认。
10. 目录视图不显示「基于缓存（N 前）」，只显示项目数、已断开与读取中；资源树的悬停提示不变。代价：用户在目录视图看不到缓存年龄。待需求方确认。
11. `vfs.interest.tabs` 上限在契约中为 8（设计写「最多 1 个」，实际只发激活标签的目录）；标签目录只在某个条目根之下时进入关注点；不扩展近 / 远层与「积极」范围。待需求方确认。
12. 实现层面的决定：双击用 click 的 `detail >= 2`；预览替换时换新 id、viewState 不沿用；`tab/navigate` 允许与其他标签 URI 重复；同 URI 已打开不更新标题；`tabs.open` / `navigate` 只传 URI、宿主 stat 一次；插件 i18n 以插件 id 为命名空间；崩溃隔离用 e2e 专用崩溃插件而非新增 DOM 测试依赖；插件模块用缓存的 Promise + `use()` 加载（失败保持失败直到重新加载窗口，无重试，有「以文件信息显示」出口）；`system.*` 失败由宿主 toast，Promise 不拒绝；预览 stat `staleTime: 0`；「上一级」可越过条目根；排序存于标签 viewState，同标签导航后重置；面包屑用现有 Button 拼成。待需求方确认。

## 记录的问题

### 可留后续

- 删除工作区后其标签集合仍留在内存的 `byWorkspace`；条目改名 / 删除后标签标题与 URI 不更新（同 URI 重新打开也沿用旧标题）。
- 标签栏 Ctrl+W：焦点在标签栏内时关闭后焦点落到 body；对话框打开或在输入框中输入时也会关闭激活标签（M5 命令面板统一快捷键时再定作用域）。
- `role=tab` 内含 Button（a11y 嵌套交互元素）；目录加载中有两个 `role=status`。
- 确认框重入时遗留一个未决 Promise；`openWithSystem` 无法验证用户手势（第三方插件前需处理）；渲染中的 `useMemo` 副作用；路径转换在两处重复；面包屑根的字符串相等比较。
- `shell.openPath` 无超时；打开失败只提示通用错误文案（需要具体文案要新增错误码与三语）；文件标签的大小 / 时间不实时更新（回到标签时刷新）。
- `fs.subscribe` 依赖 `vfs.changed` 监听器的注册顺序（已加注释）；`formatTime` 等单元测试依赖 Node 内置 ICU 输出。
- 既有的 peer 依赖告警（`@eslint/js@10` 要求 `eslint ^10`），与本里程碑无关。
- 推迟项：多窗口 / 弹出、会话恢复、标签拖拽 / 固定 / 溢出菜单 / 右键菜单、前进后退、网格视图与筛选、其他预览插件（M2）、第三方插件、viewState 持久化。

### 待需求方决定

1. **更多可执行扩展名**：`.url .website .application .inf .chm .settingcontent-ms .psm1 .ws` 目前不触发确认框，是否追加。
2. **同一标签内导航后是否保留排序**：现在 `tab/navigate` 清除 viewState，排序回到按名称升序；是否改为保留（或按目录分别记忆）。
3. **文本预览插件是否提前**：日志查看对运维很重要，是否在 M1-3 之后立即做 text 插件，而不是等 M2。
4. 目录视图是否需要显示缓存年龄：若需要，需要扫描进程在「缓存 → 已确认」时也发一次通知，或渲染端在 `FRESH_MS` 后重新取一次。
5. 滚轮 / 点击是否应转常驻的规则（决定 7）若与预期不符，随时可改回。

## 原型能做什么（试用说明）

1. **从树打开**：在资源树中单击目录或文件，会以「预览」标签打开（标题斜体），再单击另一项会替换这个预览标签；双击或按 Enter 以常驻标签打开；↑↓ 只移动选中。没有标签时主区域是欢迎页。
2. **预览与常驻**：双击标签头把预览标签固定下来；在标签内滚动、点击不会固定。× 或中键关闭标签，`Ctrl+W` 关闭当前标签；←→ / Home / End 在标签间切换。
3. **目录视图里的操作**：显示名称、修改时间、类型、大小；点击列头排序（目录始终在前，再点反转）；双击目录在同一标签内进入，双击文件以常驻标签打开；Backspace / Alt+↑ 或「上一级」回上级目录；面包屑可点击跳转；外部新增 / 删除文件会自动更新；共享断开时显示「已断开」。
4. **用系统应用打开**：点开一个文件（目前没有专用预览的文件都显示「文件信息」），点击「用系统应用打开」；`.exe .bat .ps1 .lnk` 等可执行类会先弹确认框（默认焦点在「取消」）。同页还有「在资源管理器中显示」与「复制路径」。
