## 原型能做什么（试用说明）

1. **从树打开**：在资源树中单击目录或文件，会以「预览」标签打开（标题斜体），再单击另一项会替换这个预览标签；双击或按 Enter 以常驻标签打开；↑↓ 只移动选中。没有标签时主区域是欢迎页。
2. **预览与常驻**：双击标签头把预览标签固定下来；在标签内滚动、点击不会固定。× 或中键关闭标签，`Ctrl+W` 关闭当前标签；←→ / Home / End 在标签间切换。
3. **目录视图里的操作**：显示名称、修改时间、类型、大小；点击列头排序（目录始终在前，再点反转）；双击目录在同一标签内进入，双击文件以常驻标签打开；Backspace / Alt+↑ 或「上一级」回上级目录；面包屑可点击跳转；外部新增 / 删除文件会自动更新，显示中的目录被删除时显示「找不到」。**共享断开**（最终审查修复后的实际行为）：目录标签不等 stat，立即显示缓存的列表；扫描进程判定该共享断开后（一次访问失败或超时，网络默认 10 秒；判定之前显示的是上次的缓存，状态行没有提示），状态行显示「已断开（基于缓存）」，没有缓存的目录显示「无法访问该位置」与「重试」；恢复在线后自动重新列出。文件标签在断开期间不 stat，只显示文件名与「已断开（重新连接后显示）」。以上只在本地磁盘上以注入事件的方式验证，未在真实 SMB 上验证。
4. **用系统应用打开**：点开一个文件（目前没有专用预览的文件都显示「文件信息」），点击「用系统应用打开」；`.exe .bat .ps1 .lnk` 等可执行类会先弹确认框（默认焦点在「取消」）。同页还有「在资源管理器中显示」与「复制路径」。

页面级截图（ja 浅色、zh-CN 深色、en 浅色的欢迎页 / 目录视图 / fallback）已目视确认；系统级整窗截图待补拍。

删除检测选择在扫描进程中通知（而不是让目录视图订阅父目录）：目录视图读的是 TanStack Query 的缓存，父目录的 `vfs.changed` 不会让子目录的查询失效，只订阅父目录仍会拿到旧列表；另外父目录先确认时子目录的缓存行已被删除，之后读取子目录得到「不存在」也不再有事件。通知只发给按关注点处理的目录（标签中显示的就在其中），数量有上限；之后的读取再失败不通知，不会形成「通知 → 重新列出 → 失败 → 通知」的循环（单元测试断言）。

### 发现的问题（未处理）

- `host.tabs.open`（目录视图双击文件）仍先 stat 取得类型与标题：共享无响应时要等到超时后才提示错误。目录列表中已有类型，可像 `navigate` 一样接受类型提示。
- 扫描进程判定断开之前（网络默认 10 秒内），无响应共享上的目录视图显示缓存内容（`state` 为 cached），状态行没有任何提示。
- 可达状态任何一个共享变化都会重建所有标签的宿主，显示中的目录视图都重新列出一次（读缓存；不新鲜时扫描进程排一次 P0）。
- 类型提示导航的标题取 URI 的最后一段，与 stat 的名称可能不同（例如 UNC 共享根 `file://srv/share` 的标题为 `share`）。
