# 文件名搜索界面：设计

- 日期：2026-11-19
- 状态：草案。需求方未参与讨论；按需求方睡前的授权（「先自行考虑并给出建议并记录下来，先按建议推进，等我醒了再重新跟我确认」）由控制者先行决定，**全部条目待需求方确认**（见第 6 节）。
- 前置：[01 目录刷新与缓存引擎](./2026-11-19-01-refresh-cache-design.md)（索引 `index.db` 的 `entries` / `entries_fts`）

## 1. 意图

需求方：缓存除了让显示更快，「最大用途就是希望能搜索了。windows 自带的搜索太慢了，希望可以像 everything 一样。不用达到和其一样的速度，比 windows 快就行，特别是 UNC」。搜索范围与刷新级别绑定（需求方决定）：能搜到的是按级别扫描过、或开启了「建立索引」的目录中的内容。

## 2. 目标 / 非目标 / 反目标

- 目标：在当前工作区的缓存中按文件名即时搜索（输入即出结果，常见规模下 < 200ms 返回首屏），结果可定位到资源树。
- 非目标：文件内容搜索；正则；跨工作区搜索；搜索时实时访问文件系统（搜索只查缓存）。
- 反目标：搜索触发对文件系统的扫描；搜索阻塞窗口；结果看起来是「实时的」却实际过期而不加说明。

## 3. 方案（控制者决定）

### 3.1 入口与布局

- 活动栏新增「搜索」视图（lucide `Search` 图标），位于资源管理器之下；`Ctrl+Shift+F` 打开并聚焦搜索框（`Ctrl+F` 留给将来的预览窗口）。
- 侧栏视图结构：

```
┌ 搜索 ────────────────────────┐
│ [🔍 文件名…              ] [×] │
│ (全部) 文件  文件夹            │  ← 类型筛选（切换组）
│ 1,234 项 · 基于缓存（3 分钟前更新） │
├──────────────────────────────┤
│ 📄 設計書_第10章.xlsx          │
│    案件A › 設計書 › 第10章      │  ← 条目标签 + 相对路径
│ 📁 第10章                      │
│    案件A › 設計書               │
│ …（虚拟滚动）                   │
└──────────────────────────────┘
```

### 3.2 匹配规则

- 只匹配名称，不区分大小写（含全角 / 半角的区分：不做归一化，按原样匹配；将来可加）。
- 空格分隔的多个词 = 全部包含（AND）。
- `*`（任意长度）与 `?`（单个字符）通配；含通配符的词按通配匹配整个名称，不含的词按「包含」匹配。
- 3 个字符以上的「包含」词走 FTS5 trigram 索引（`MATCH`）；不足 3 个字符的词与通配词在候选集上用 `LIKE` / `GLOB` 过滤。所有词都不足 3 个字符时直接在 `entries` 上 `LIKE`（可能较慢，结果上限保护）。
- 遵守「显示隐藏文件」设置。
- 范围：当前工作区所有 folder 条目根之下的缓存（按 URI 前缀）；file 条目自身也参与匹配。

### 3.3 执行

- 查询在扫描进程中执行（不阻塞主进程），经 IPC `search.query({ text, kind, limit })` → `{ items, total, truncated, indexedAt }`。输入防抖 150ms；新查询取消旧查询（同一 requestId 机制）。
- 结果上限 1000 条（`truncated` 时显示「只显示前 1000 项，请输入更多关键词」）；按「名称以关键词开头」优先，其次名称排序（`Intl.Collator('ja', { numeric: true })` 在渲染端排序首屏）。
- `indexedAt` = 范围内目录最早的 `checked_at`，显示为「基于缓存（N 分钟前更新）」；范围内存在从未扫描完的根时追加「部分目录尚未扫描」。

### 3.4 结果操作

- 单击 / Enter：在资源树中定位（切到资源管理器视图、展开祖先、选中并滚动到该行）。资源树只做展示（需求方决定），打开文件随将来的预览窗口。
- 右键菜单：在树中定位、在资源管理器中显示、复制路径、复制 URI（与资源树一致，不含「用系统应用打开」）。
- 键盘：搜索框中 ↓ 进入结果列表；结果列表 ↑↓ 移动，Enter 定位，Esc 回到搜索框。

### 3.5 状态

- 空输入：显示说明「在当前工作区的缓存中按文件名搜索。范围取决于各条目的刷新级别与『建立索引』。」
- 无结果：「没有找到」+ 同上的范围说明。
- 扫描进程不可用（降级模式）：显示「搜索不可用」及原因。

## 4. 验证

- 单元：查询解析（AND、通配、短词）、SQL 生成、前缀范围、隐藏过滤、上限与排序。
- 集成：在 `index.db` 中灌入 10 万条名称，测 3 字以上 / 短词 / 通配的耗时（记录到 devDoc）。
- e2e：输入 → 结果 → Enter 定位到树中的行；类型筛选；无结果；`Ctrl+Shift+F`。
- 截图：浅色 / 深色、ja / zh-CN / en 至少各一张整窗截图。

## 6. 待需求方确认（控制者的决定）

1. 入口在活动栏的独立视图，快捷键 `Ctrl+Shift+F`。
2. 只搜当前工作区；只匹配名称；AND + `*` / `?` 通配；不做全角半角归一化。
