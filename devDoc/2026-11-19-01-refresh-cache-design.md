# 目录刷新与缓存引擎：设计

- 日期：2026-11-19
- 状态：草案。第 1–6 节与需求方讨论后写成；第 7 节为需求方睡眠期间控制者的决定（需求方授权先按建议推进），待需求方确认
- 分支：`feat/m1-workspace`（M1-2 之后、M1-3 之前）
- 关联：[08 M1-2 资源树](./2026-11-18-08-m1-2-explorer.md) 的「待需求方决定」与手动确认结果；架构文档 [`doc/`](../doc/PremiumCowHorse-架构设计方案.md) v1.8 的 7.1、7.2、8.2、8.3、13 节（实现时同步改写）
- 后续项目：文件名搜索界面（另行设计，复用本项目的索引）

## 1. 意图

资源树要「尽量快地显示最新内容」，同时遵守原则：**应用不变动文件和目录的数据：不写入、不新建、不删除、不移动、不改名，不长期持有句柄（不能妨碍用户改名或移动）。读取时由系统自动更新的元数据（如访问时间）不在此列。**（原表述为「应用本身不得对文件系统产生任何影响」，2026-11-19 需求方改为此表述）。M1-2 用 `fs.watch` 做实时监听，实测会锁住被展开目录的上级目录（无法改名 / 移动），违反这一原则，因此改为「扫描 + 缓存」：

- 目录内容缓存在本地 SQLite，展开时先显示缓存、再在后台确认，网络上的大目录不再每次等待。
- 按「离用户关注点的远近」安排扫描的优先级和频率，没变化的目录不重复枚举。
- 缓存同时是文件名索引，供后续的搜索项目使用（目标：比 Windows 自带搜索快，尤其是 UNC）。

## 2. 目标 / 非目标 / 反目标

**目标**

1. 去掉 `fs.watch`；任何时刻都不长期持有目录句柄。
2. 目录列表缓存到 SQLite；展开、选中、切回窗口时先显示缓存，确认后再更新。
3. 扫描策略分 4 级（全部 / 积极 / 默认 / 消极），全局默认按位置类型区分，每个根条目可单独设置；另有「建立索引」开关。
4. 按优先级调度：关注点附近优先、热点目录提升、远处低频低功耗；网络位置按服务器限制并发。
5. 超时可设置；连不上时显示「断开」图标，继续显示缓存内容，后台按退避重试。
6. 用 Windows 原生目录枚举（koffi）一次取得名称、大小、时间、属性；隐藏文件按属性判断。
7. 顺带完成：拒绝临时文件拖入、去掉「用系统应用打开」、拖入时按松手位置插入。
8. 缓存的表结构从一开始就支持按文件名快速搜索（FTS5 trigram，已实测可用，见 4.3）。

**非目标**

- 搜索界面（下一个项目）。
- 设置页面（M5「设置页完善」）。本项目只定义设置键与默认值；条目级的设置在右键菜单中提供。
- FTP / SFTP / 未挂载 SMB 的实现（M4）；本项目只定好它们接入时的检查方式（见 4.4）。
- 「已打开的目录标签」参与调度（随 M1-3 加入，接口在本项目预留）。

**反目标**（技术上能工作也算失败）

- 应用造成文件系统的任何变化，或让用户在资源管理器中的改名 / 移动 / 删除失败（枚举期间毫秒级的句柄占用除外，见 4.2）。
- 扫描导致窗口卡顿。
- 给共享文件服务器带来明显的持续负载。
- 断开的网络位置拖慢其他位置，或每次切回窗口都卡在「加载中」。

## 3. 约束

- Windows 为主；`sandbox: true`、`contextIsolation`；IPC 仍只有 `pch:invoke` / `pch:event`，契约在 `packages/shared/src/ipc/contract.ts`。
- 新依赖 **koffi**（需求方已同意）：当前最新 3.3.8（2026-11-13）。有安装脚本（`cnoke` 预编译），各平台二进制在 `@koromix/koffi-*` 可选依赖中；需要在 `pnpm-workspace.yaml` 的 `allowBuilds` 中声明。安装前按 TVM 规则确认不下载额外的可执行程序。
- `node:sqlite`（Electron 内置 Node 24.22.3，SQLite 3.54.1）：已实测支持 FTS5 的 `trigram` 分词，`設計書_第10章.xlsx` 能用「第10章」查到。同步 API，所以重活不能放在主进程。
- electron-vite 支持 `?modulePath` 导入（`node_modules/electron-vite/node.d.ts`），用于打包 utilityProcess 的入口。
- **目录修改时间的语义（已在本机 NTFS 实测）**：只在直接子项新增、删除、改名时变化；子文件内容变化（如日志追加）、孙目录中的变化都**不会**改变它。

## 4. 方案

### 4.0 考虑过的实现方式（需求方选择方式二）

| 方式                                             | 要点                                                                   | 取舍                                                                                             |
| ------------------------------------------------ | ---------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| 一：全部在主进程                                 | 调度、koffi 枚举、缓存写入都在主进程，共用 `pch.db`                    | 改动最少；但同步 SQLite 的成批写入与以后的搜索查询会阻塞主进程，窗口与所有 IPC 跟着卡            |
| **二：独立扫描进程（`utilityProcess`）**（采用） | 调度、枚举、缓存库 `cache.db` 都在后台进程，主进程只转发请求与变化通知 | 重活与慢网络不影响窗口；缓存与工作区数据分离，可随时清空重建；进程可重启。代价：多一层进程间通信 |
| 三：主进程的 worker_threads                      | 分工同方式二，但用线程                                                 | 隔离弱于进程（崩溃可能带倒主进程），原生模块在线程中加载需另外确认；省下的不多，风险更多         |

### 4.1 进程结构

```
渲染端（每个窗口）
  └─ vfs.list / vfs.interest / vfs.refresh …（IPC，契约不变的传输）
主进程
  ├─ VfsService（保留：stat、条目添加时的校验等一次性调用）
  └─ ScannerClient ──MessagePort── 扫描进程（utilityProcess，serviceName 'pch-scanner'）
                                     ├─ Scheduler（优先级队列、并发与节流、退避）
                                     ├─ Enumerator（koffi：FindFirstFileExW；失败时回退 fs）
                                     └─ Cache（node:sqlite，userData/cache/index.db）
```

- 扫描进程随主进程启动；意外退出时主进程记录日志并重启（连续失败时停止重启，树退回「直接枚举、不缓存」的降级模式并在日志中说明）。
- 主进程与扫描进程之间的消息用 zod 校验（与 IPC 契约同样的做法），类型定义放在 `packages/shared`。
- 主进程里的 `VfsService` 保留 `stat` / 一次性 `list`（条目添加的校验、降级模式用），删除全部监听代码。

### 4.2 读目录（Enumerator）

- 用 koffi 调用 `FindFirstFileExW(path\*, FindExInfoBasic, …, FIND_FIRST_EX_LARGE_FETCH)` / `FindNextFileW` / `FindClose`，一次枚举得到每个子项的名称、属性、大小、修改时间（`ftLastWriteTime`）。koffi 的异步调用在线程池执行，不阻塞扫描进程的事件循环（具体 API 以安装后的类型定义与文档为准）。
- 句柄只在一次枚举期间持有，结束（含出错、取消）立即 `FindClose`。枚举期间（毫秒级，网络上的大目录可能更长）恰好改名可能失败，这是读取目录本身不可避免的，在 doc 中写明。
- **最后访问时间**（已在本机实测：Windows 11，`fsutil behavior query disablelastaccess` = 2「System Managed, ENABLED」）：枚举目录会更新**该目录自身**的最后访问时间（NTFS 只在与旧值相差超过约 1 小时时写入）；子文件的访问时间不变（只有读取内容才变）。为遵守「不影响文件系统」，枚举时先尝试以 `FILE_LIST_DIRECTORY | FILE_WRITE_ATTRIBUTES` 打开目录（`CreateFileW` + `FILE_FLAG_BACKUP_SEMANTICS`），用 `SetFileInformationByHandle` 把 LastAccessTime 设为 -1（文档化的「此句柄后续操作不更新访问时间」），再在同一句柄上枚举（`GetFileInformationByHandleEx` 的目录信息类）。拿不到写属性权限（只读共享等）或 -1 不生效时回退到普通枚举，并在 doc 中写明「此位置的目录访问时间会被系统更新」。首个任务实测本地是否生效、网络上是否生效（不能实测则写明未验证）。此项待需求方确认（见第 7 节）。**【2026-11-19 需求方决定：全部去掉该保护，枚举一律只读打开，原则改为新表述（见文首）；本条处理方式作废，保留为历史。】**
- 属性（与资源管理器一致）：有 `FILE_ATTRIBUTE_HIDDEN` → `hidden: true`（含 HIDDEN + SYSTEM 的受保护系统文件，本项目只有一个「显示隐藏文件」开关，二者一起受它控制）；只有 `FILE_ATTRIBUTE_SYSTEM`、没有 HIDDEN 的项照常显示（例如带 `desktop.ini` 的自定义图标文件夹）；`FILE_ATTRIBUTE_REPARSE_POINT`（符号链接 / 目录联接）→ `kind: 'symlink'`，目标类型沿用现有做法（对链接额外解析一次）。
- 目录自身的修改时间用 `GetFileAttributesExW` 取得（一次调用，不枚举）。
- 映射盘符：`GetDriveTypeW` 返回 `DRIVE_REMOTE` 时按网络位置处理（顺带让「复制路径」可以转换为 UNC，用 `WNetGetConnectionW`；是否在本项目做由实现者决定，不做则留在遗留事项）。
- koffi 加载失败（例如非 Windows、二进制缺失）时回退到现在的 `fs.readdir` + `lstat` 实现，隐藏文件退回按 `.` 开头判断，日志记一条警告。

### 4.3 缓存（`index.db`）

位置 `userData/cache/index.db`，与 `pch.db` 分开（可随时删除重建）。表结构示意（实现者可调整列名，含义须保留）：

```sql
CREATE TABLE dirs (
  uri          TEXT PRIMARY KEY,
  parent_uri   TEXT,              -- 根目录为 NULL
  dir_mtime    INTEGER,           -- 上次枚举时目录自身的修改时间
  listed_at    INTEGER,           -- 上次完整枚举的时刻
  checked_at   INTEGER,           -- 上次检查（比较 dir_mtime 或枚举）的时刻
  state        TEXT NOT NULL,     -- 'ok' | 'not-found' | 'denied' | 'unreachable'
  error_code   TEXT,
  visited_at   INTEGER,           -- 热点计算用
  visit_score  REAL NOT NULL DEFAULT 0
);
CREATE TABLE entries (
  dir_uri  TEXT NOT NULL REFERENCES dirs(uri) ON DELETE CASCADE,
  name     TEXT NOT NULL,
  kind     TEXT NOT NULL,         -- file | directory | symlink
  target   TEXT,                  -- symlink 的目标类型
  size     INTEGER NOT NULL,
  mtime    INTEGER NOT NULL,
  hidden   INTEGER NOT NULL,
  PRIMARY KEY (dir_uri, name)
);
-- 搜索用（下一个项目使用；本项目建立并维护）
CREATE VIRTUAL TABLE entries_fts USING fts5(name, content='entries', tokenize='trigram');
```

- **变化检测**（目的：尽量少做不必要的枚举）：
  - 「检查」一个目录 = 取目录自身的修改时间，与 `dir_mtime` 相同则认为名称列表没变，跳过枚举，只更新 `checked_at`；不同（或从未枚举）则完整枚举，与缓存逐项比较，有差异才写库并通知。
  - 目录修改时间反映不了子文件的大小 / 时间变化，也反映不了孙目录的变化。因此：**关注点目录**（选中的目录，或选中文件所在的目录）与**可见的已展开目录**每次检查都直接完整枚举（树上看得到，且一次枚举的成本与一次 stat 接近）；其他目录先比较修改时间；每个目录无论如何在 `listed_at` 超过一定时长（实现者决定，建议 1 小时级）后做一次完整枚举，兜底修改时间粒度与例外情况。
  - 子目录不能因父目录没变而跳过：每个目录按自己的时刻表检查。
- 缓存写入只在内容有差异时发生；通知粒度为目录（`uri`）。
- **清理**：启动时与 `workspace.changed` 后，删除不在任何工作区任何 folder 条目之下的目录缓存。缓存占用与「清空缓存」通过 IPC 提供，界面随 M5 设置页。

### 4.4 位置类型

| 类型                    | 识别                               | 检查方式                                                        | 并发                                        |
| ----------------------- | ---------------------------------- | --------------------------------------------------------------- | ------------------------------------------- |
| 本地磁盘                | 盘符且 `GetDriveTypeW` 不是 REMOTE | 目录修改时间 + 枚举（4.3）                                      | 同时最多 4 个枚举                           |
| 网络路径（UNC、映射盘） | URI 带主机名，或映射盘             | 同本地；注意 Windows SMB 客户端自身的目录缓存约 10 秒（未实测） | 每台服务器同一时刻 1 个；低优先级之间有停顿 |
| FTP（M4）               | `ftp://`                           | 目录修改时间不可靠 → 检查 = 重新列出                            | 每个连接 1 个（连接池的列目录客户端）       |
| SFTP（M4）              | `sftp://`                          | 列目录一次带回全部属性；目录修改时间同 POSIX 语义               | 每个连接 1 个                               |

位置类型决定：默认级别、刷新间隔的默认值与下限、超时、并发。

### 4.5 扫描级别与范围（已被第 8 节取代）

术语：**关注点** = 当前窗口选中节点所在的目录（选中目录本身；选中文件时为其父目录；选中条目根时为该根）。范围按关注点所在的根条目计算。

| 级别 | 范围（在关注点所在的根条目内）                                                                                                                             |
| ---- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 消极 | 关注点目录。选中、切回窗口时立即检查；停留不动时每隔「刷新间隔」检查一次                                                                                   |
| 默认 | 消极 + 关注点路径上的各级祖先 + 关注点的子目录 + 兄弟目录                                                                                                  |
| 积极 | 默认 + 以关注点为中心上下 N 级（`refresh.activeDepth`，默认 3）：关注点向上 N 级的祖先 A，A 之下深度不超过「关注点深度 + N」的所有目录（含叔伯、侄目录等） |
| 全部 | 根条目下的所有目录                                                                                                                                         |

此外，无论级别：

- 当前工作区所有 folder 条目的根目录、所有可见的已展开目录：按「默认」对象对待（展开 / 显示时先给缓存，再检查一次）。
- **热点目录**：近期访问（选中、展开）多的目录按访问记录衰减计分，取前 K 个（实现者决定，建议 20）按「默认」对象对待（目录本身 + 子目录）。
- **建立索引**：条目或其下任意目录可开启；开启的目录及其全部子目录按「默认」对象对待、但用最低优先级，后台慢慢扫完；用于搜索。
- 级别：每个 folder 根条目可单独设置（右键菜单），未设置时跟随全局默认：本地「积极」、网络「默认」。
- 只调度**当前工作区**（多窗口时为各窗口的工作区之和）；其他工作区的缓存保留，切回时先显示缓存再检查。

### 4.6 优先级、间隔与节流（已被第 8 节取代）

| 优先级 | 对象                                                               | 时机 / 间隔                                                                  |
| ------ | ------------------------------------------------------------------ | ---------------------------------------------------------------------------- |
| P0     | 用户动作：展开、选中、F5 / 刷新、窗口重新获得焦点时的关注点        | 立即；同一目录 2 秒内去重                                                    |
| P1     | 关注点所在根条目的「默认」范围、根目录、可见的已展开目录、热点目录 | 刷新间隔：本地默认 5 秒，网络默认 30 秒（下限 10 秒）                        |
| P2     | 级别高于「默认」时多出的范围（积极 / 全部）、建立索引的目录        | 低频：默认 10 分钟一轮；同一服务器的两个目录之间至少停顿 200ms（实现者可调） |

- **「可见的已展开目录」分两种**：视口内（虚拟滚动实际渲染的行范围，含 overscan）有行的已展开目录 → 每次检查完整枚举（P1）；滚出视口的已展开目录 → 只比较目录修改时间（P1 间隔，一次往返），回到视口时立即完整枚举一次（P0）。渲染端按 300ms 防抖发送 `vfs.interest`（滚动停止后发送）。
- **并发**：网络位置按主机名分组（DFS 命名空间 `\\域名\dfs` 视为一台，不解析实际目标服务器——这会让同一命名空间下的后台扫描串行，属于「慢而不打扰」，写入已知限制）；每台主机 P1 / P2 同时 1 个枚举；**P0（用户动作）不排在后台扫描之后**，每台主机另有 1 个 P0 专用并发。
- 窗口失去焦点或最小化时，P1 暂停，只保留 P2 的低频扫描；重新获得焦点时关注点进入 P0。
- 队列按 URI 去重，每个目录记下次到期时刻；新的关注点出现时重新计算范围，离开范围的目录从 P1 移除（缓存保留）。
- 全部级别下的大型网络根目录，一轮可能需要数小时（例如 10 万个目录 × 200ms），这是预期的「慢而不打扰」。

### 4.7 超时与断开

- 超时（设置，秒）：本地默认 5、网络默认 10（下限 10）。**计时方式是「没有进展的时间」**，不是整次枚举的总时长：从发出调用到拿到第一批结果、以及两批结果之间，超过超时即判定超时。几万项的大目录只要在持续返回结果就不会超时。
- **「断开」只由探测判定**：目录自身的属性查询（`GetFileAttributesExW`，一次往返）或枚举的第一批结果超时 / 网络类错误 → 判定该位置断开；枚举中途超时只算该目录本身的错误（错误行，按 P2 间隔重试），不影响同一服务器的其他目录。
- 错误分类：
  - `FS_NOT_FOUND`：目录不在了 → 缓存删除该目录及其子树，树上显示现在的「找不到」错误行（条目根）或随父目录消失（子目录）。
  - `FS_PERMISSION`：显示现在的错误行，按 P2 间隔重试。
  - 探测超时 / `FS_UNAVAILABLE` 等网络类错误：该**共享**（`\\主机\共享名`；映射盘按其对应的共享）标记为断开 → 该共享上的所有扫描暂停；树中属于它的根条目显示「断开」图标，其下内容照常显示缓存（浅色，悬停显示最后更新时间）；后台按 30 秒、1 分钟、2 分钟……最长 5 分钟退避重试；切回窗口不触发重连、不显示「加载中」；F5 / 「重试」立即尝试一次；连上后清除断开状态并检查关注点。
  - 本地磁盘（如拔掉的 USB 盘）同理按「卷」标记。
- 没有缓存且连不上：显示错误行（带断开图标），与现在一致。

### 4.8 渲染端接口（IPC）

- `vfs.list({ uri })` → `{ items, state: 'fresh' | 'cached' | 'offline', checkedAt }`：有缓存立即返回缓存（并让调度器以 P0 检查），没有缓存则立即枚举后返回。
- `vfs.interest({ focus: uri | null, visible: uri[] })`（整体替换，按窗口）：取代 `vfs.watch`，告诉调度器关注点与可见目录。
- `vfs.refresh({ uris })`：F5 / 重试 / 刷新按钮，P0。
- 事件 `vfs.changed { uri }`：缓存内容有差异时才发；`vfs.reachability { host, state }`：断开 / 恢复。
- 渲染端目录查询改回 `staleTime: Infinity`，不再依赖 focus refetch（窗口焦点由主进程的窗口事件告知调度器）；收到 `vfs.changed` 时让对应查询失效（读缓存，很快）。
- 删除：`vfs.watch`、`VFS_WATCH_MAX`、`createWatchScheduler`、`useWatchDirectories`、`DIRECTORY_STALE_MS` 等监听相关代码，以及设置 `remote.pollIntervalSec`。

## 7. 待需求方确认（控制者在需求方睡眠期间的决定）

需求方睡前授权：「如果有问题你可以先自行考虑并给出建议并记录下来，先按建议推进，等我醒了再重新跟我确认」。以下是写完设计后由实现者视角审阅提出、由控制者决定的事项，以及其他由控制者补充的决定：

2. **断开的单位是共享**（`\主机\共享名`），不是整台主机。并发上限按主机名分组；DFS 命名空间视为一台主机，不解析实际目标服务器（已知限制：同一命名空间下的后台扫描串行）。

4. **P0（用户动作）每台主机另有 1 个专用并发**，不排在后台扫描之后。
5. **隐藏判定与资源管理器一致**：有 HIDDEN 属性即隐藏；只有 SYSTEM 属性的项照常显示（例如自定义图标的文件夹）。不再把 `.` 开头的名称视为隐藏。
6. **目录的最后访问时间**：已实测确认，枚举会更新目录自身的最后访问时间。处理方式：尝试「此句柄不更新访问时间」的打开方式（需要写属性权限）；做不到时回退到普通枚举，并在 doc 中写明。**请确认**：回退时这种系统自身的元数据更新是否可以接受；如果不能接受，网络位置的「全部」与「建立索引」需要加限制或提示。
   - **需求方决定（2026-11-19）**：全部位置都去掉访问时间保护，一律以只读方式打开目录枚举（不再请求写属性、不设置 LastAccessTime = -1）；原则改为新表述（见文首）。原因：写属性访问会在开启访问审核的文件服务器上留下记录，安全软件可能视为可疑；UNC 上访问时间早已被他人不断更新，保护没有意义；变化检测用修改时间，与访问时间无关。上述「尝试写属性打开」的处理方式作废，仅保留为历史。

8. **右键菜单保留「在资源管理器中显示」「复制路径」「复制 URI」**；「用系统应用打开」与 `system.openPath` 通道删除。

## 8. 第二版：缓存策略（2026-11-19，需求方确认，取代 4.5、4.6 与 4.3 的「1 小时兜底」）

需求方的反馈：扫描与缓存的根本目的只有两个——**展开文件树时立刻显示**（不再一项一项慢慢冒出来），以及**文件检索**。缓存可以有过时信息，重点是发现过时后更新；频繁扫描会造成持续负荷，网络盘完整扫一遍可能要几个小时，因此**不做按轮次的定期扫描，缓存不设过期 / 失效时间**，只在发现信息已经错误时更新或删除。后台扫描改为一个综合多种因素的优先级队列，平缓、低功耗地进行。

### 8.1 名称

「全部 / 积极 / 默认 / 消极」改称**缓存策略**（ja「キャッシュ方針」、zh-CN「缓存策略」、en「Cache strategy」）；级别名不变。代码标识符、设置键、IPC 通道、数据库列一并改名（见计划）。

### 8.2 两种机制并行，都不设过期

**(1) 关注点周边的定期确认**（按远近分三层；前台操作时也照常进行；所有窗口失焦时暂停，重新获得焦点时立即确认关注点）

| 层     | 对象                                                                     | 本地   | 网络   | 确认方式                                      |
| ------ | ------------------------------------------------------------------------ | ------ | ------ | --------------------------------------------- |
| 关注点 | 选中的目录（选中文件时为其所在目录）                                     | 5 秒   | 10 秒  | 每次完整读取（文件大小 / 时间的变化也能发现） |
| 近     | 父目录、子目录、兄弟目录；视口内可见的已展开目录                         | 30 秒  | 1 分钟 | 比较目录修改时间，变了才完整读取              |
| 远     | 祖父以上的祖先、叔伯目录；滚出视口的已展开目录；当前工作区各条目的根目录 | 2 分钟 | 5 分钟 | 同上                                          |

- 「消极」只确认关注点一层；「默认」及以上确认三层。
- 网络位置的间隔不低于 10 秒（Windows SMB 客户端自身约 10 秒的目录信息缓存，未实测）。

**(2) 后台缓存队列**（不分轮次；一次只做一件事；平缓、低功耗）

- 节奏：同一位置组（本地按卷、网络按主机）后台同时只确认 1 个目录；每确认完一个先休息：本地约 0.5 秒、网络约 2 秒；用户正在操作时（最近 10 秒内关注点 / 可见范围有变化）休息时间加倍。前台操作时不完全暂停。窗口失焦时照常进行。
- 优先级（从高到低）：
  1. 「建立索引」的目录（及其子树）中还没有任何信息的目录；
  2. 缓存策略范围内还没有任何信息的目录；
  3. 热点目录中最久没确认过的；
  4. 其余范围内目录中最久没确认过的。
- 缓存策略决定哪些目录进入队列：消极 = 只有「建立索引」的目录；默认 = 再加热点目录；积极 = 再加关注点上下 N 层（`activeDepth`，默认 3）的范围；全部 = 根条目下的所有目录。
- 「没有任何信息」= 已经从父目录的列表中得知它存在、但自身还没被完整读取过；因此新目录的发现天然由上而下，已知目录的确认则每个目录独立排队。
- 队列每次从缓存中按上述顺序选出下一个目录（不在内存中展开整棵树），确认方式：没有信息的完整读取，其余比较修改时间、变了才完整读取。

### 8.3 发现过时就更新

时机：展开、选中、切回窗口、F5 / 重试、上面两种机制的确认、**从搜索结果定位时发现目录或文件已不在**（顺带确认该目录）。一律只更新或删除出错的那一部分；目录不存在时连同子树的缓存一起删除。

### 8.4 去掉的

- 「距上次完整读取超过 1 小时强制完整读取」（实际上是过期时间）；
- 后台「每 N 分钟一轮」（`refresh.backgroundIntervalMin`）与单一的 P1 刷新间隔（`refresh.intervalSec.*`）。

### 8.5 已知盲区（需求方已接受）

目录修改时间只反映直接子项的增删改名；工具把时间改回去（robocopy `/DCOPY:T`、rsync `-t`、解压、备份还原）、时间精度不足（FAT32 2 秒等）时变化会被漏掉。不设过期时间，因此这类过时信息保留到该目录成为关注点（完整读取）或用户按 F5 为止。
