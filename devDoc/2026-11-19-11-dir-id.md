## 两个设计决定

1. **`AUTOINCREMENT`**（计划写的是 `INTEGER PRIMARY KEY`）。纯 rowid 在删除最大编号的目录后会复用该编号：新建的目录会得到已删除目录的编号，若有残留的 `parent_id` 指向它，就会被误认为子目录；「目录删除后以同一 URI 重建得到新编号」也不成立。`AUTOINCREMENT` 保证编号不复用。代价：SQLite 在检查 `UNIQUE` 之前就已分配 rowid，冲突的 `INSERT … ON CONFLICT` 也会烧掉编号（已实测，见 `knowledge/libraries.md`），因此 `upsertDir` 与子目录循环改为先查后写，测试断言重复刷新不增加 `sqlite_sequence.seq`。另外版本升级时的「删表重建」不能 `DROP TABLE sqlite_sequence`（报 `table sqlite_sequence may not be dropped`），只删业务表（`a54eb7c`，有测试）。
2. **`parent_id` 的孤儿认领**。原先 `parent_uri` 是字符串，先访问深层目录（`visit` / `setState`）时父行不存在也能记录；改成编号后，父行不存在时 `parent_id` 只能为 NULL。处理：`getDir().parentUri` 在父行不存在时回落到按 URI 计算（`parentOf`）；新建目录行之后（每次 `applyListing` / `ensureDir` 一次，而不是每个新行一次）用 `adoptOrphans()` 读 `parent_id IS NULL` 的行（只有根与孤儿，走 `dirs_parent` 索引）补上 `parent_id`。每个新行一次的做法曾使 5 万子目录的用例升到 4s 并在全量并行时超时。理由：保持原有行为与公开签名不变，同时不让热路径随表增大而变慢。

## 遗留问题的修复

### (a) 系统时钟回拨

- 症状：`now - checkedAt` 为负（确认时刻在「未来」）时，`listNow` 一直把目录当作 fresh（不排 P0），`requestP0` 的去重也把 `p0Done` 在未来的目录当作重复，F5 与展开静默失效，直到时钟追上。
- 修复：两处都改为「差为负不算新鲜 / 不算重复」。
- 测试（先失败后通过）：`listNow after the clock is set back still confirms a directory checked "in the future"`、`refresh after the clock is set back is not swallowed by the P0 dedupe`。

### (b) `FS_NOT_A_DIRECTORY`

- 症状：目录被同名文件替换时，`handleError` 调用 `removeMissing`，把父目录缓存列表中的同名项也删掉了，这个文件会暂时从树与搜索中消失（直到父目录下一次确认）。
- 修复：`FS_NOT_A_DIRECTORY` 单独处理：`cache.removeSubtree(uri)`（只删该目录自身及其子树的缓存）→ `setState(uri, 'unreachable', 'FS_NOT_A_DIRECTORY', now)`（行保留为错误状态并带确认时刻，后台队列不会立即重选）→ 通知渲染端 → 对父目录排一次确认。该目录已记为 `FS_NOT_A_DIRECTORY` 时再次出错不再强制父目录，走通用错误分支。**父目录的确认选用「P0」**（现有机制），新增内部选项 `force`：不与刚完成（`p0Done` 的 2 秒去重）或正在执行的 P0 合并，因为那一次读到的可能还是更正之前的状态；未选用「标记为待确认」是因为现有没有这种标记，增加会扩大改动。根目录本身被文件替换时没有父目录：只删除缓存并通知根。`FS_NOT_FOUND` 的行为不变（仍连同父目录列表中的该项一起删除）。
- 测试（先失败后通过）：`a directory replaced by a file keeps its entry in the parent listing until the parent is confirmed`（父目录真实列表中 `a` 变为文件：目录缓存已删除、父目录被重新读取一次、`a` 的类型更正为 `file`、通知了父目录）、`a directory replaced by a file is not dropped from a stale parent listing meanwhile`（父目录的真实内容没有变：确认后该项仍在）。
- 已知的边界（最终审查修正）：父目录持续把某名称列为目录、而读取它返回 `FS_NOT_A_DIRECTORY` 时，若每次都「删除缓存 → 强制父目录 → 列表重建该行（`checked_at IS NULL`）→ 后台队列立即再选中」会无限循环（审查实测本地后台休息 500ms 时 10 分钟内父目录完整读取 1171 次）。现在第一次出错后该行保留为 `unreachable` / `FS_NOT_A_DIRECTORY`，再次出错只按远层间隔重试、不通知、不强制父目录（同一场景 10 分钟内父目录读取 ≤ 3 次，测试 `a name the parent lists as a directory but cannot be read as one does not loop on the parent`；根被文件替换的用例 `a root replaced by a file is recorded as an error and is not retried in a loop`）。
- 同次修复：`applyListing` 自身行不再以 NULL 覆盖已有 `parent_id`（嵌套根 `[R, R/a]` 时不再翻转）；`prune` 末尾把指向不存在行的 `parent_id` 置 NULL（使之后 `adoptOrphans` 能认领）。

## `FS_NOT_FOUND`：重新读取父目录（e2e 原则用例的偶发失败）

- 提交：`fix(scanner): re-list the parent when a cached child is not found`
- 来源：全量 e2e 中 `principle: renaming an ancestor of an expanded directory succeeds` 偶发失败（改名全部成功，改回后树中 `A` 显示「没有项目」）。诊断（扫描进程插桩 + 定向复现）结论：改名不受影响，是缓存的逻辑缺陷，默认设置下同样存在。用例保持不变。

### 缺陷

`A` 改名期间扫描进程确认 `A\B` 得到 `FS_NOT_FOUND`，`Cache.removeMissing`（`5a69be0` 引入）把 `B` 从 `A` 的缓存列表中删除。`A` 在 50–80ms 前刚比较过修改时间（近层同一位置组的确认之间至少 `PERIODIC_GAP_MS`，父子目录的确认因此错开），属于 fresh，渲染端重新列出时直接用缓存、不排 P0。`A` 改回后它自身在磁盘上的修改时间没有变（改名 `A` 只改变 `案件` 的修改时间），之后每次确认都判为「没变」，`A` 的列表永远缺 `B`：树中 `A` 显示「没有项目」，搜索也找不到 `B` 的子树，直到选中 `A`、F5 或重新展开。默认设置下每次「改走并改回」约 0.2% 以上触发，不会自愈。

### 修复

| 部分                 | 内容                                                                                                                                                                                                                                                                                                                                   |
| -------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 强制读取父目录       | `handleError` 的 `FS_NOT_FOUND` 分支：`removeMissing` 之后对父目录排一次 `requestP0(parent, { force: true })`（与 `FS_NOT_A_DIRECTORY` 同一机制），由真实枚举决定父目录的列表。父目录也不存在时逐级向上得到 `FS_NOT_FOUND`，停在真实存在的最近上级                                                                                     |
| 父目录的修改时间失效 | `removeMissing` 删除了父目录列表中的该项时把父目录的 `dir_mtime` 置为 NULL：强制 P0 因故没有执行时，父目录下一次被确认（任何层）也一定完整读取                                                                                                                                                                                         |
| 循环上限             | 该目录行保留为 `not-found` / `FS_NOT_FOUND`（带确认时刻；`listed_at` 为空，展开时照常 P0）。父目录的真实列表不再含它时，父目录的确认删除这一行；仍列出它时行留下，它再次报 `FS_NOT_FOUND` 时只更新状态与确认时刻、不再强制父目录、不再从父目录列表中删除（以父目录的真实列表为准），按远层间隔重试。根没有父目录：仍只删除缓存并通知根 |
| 保留                 | `removeMissing` 本身（`5a69be0`：父目录 fresh 时树与搜索立即不显示已删除的目录）。未回退到 `removeSubtree`                                                                                                                                                                                                                             |

### 测试（TDD）

- `a child not found while its ancestor was renamed is re-listed in the parent after the rename is undone`（新增；`FakeFs.failOnce` 让 `b` 只有下一次读取返回 `FS_NOT_FOUND`，模拟上级改名期间的一次读取，`a` 的修改时间不变）：修复前失败——`a` 没有被读取（`list` 0 次），`a` 的列表为 `[]`，`listNow(a)` 不含 `b`，关注点设为 `b` 再过 120 秒 `a` 的列表仍为 `[]`（不自愈）；修复后 `a` 被真实读取 1 次，列表含 `b`，`b` 展开后有 `c.txt`，120 秒后仍含 `b`。
- `a name the parent lists as a directory but reports not-found does not loop on the parent`（新增；父目录持续列出 `a`、读取 `a` 返回「不存在」，「全部」策略，10 分钟）：修复前失败（`a` 从父目录列表中被删除）；**只加强制 P0、不设限的中间版本**下父目录完整读取 1171 次（断言 ≤ 3 失败）；设限后通过（父目录读取 ≤ 3、`a` 的 stat ≤ 8、父目录列表保留 `a`、行为 `not-found` / `FS_NOT_FOUND`）。
- `removeMissing invalidates the parent mtime only when it removed the parent entry`（`cache.test.ts`，新增）：修复前失败（`dirMtime` 仍为 7），修复后通过；同名是符号链接、没有删除该项时不置空。
- 既有用例的调整：`FakeFs.rmdir` 保留父目录的条目（「父目录仍列出、读取失败」），真实删除改用新增的 `FakeFs.remove(parent, name)`（同时从父目录列表删除该项并改变父目录的修改时间）。`not-found removes the subtree…`、`not-found also removes the directory from a fresh parent listing (tree and search)`、`confirming after a failed reveal…` 改用 `remove`（原先用 `rmdir`，强制读取父目录时假文件系统仍列出已删除的目录，与真实删除不符）；其中 `fresh parent listing` 用 `gate` 挡住父目录的读取，断言在父目录读取完成**之前**树与搜索已不显示该目录（`5a69be0` 的效果），放行后父目录被读取 1 次、「不存在」的行随之删除。`not-found removes the subtree…` 中父目录的通知可能有两次（推断删除时一次、父目录确认删除「不存在」的行时一次），断言改为集合相等。

### 取舍

每个不存在的目录多一次父目录完整读取（上级改名时沿路径向上各一次，有界）。父目录列出、读取却持续「不存在」的目录：第一次强制父目录 1 次，之后按远层间隔（本地 2 分钟 / 网络 5 分钟）只 stat 它本身。
