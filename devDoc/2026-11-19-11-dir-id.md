## 两个设计决定

1. **`AUTOINCREMENT`**（计划写的是 `INTEGER PRIMARY KEY`）。纯 rowid 在删除最大编号的目录后会复用该编号：新建的目录会得到已删除目录的编号，若有残留的 `parent_id` 指向它，就会被误认为子目录；「目录删除后以同一 URI 重建得到新编号」也不成立。`AUTOINCREMENT` 保证编号不复用。代价：SQLite 在检查 `UNIQUE` 之前就已分配 rowid，冲突的 `INSERT … ON CONFLICT` 也会烧掉编号（已实测，见 `knowledge/libraries.md`），因此 `upsertDir` 与子目录循环改为先查后写，测试断言重复刷新不增加 `sqlite_sequence.seq`。另外版本升级时的「删表重建」不能 `DROP TABLE sqlite_sequence`（报 `table sqlite_sequence may not be dropped`），只删业务表（`a54eb7c`，有测试）。
2. **`parent_id` 的孤儿认领**。原先 `parent_uri` 是字符串，先访问深层目录（`visit` / `setState`）时父行不存在也能记录；改成编号后，父行不存在时 `parent_id` 只能为 NULL。处理：`getDir().parentUri` 在父行不存在时回落到按 URI 计算（`parentOf`）；新建目录行之后（每次 `applyListing` / `ensureDir` 一次，而不是每个新行一次）用 `adoptOrphans()` 读 `parent_id IS NULL` 的行（只有根与孤儿，走 `dirs_parent` 索引）补上 `parent_id`。每个新行一次的做法曾使 5 万子目录的用例升到 4s 并在全量并行时超时。理由：保持原有行为与公开签名不变，同时不让热路径随表增大而变慢。

## 遗留问题的修复

### (a) 系统时钟回拨

- 症状：`now - checkedAt` 为负（确认时刻在「未来」）时，`listNow` 一直把目录当作 fresh（不排 P0），`requestP0` 的去重也把 `p0Done` 在未来的目录当作重复，F5 与展开静默失效，直到时钟追上。
- 修复：两处都改为「差为负不算新鲜 / 不算重复」。
- 测试（先失败后通过）：`listNow after the clock is set back still confirms a directory checked "in the future"`、`refresh after the clock is set back is not swallowed by the P0 dedupe`。

### (b) `FS_NOT_A_DIRECTORY`

- 症状：目录被同名文件替换时，`handleError` 调用 `removeMissing`，把父目录缓存列表中的同名项也删掉了，这个文件会暂时从树与搜索中消失（直到父目录下一次确认）。
- 修复：`FS_NOT_A_DIRECTORY` 单独处理：`cache.removeSubtree(uri)`（只删该目录自身及其子树的缓存）→ 通知渲染端 → 对父目录排一次确认。**父目录的确认选用「P0」**（现有机制），新增内部选项 `force`：不与刚完成（`p0Done` 的 2 秒去重）或正在执行的 P0 合并，因为那一次读到的可能还是更正之前的状态；未选用「标记为待确认」是因为现有没有这种标记，增加会扩大改动。根目录本身被文件替换时没有父目录：只删除缓存并通知根。`FS_NOT_FOUND` 的行为不变（仍连同父目录列表中的该项一起删除）。
- 测试（先失败后通过）：`a directory replaced by a file keeps its entry in the parent listing until the parent is confirmed`（父目录真实列表中 `a` 变为文件：目录缓存已删除、父目录被重新读取一次、`a` 的类型更正为 `file`、通知了父目录）、`a directory replaced by a file is not dropped from a stale parent listing meanwhile`（父目录的真实内容没有变：确认后该项仍在）。
- 已知的边界：目录被文件替换后，若父目录确认仍读到 `a` 是目录（例如替换发生在读取之间），下一次定期确认或后台队列会再读它并重复这一过程；每次都只多一次父目录读取。
