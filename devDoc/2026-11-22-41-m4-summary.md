## 2. 待确认的决定清单

每条格式：决定内容 → 当前实现 → 出处。勾选表示「同意当前实现」；不同意的在条目后写意见。D / R 编号沿用实现记录 40 第 4 节。

### 2.1 需要需求方判断

- [ ] **D6 被推翻：编辑锁定中的连接只在凭据变化时解锁** → 计划中原定「编辑一律解除锁定」，整体审查发现「只改名称也会解锁并以原来的错误密码重连」，按设计 5.3 改为：登录锁定只在密码 / 认证方式 / 私钥 / 用户名 / 主机 / 端口变化时解除，sudo 锁定只在实际使用的 sudo 密码变化时解除；其余编辑保留锁定，要再试请点「重新连接」或「测试连接」。出处：40 §5 第 1 项、§4.2 R24 / R25。
- [ ] **断线显示的方式** → 已建立的连接稳定存续后因错误断开时，主动让树重新检查一次，约 1–1.5 分钟显示断开（实测 78 秒），之后按 30 秒起翻倍的退避重连；代价是断线时多一次连接尝试，「远程连接」视图在这次尝试期间显示「接続中」而不是「オフライン」。出处：40 §5 第 2 项、R21 / R22 / R24 I2。
- [ ] **残余风险的接受** → 交出密码（登录或 sudo）后只要结果没法确定（超时、断线、通道关闭），一律按认证失败锁定：宁可误锁、让用户手动「重新连接」，也不重交一个可能错误的密码。出处：40 §5 第 3 项、doc 7.6「残余风险」、R7 / R11 / R24 I1。
- [ ] **合并前建议处理的 6 项（现已合并，改为 beta 前处理？）** → 见第 4.1 节 K1–K6。出处：40 §6.1。

### 2.2 控制者的决定（影响使用，建议一次确认）

## 4. 已知问题 / 待解决

### 4.1 建议 beta 前处理（原「建议合并前处理」）

- **K1 打包产物里带着 `ssh2/util/pagent.exe`**（未签名，本应用不用 Pageant），整个 `ssh2` 因此被解包到 `app.asar.unpacked`；可能被公司漏洞管理 / 杀毒扫描关注。在 electron-builder 的 `files` 中排除 `**/ssh2/util/**` 即可。出处：40 §6.1、knowledge/build-and-packaging.md。
- **K2 不支持的认证提示显示为「认证失败」**：keyboard-interactive 一轮有多个 / 回显提示（MFA 等）时中止并锁定，界面文案与密码错误相同，但其实没有交出密码；应按 detail `unsupported prompt` 显示不同文案。出处：40 §6.1。
- **K3 改主机 / 端口时 sudo 锁定不随之解除**（需「重新连接」）。出处：40 §6.1。
- **K4 SFTP 子系统打开超时后才到达的通道不关闭**，反复超时会接近 `MaxSessions`。出处：40 §6.1。
- **K5 无法清除已保存的私钥口令**（留空 = 不变）。出处：40 §6.1。
- **K6 地址栏 sftp 的悬停提示（`<连接名>:<路径>`）与复制内容（服务器路径）不一致**；没有连接时 `htmlFor` 指向不存在的元素。出处：40 §6.1。

### 4.2 用户可见（以后处理）

- **K7 首次确认主机密钥超过 20 秒时**，树先显示断开，回答后要等下一次退避探测（30 秒以上）才恢复；「添加远程文件夹」的默认路径也会超时且不自动重取。出处：40 §6.2 整体审查 Minor 4。
- **K8 服务器新增更优先的主机密钥算法（例如加了 ed25519）时误报「主机密钥已变化」**。出处：40 §6.2 Minor 5。
- **K9 断线重连期间「远程连接」视图显示「接続中」而不是「オフライン」**。出处：40 §5 第 2 项。
