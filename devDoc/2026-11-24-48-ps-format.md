# RHEL 7 上身份切换判定不出成功：ps 列写法

日期：2026-11-24　｜　相关：`devDoc/2026-11-24-47-remote-shell-compat.md`（前一个问题）、`doc/` 7.6 节（v1.30）、`knowledge/libraries.md`「procps-ng `ps -o pid=,ppid=,comm=`」

## 1. 现象

修复登录 shell 为 csh 的问题（devDoc 47）后，在现场服务器上切换用户仍然失败。该服务器的 sudo 为 1.8.19p2，登录用户与目标用户 `mebiap` 都是 `/bin/csh`；客户环境为 RHEL 7.6 / 8.10 / 9.6 / 9.10，该台大概率是 RHEL 7（未确认）。

## 2. 调查（需求方按应用的步骤手动执行）

- 探测、轮询循环、在无终端环境中执行 sudo 并读到 `PCHSTART`：都正常。
- 在 `sudo su - mebiap` 进入 mebiap 的状态下，从另一个窗口按终端筛选进程表：

  ```
   6802  6800 fuyongju pts/1 csh
  10165  6802 root     pts/1 sudo
  10347 10165 root     pts/1 su
  10348 10347 mebiap   pts/1 csh
  ```

  进程链与 comm（`su`）都符合应用的判定条件。

- `ps -eo pid=,ppid=,user=,comm=,args=` 只输出一列：首行为标题 `,ppid=,user=,comm=,args=`，其下为右对齐的 PID。
- 结论：该 procps-ng 把 `-o` 中第一个 `=` 之后的整段（含逗号）当作 PID 列的标题。这种处理符合 POSIX；本机 WSL 的 procps-ng 3.3.17～4.0.5 则按逗号拆成多列。应用的轮询命令 `ps -eo pid=,ppid=,comm=` 因此拿不到 PPID 与进程名，判定不出成功，一直等到超时。
- 需求方在现场确认：`ps -e -o pid= -o ppid= -o comm=` 能输出三列，没有标题行。

## 3. 修复

- `sudo-switch.ts` 的 `pollCommand`：`ps -eo pid=,ppid=,comm=` 改为 `ps -e -o pid= -o ppid= -o comm=`（每列各一个 `-o`，POSIX 写法）。
- 单元测试更新了期望值，并新增断言：命令中不含 `=,`。

## 4. 验证（已执行）

- `src/main/modules/connection/` 的单元测试：237 passed。
- `pnpm typecheck`、`pnpm lint` 通过。
- WSL 实机测试：21 passed、1 skipped（原有的跳过）。覆盖 4 个发行版的 bash 用例与 Debian / AlmaLinux-9 的 csh 用例。

未验证：

- 现场服务器上用新构建实际切换（WSL 只有新版 procps-ng，复现不了旧版的行为）。
- RHEL 8.x 的 procps-ng 对旧写法的处理（不影响修复：新写法在新旧版本上都成立）。
