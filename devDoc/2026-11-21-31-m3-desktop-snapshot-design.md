## 1. 目的与背景

需求方原话（2026-11-21）：「主要是想保存其他打开的应用或系统资源管理器，在电脑重启后一键恢复或手动选择恢复。」重启有两种：自己下班关机，与公司推补丁强制重启（需求方：两种都有）。

对应产品目标（memory「product goals」）：6「重启后恢复之前打开的目录和文件，继续工作」；4「大部分工作在一个应用里完成」（每天开工从本应用恢复现场）。

Windows 自带的「登录时还原以前的文件夹窗口」「自动保存可重启的应用」只能全部恢复、不能挑选、只记上一次关机、第三方程序要自己登记，且有失效报告（讨论中已调查，本机两项均为默认关闭）。PowerToys Workspaces 记录的是程序与窗口位置，不记录打开的文件，本机未安装。本功能要补的正是这些短板：**能挑选、能保存多份、记录具体的目录与文件、不依赖正常关机**。

## 2. 目标、非目标、反目标

### 目标

1. **记录对象**（需求方）：资源管理器（含 Windows 11 的标签页）、Word / Excel / PowerPoint 打开的文件、VS Code 打开的文件夹、Eclipse 的 workspace。
2. **记录方式**（需求方）：监控（读取系统与这些程序的状态），不要求程序经本应用启动。
3. **保存**（需求方）：定时自动保存 + 手动保存 + **退出本应用时选择保存哪些**。
4. **恢复**（需求方）：一键恢复，或**选择要恢复的项目**；重启后打开本应用时提示恢复。
5. **关机时程序被逐个关掉不能把记录冲掉**（需求方提出的问题，第 5.3 节）。
6. **整台桌面一份记录，不按工作区区分**（需求方）。
7. **入口在活动栏**（最左侧的窄列，需求方）。

### 非目标（本次不做，记录）

- 开机自启、关窗缩到托盘（需求方：先不考虑）。因此本应用没在运行的时段不记录。
- 从本应用启动 VS Code / Eclipse 等，并与监控结合（需求方：将来实现启动功能后再结合）。
- 其他程序：樱花编辑器、Tera Term、WinSCP、FFFTP 等（讨论中分析过，后续逐个加入）。
- **恢复窗口位置与大小**：本次记录位置（数据里保留），恢复时不移动窗口（控制者：需要启动后找到对应窗口再移动，放到下一步）。
- 未保存过的新建文档、浏览器的网页标签：拿不到路径，不记录。
- SharePoint / OneDrive / Teams 上的 Office 文件（路径为 `https://` 网址）：第一版跳过，快照页注明不支持（需求方）。
- 从 Outlook 附件等打开、位于临时目录中的 Office 文件：不记录（控制者：临时副本重启后多半已被清理，恢复它也不是用户要的那份）。
- 本应用自己的标签 / 多窗口会话（见文首「取代」）。

### 反目标（即使能用也算失败）

- 关机 / 强制重启之后，最新的自动记录里是空的或缺了关机前开着的项目。
- 记录或恢复过程中改动了任何文件（违反文件系统原则；读取其他程序的状态文件也只能只读，且不能长期持有句柄、不能锁住它们）。
- 记录的数据里出现密码等机密（本次的四类对象一般不会出现；作为原则写明，第 5.6 节）。
- 监控让本应用或系统明显变卡（定期扫描的开销要能忽略）。
- 渲染端可以借恢复功能启动任意程序（恢复只能启动记录中由主进程采集到的项目，第 5.5 节）。

## 5. 设计

### 5.1 各程序的采集与恢复

讨论中的调查结果。「实测」= 本机 2026-11-21 实际运行过；其余为资料或推断，进入实施前先验证（第 7 节）。

| 对象                      | 采集什么                                                | 怎么取                                                                                                                                                                                                                            | 恢复                                                                                                                                                | 依据                                                                 |
| ------------------------- | ------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------- |
| 资源管理器                | 每个窗口的每个标签：路径、标签顺序；窗口位置            | PowerShell：`Shell.Application.Windows()` 每个标签是一项，同窗口共用 `HWND`（据此分组）；标签顺序用 UI Automation 读 `TabItem`（要滤掉主文件夹页内的「收藏夹 / 已共享」等非窗口标签）；特殊位置（主文件夹等）的路径是 `::{CLSID}` | 每个窗口：打开第一个标签的路径，其余标签以「添加新标签页」按钮（UI Automation，`AutomationId = AddButton`）新建后导航；做不到时退回每个标签一个窗口 | 读取与按钮点击：实测；新标签导航：未验证                             |

### 5.2 监控

- 主进程模块 `modules/desktop`（控制者：枚举窗口在主进程里是毫秒级调用；实测若影响界面再移到 utilityProcess）。
- **窗口列表**：每 5 秒（需求方 2026-11-21）经 koffi（`user32`：`EnumWindows`、`GetWindowTextW`、`GetWindowThreadProcessId`、`IsWindowVisible`、`GetWindowRect`；进程路径 `QueryFullProcessImageNameW`）枚举可见顶层窗口，只保留四类对象的进程（`explorer.exe`、`WINWORD.EXE`、`EXCEL.EXE`、`POWERPNT.EXE`、`Code.exe`、`eclipse.exe`），与上一次比较「窗口集合 + 标题」。
- **详情**：窗口集合或标题变化后（防抖约 2 秒）读取变化了的那一类的详情；另外每 5 分钟对四类做一次完整读取兜底（后台新开标签等不改标题的变化）。
- 权限：以管理员身份运行的程序读不到详情，记录为「无法读取」并跳过（不报错打扰）。
- Office 正弹着对话框时自动化调用可能卡住：每次读取设超时（如 10 秒），超时则本轮保留该类的上一次结果。

### 5.3 关机时不冲掉记录（控制者，讨论中已说明）

- **当前现场**（内存中的「现在开着什么」）：新出现的项目立即加入；**消失的项目要持续消失 1 分钟（需求方 2026-11-21）**（本应用一直在运行的前提下）才移除。关机时本应用几秒内被结束，等不到 1 分钟，所以最后保存的记录保留关机前的全部项目。代价：关掉某个窗口后马上重启，它会出现在恢复清单里（恢复时可以不勾）。
- **自动保存**：每 5 分钟、且当前现场与最近一份自动记录不同时，写一份新的自动记录。
- **会话结束通知**：主窗口的 `query-session-end` / `session-end`（Electron 45 类型定义中有，`reasons` 区分 `shutdown` / `logoff` / `critical` 等）到达时，立即把当前现场写一份自动记录并停止监控。其他程序与本应用谁先收到通知未验证，所以只作补充，不作依赖。
- **会话结束期间冻结**（控制者，因移除时间缩短为 1 分钟而补充）：关机可能被某个程序拖住超过 1 分钟（如 Word 询问是否保存），这期间其他程序已关闭、本应用仍在运行。因此收到 `query-session-end` 后冻结当前现场（不再移除、不再自动保存）5 分钟；5 分钟后本应用仍在运行，视为关机被取消，恢复正常。
- **登录标识**（控制者，采纳审阅意见）：每份记录带「登录时刻」（本应用所在 Windows 登录会话的开始时刻，经 koffi 调 `WTSQuerySessionInformationW` 取得，先行验证），据此找出「上一次登录的最后一份记录」。不用系统开机时刻：注销后再登录、开着「快速启动」时的关机，程序都会全部关掉，但开机时刻不变，用它会漏掉恢复提示。下文「上一次登录」均指此标识。

### 5.4 记录的保存与保留

- 应用数据库新增迁移 `0006-desktop-snapshots`：快照表（id、机器 `machine`、种类 `auto` / `manual` / `exit` / `exit-none`、创建时刻、登录时刻、可选名称；`machine`（控制者）= 主机名，只读写本机的行，因为 `%APPDATA%` 可能随漫游配置到别的机器，与 `launch_capabilities` 同理）与项目表（快照 id、对象类别、显示名、恢复所需数据 JSON、窗口位置 JSON、排序）。
- 保留（控制者）：自动记录保留最近 20 份，另外每次登录的最后一份自动记录保留最近 10 次登录；手动与退出时的记录一直保留，直到用户删除。
- 记录只存在本机数据库里，不上传、不导出（导出属于目标 5，以后再说）。

### 5.5 恢复

- 渲染端只发「快照 id + 勾选的项目 id」，主进程从数据库取出采集时记录的程序路径与参数再启动（反目标：渲染端不能借此启动任意程序）。
- 已经开着的项目跳过（Office 文件按路径比较、资源管理器按路径、VS Code 按文件夹、Eclipse 按 workspace）；路径已不存在或网络位置连不上时跳过并在结果中提示，不阻塞其余项目。
- 逐个启动，项目之间留短间隔（如 0.5 秒），避免同时拉起很多 Office。
- 结果以应用消息汇总（成功几项、跳过几项及原因）。

### 5.6 机密

本次四类对象的采集结果是路径与窗口标题，一般不含密码。原则写明：采集到的启动参数只保留恢复所需的部分（`-data` 等），不保存整串命令行；以后加入 Tera Term / WinSCP 时按需过滤 `/passwd=`、`user:密码@` 等。

### 5.7 界面

- **活动栏**：在「搜索」之后新增「桌面记录」按钮（`SidebarView` 增加 `desktop`；图标控制者暂定 lucide `MonitorIcon`，可改）。
- **侧栏**：顶部「今すぐ保存」按钮；下面是快照列表（按时间倒序，标注种类与「重启前」，可删除 / 改名）；最上面一行固定为「現在」（当前现场）。
- **快照页**（标签中打开，内置视图，不是插件；位置 URI `pch-desktop:<快照 id>`，「現在」为 `pch-desktop:current`）：按类别分组的项目清单，每项一个勾选框、显示名与路径；底部「選択した項目を復元」（「現在」页为「保存」）。
- **重启后的恢复对话框**：打开本应用时，取「上一次登录」的记录决定是否提示（需求方，第 8 节第 1 条）：那次登录以「保存して終了」结束 → 用那份 `exit` 记录；以「保存しないで終了」结束 → 不提示；其余（直接关机、强制重启、本应用异常结束）→ 用那次登录的最后一份自动记录。所选记录中有当前没开着的项目时，弹出同一个勾选清单（默认全选）；可「復元」「後で」（之后仍可在侧栏中找到）。为此记录需能区分「这次登录是怎样结束的」（例如在退出时写入一份带结束方式的记录，具体由实施者定）。
- **退出时的保存对话框**（需求方）：用户主动退出本应用时，列出当前现场（默认全选），「保存して終了」「保存しないで終了」「キャンセル」；勾选「次回から確認しない」后不再弹出、以后退出时按全部保存处理（需求方），可在侧栏中重新打开（设置页随 M5）。会话结束（关机）时不弹，直接按 5.3 节自动保存。
- 文案 ja / zh-CN / en 三语。

### 5.8 结构（控制者）

- 主进程 `modules/desktop/`：`window-list.ts`（koffi 枚举）、`collectors/{explorer,office,vscode,eclipse}.ts`（各类详情，Explorer / Office 为固定 PowerShell 脚本，输入只经环境变量，同 launcher 的做法）、`live-state.ts`（当前现场与 1 分钟延迟移除，纯逻辑可单测）、`snapshot.repo.ts`、`restore.ts`、`desktop.ipc.ts`；在 `eslint.config.mjs` 登记。
- IPC（`packages/shared/src/ipc/contract.ts`）：`desktop.list`、`desktop.get`、`desktop.current`、`desktop.save`（带勾选的项目）、`desktop.restore`、`desktop.delete`、`desktop.rename`；事件 `desktop.changed`。
- 渲染端 `features/desktop/`（侧栏视图、快照页、两个对话框）；`LocationKind` 增加 `desktop`。

## 7. 先行验证（实施计划的第一个任务）

1. Office：多个 Excel 进程、Word、PowerPoint 同时开着时，能否逐个取到文档路径与只读状态；弹着对话框时的超时行为。
2. 资源管理器：新标签导航到指定路径（按钮点击已实测）；特殊位置（`::{CLSID}`）的恢复。
3. VS Code：多窗口时 `storage.json` 的内容与写入时机；标题中的文件夹名与状态文件的对应方法。
