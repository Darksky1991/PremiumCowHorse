## 4. 已知问题 / 待解决

### 4.1 用户可见

- **K1 首屏未达标**：1GB 日志（部分模式）点击到末尾行可见约 0.9 秒（888 / 928 / 905 ms），设计目标 < 300ms；测量含点击 → 树 → sniff / 匹配 → `doc.open`（等第一块 1MB 索引 + 读 4MB 窗口 + 编码抽样）→ 解码 → 渲染，瓶颈在哪一段未逐段打点（未验证）；500MB 以下全量模式未测。出处：[文本预览 §基准数据](./2026-11-20-20-text-preview.md)。
- **K2 全量索引吞吐未达标**：1GB 点「すべて読み込む」约 4.9 秒、约 217MB/s，目标 ≥ 300MB/s；纯引擎 1180MB/s，差距在主进程分块读取 + UTF-8 校验 + 事件。日常不点「全部读取」就不会发生。出处：同上。
- **K3 读取 / 枚举期间持有句柄，可能阻止上级目录改名**：句柄只在一次读取 / 枚举期间持有（本地毫秒级），文本索引期间读取间隙可改名；网络上的大目录与大文件持有更久（未实测）。出处：[刷新与缓存 §未验证](./2026-11-19-06-refresh-cache.md)、文本预览 控制者的决定 第 5 条、doc 第 19 节。
- **K4 部分模式状态栏行数是窗口内行数**：例如 7.9MB 文件显示「Lines: 60,497」，易被理解为总行数，只靠「只显示末尾 4 MB」文字区分。出处：文本预览 §截图 / §记录的问题。
- **K5 编码判断的已知局限**：GB2312 / EUC-JP 一级汉字与 Shift_JIS 半角片假名评分平局（稀疏中文日志在日文偏好下判成 shift_jis，guess）；约 10% 的 cp1252 短行判为 shift_jis；EOF 无换行的重音字符判 UTF-8；约 6% 的纯 CJK 无 BOM UTF-16 检测不出；留出集 8 / 410 的 CJK 对 CJK 错判。出处：文本预览 §记录的问题。
- **K6 临时文件副本仍由 Chromium 写入临时目录**（应用不写不删）；`%TEMP%` 的 8.3 短文件名形式与 `app.getPath('temp')` 长名不会匹配（未处理，Chromium 实际使用的形式未验证）。出处：[松手位置与临时文件 §决定与限制](./2026-11-19-05-drop-position-and-temp-files.md)、doc 第 19 节。
- **K7 标签标题是打开时的快照**：条目 / 工作区改名与语言切换后不更新；删除工作区后其标签集合仍留在内存。出处：[导航 §记录的问题](./2026-11-19-17-navigation.md)、[M1-3 §记录的问题](./2026-11-19-14-m1-3.md)。
- **K8 慢速 / 无响应共享上的标签与定位**：`host.tabs.open` 先 stat，共享无响应时要等超时才提示；`shell.openPath` 无超时保护；同步定位进行中不会被用户自己的选中取消（选中会被拉回）；类型提示导航的标题取 URI 最后一段（UNC 共享根显示为 `share`）。出处：M1-3 §发现的问题（未处理）、§记录的问题；导航 §记录的问题。
- **K9 判定断开之前目录视图显示缓存且无提示**（网络默认 10 秒内）；可达状态变化会让所有标签的目录视图重新列出一次。出处：M1-3 §发现的问题（未处理）。
- **K10 映射网络盘**：按盘符各自成组，同一服务器的两个映射盘被视为两台主机；未做盘符转 UNC（`WNetGetConnectionW`）；文本预览中映射盘按本地轮询间隔。出处：刷新与缓存 §遗留事项、文本预览 §记录的问题。
- **K11 无设置界面**：缓存策略 / 间隔、`singleClickPreview`、强调色、密度、`preview.maxTextSizeMB`、缓存占用与清空，均随 M5 设置页。出处：刷新与缓存 §遗留事项、导航 §待需求方确认、[M0 验收 §遗留事项](./2026-11-18-04-m0-acceptance.md)。
- **K12 搜索的小问题**：FTS5 trigram 大小写折叠覆盖 Unicode，短词 / 通配词 / 固定文件条目只折叠 ASCII，非 ASCII 大小写（`É` / `é`）可能不一致；设置「显示隐藏文件」变化后不自动重新查询。出处：搜索 §后端、§实现中的决定。
- **K13 资源树 / 菜单的 M1-2 暂缓 minor**：Menu 键 / Shift+F10 不打开所选节点菜单；无选中项时无可见焦点指示；窄侧栏中错误文案被截断；`maxLength` 静默截断粘贴；拖入折叠分组后选择落到无关节点；同一批多个文件失败时逐个提示等（与 `fs.watch` 相关的项已随其删除而失效，未逐条核实）。出处：[M1-2 §遗留事项](./2026-11-18-08-m1-2-explorer.md)。
- **K14 标签栏与导航的小问题**：Ctrl+W 在对话框打开或输入框中也会关闭激活标签，焦点在标签栏内时关闭后落到 body；滚动位置保存有 150ms 防抖，切走瞬间的滚动可能丢失；一直读取失败的目录让选中停留在祖先；抽屉重新展开时选中节点仍在加载可能被抽屉覆盖（已缓解、未单独验证）；`role=tab` 内含 Button、目录加载中两个 `role=status`；条目未加载时地址栏短暂显示绝对路径段。出处：M1-3 §记录的问题 可留后续、导航 §记录的问题。
- **K15 文本预览的小问题**：空文件 → 有内容后 F5 重新挂载有闪烁；刷新持续失败时占位行一直显示；孤立的 `\r` 不算换行；字节级截断可能切开多字节字符（末尾显示 U+FFFD）；F5 不重新 sniff；sniff 失败时兜底插件显示文件信息而不是错误；`did-start-navigation` 在提交之前触发（旧页面可能打开文档）。出处：文本预览 §记录的问题。
- **K16 其他**：默认工作区改名后无法恢复为本地化的默认名称；缓存的目录修改时间有盲区（需求方已接受，F5 / 展开时更正）。出处：[M1-1 §遗留事项](./2026-11-18-06-m1-1-data-layer.md)、doc 第 19 节。

### 4.2 内部 / 测试

- **K17 安全加固**：渲染端可对任意 UNC 主机发起 stat（被入侵时可能泄露 NTLM 哈希），预览插件引入前需加入 doc §15 加固；`openWithSystem` 无法验证用户手势（引入第三方插件前处理）。出处：M1-1 §遗留事项、M1-3 §记录的问题。
- **K18 M1-1 审查暂缓项**：渲染端传入路径未规范化（相对路径、带引号路径、单独的 `\\server`）；网络类错误映射为 `UNKNOWN`（后续刷新引擎对 Win32 错误码做了映射，其余路径是否仍遗留未核实）；`moveEntry` / `removeEntry` 在事务外读取条目；requestId 未按窗口区分（M3 多窗口前处理）。出处：M1-1 §遗留事项。

- **K20 验证空白**：
  - 真实 Alt+Tab、系统双击、侧键只有合成事件或一次性脚本。

  - 选中每次写入 tabs-store 的额外渲染未测量。
