## 1. 需求方原话

1. 「改成 1 分钟。另外保存的内容希望尽可能和实时同步，看哪里还能缩短。」（自动保存间隔原为 5 分钟）
2. 「恢复后删除快照要确认，不要默认删除。」
3. 「快照内容中的卡片大小高度要一致。」
4. 「多标签的资源管理器在快照内容中展示时要分开，并可以分别选择，退出时的保存同样。同时要能知道哪些是在同一个窗口中，可以以分组或视觉样式来区分。」

## 2. 做了什么

### 2.1 实时同步（第 1 条）

时序数值（`modules/desktop/constants.ts`）：

| 项目                         | 原值         | 新值                    | 理由 / 代价                                                                                                              |
| ---------------------------- | ------------ | ----------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| 自动保存兜底 `autoSaveMs`    | 300_000      | **60_000**              | 需求方指定                                                                                                               |
| 现场变化后写入               | 无（等周期） | **合并 1000 ms 后写入** | 新增 `DesktopService.liveChanged()`，组合根接到 `DesktopMonitor.onChange`；内容没变不写                                  |
| 消失项目到期                 | 等周期       | **到期时刻再写一次**    | 新增 `LiveState.nextExpiry(now)`，服务每次检查 / 写入后按它重排定时器                                                    |
| 窗口枚举 `pollMs`            | 5000         | **2000**                | 枚举只调用 Win32 API（台账 33：几毫秒），代价可忽略                                                                      |
| 防抖 `debounceMs`            | 2000         | **1000**                | 快速连续浏览文件夹时 Explorer 采集（PowerShell）最多约每秒一次（单飞，进行中再变化只补一次）                             |
| VS Code 防抖                 | 10_000       | 10_000（不变）          | 新窗口打开后约 4–9 秒才写 `storage.json`（台账 33），更短会漏记新窗口                                                    |
| 完整读取兜底 `fullRefreshMs` | 300_000      | **60_000**              | 标题不变的变化（Explorer 新增后台标签等）只能靠它发现；每分钟对开着窗口的类别各启动一次 PowerShell（无窗口的类别不启动） |
| 消失后移除 `removeAfterMs`   | 60_000       | 60_000（不变）          | 这是关机保护本身（设计 5.3），缩短会让关机时被逐个关掉的程序从记录中消失                                                 |

会话结束冻结期间（`pausedUntil`）、退出流程中（`closing`）、第一次完整读取之前，`liveChanged` 与到期检查都不写（走同一个 `tick()`）。

实机（真实模式、构建产物、临时 userData，脚本 `.superpowers/sdd/2026-11-21-32-m3-desktop-snapshot-plan/spikes/sync-real.mjs`，只开 / 关自己的窗口）：

- 开资源管理器窗口（`folder-a`）：窗口出现约 2.5 s → 「现在」约 2.3 s 后有它 → 自动快照再约 1.1 s 后有它（窗口出现后约 3.5 s）。
- 关闭该窗口：「现在」约 3.1 s 后去掉；5 s 后自动快照仍有它（关机保护）；**关闭后约 63 s** 从自动快照去掉（加到期定时器前为 110 s：要等下一次 60 秒兜底）。

### 2.2 恢复后确认删除（第 2 条）

- 主进程 `restore()` 不再删除快照（取消 v1.24 的 Ruling 14「没有 unreachable / failed 时自动清空」），返回 `DesktopRestoreResult`（`DesktopRestoreOutcome` / `cleared` 删除）；`10_000` ms 后的重新扫描照常。
- 新通道 `desktop.clear` → `DesktopService.clear()`：在写入队列中删除本机全部快照（含 `exit-none`），然后（第一次完整读取之后）立即写一份本次登录的 `auto`；失败时抛出（页面提示）。退出流程中不做。
- 渲染端 `clear-snapshots.tsx` 的 `ClearSnapshotsBody`：「删除已保存的快照吗？」+ 快照数；恢复中有 `unreachable` / `failed` 时加一句「保留快照可以稍后再试」。「保留」在前且为默认焦点，Esc / 点外部 = 保留；「删除」为 destructive 按钮。启动时的恢复对话框在同一对话框中切换到这一步；快照页用单独的对话框，删除后该标签改到「現在」页（Ruling 17 沿用），保留时留在原页并重新取得。

### 2.3 卡片等高（第 3 条）

`ItemCard` 固定 `h-16`：主标题与路径各一行省略（原来路径最多两行、Explorer 的路径作为主标题，导致高度不一），只读标记放在主标题行。e2e 断言不同分组（长路径 + 只读的 Excel、Word、特殊位置与普通路径的 Explorer 标签）的卡片高度相同。

### 2.4 资源管理器标签分开选择（第 4 条）

- 清单：Explorer 每个标签一张卡片（主标题为最后一段、详情为完整路径，`::{CLSID}` 为「特殊位置」、无详情，`item-label.ts` 的 `tabLabel`）。多标签窗口用虚线框（`border-dashed` + 浅底色）围起，框头「同一窗口 · N 个标签」（`role="group"`，可被读屏识别）；连续的单标签窗口排在普通网格中。
- 勾选模型 `checklist-model.ts`：勾选单位 id = 项目 id + 制表符 + 标签下标（`tabEntryId`），`entryIdsOf`（全部勾选单位）、`picksOf`（→ `{ id, tabs? }[]`，一个标签都没选的窗口不出现）。快照页、恢复对话框、退出对话框共用。
- IPC：`desktop.save` / `desktop.exit` 的 `keys: string[]` 改为 `picks: { key, tabs? }[]`，`desktop.restore` 的 `itemIds: number[]` 改为 `picks: { id, tabs? }[]`（`tabs` 为非负整数下标，最多 500 个）。主进程用共享的 `pickTabs(item, tabs)`（按原顺序保留选中的标签，重复与越界忽略，一个都不剩 → 不保存 / 不恢复该窗口）。`ExitGuard` 的「不询问 = 全部保存」改为 `currentPicks()`。
- 项目数统一为「Explorer 每个标签算一项」：共享 `desktopEntryCount`；侧栏「現在」与「今すぐ保存」的提示、分组「已选 x / y」、页脚件数；快照摘要的 `itemCount` 在 SQL 中用 `json_array_length(data, '$.tabs')` 同样计算（`get()` 用 `desktopEntryCount`）。改之前侧栏显示 6 项而页面显示 8 项。
- 恢复部分标签时，「已开着」的判断仍是「选中的第一个标签已开着 → 跳过整个窗口」（未改）。

## 3. 控制者的决定（Ruling，待需求方确认）

- Ruling 19：完整读取兜底也改为 60 秒（需求方只指定了自动保存）——否则后台新增的标签最长 5 分钟才进记录。代价：每分钟对开着窗口的类别各启动一次 PowerShell（约数百毫秒 CPU）；若感觉卡顿可改回。
- Ruling 20：窗口枚举 5 → 2 秒、防抖 2 → 1 秒（需求方原定 5 秒，这次要求「看哪里还能缩短」）。代价：枚举几毫秒；连续浏览时 Explorer 采集更频繁。
- Ruling 21：「删除」删除**全部**快照（沿用需求方第 1 轮「恢复后快照清空」的范围），删除后立即重新记录当前桌面（而不是等 10 秒的重新扫描）；只删除恢复的那一份是另一种可能。
- Ruling 22：恢复失败（连不上 / 启动失败）时仍允许删除，只提示「保留可以再试」（Ruling 14 的自动判断改为提示）。
- Ruling 23：单标签窗口不加窗口框，只有多标签窗口用虚线框；窗口框不提供「全选该窗口」（第 1 轮「分组不需要可选」）。
- Ruling 24：项目数统一按标签计（见 2.4）。快照列表中旧快照的项目数随之变化（按存储的标签重新计算，数据不变）。
