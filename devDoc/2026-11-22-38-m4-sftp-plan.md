# M4 远程目录（SFTP 只读）：实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal：** 在资源管理器中以只读方式浏览 SFTP 服务器上的目录（登录用户，或经 `sudo su - <身份>` 切换），目录只在展开 / 选中时读取并缓存，「建立索引」的目录定期扫描，文件只显示文件信息；活动栏「远程连接」视图管理连接。

**Architecture：** 主进程新模块 `modules/connection` 持有 SSH 连接（`ssh2`）：连接池（懒连接、保活、空闲断开、认证锁定、主机密钥确认）与身份切换（命令通道上 `sudo su -` 后 `exec sftp-server -R`，借用 `ssh2` 的内部 SFTP 类走 SFTP）。`vfs/providers/sftp.provider.ts` 经注入的接口取得 SFTP 会话，提供 `stat` / `list`。扫描进程新增第三种位置 `remote`：远程枚举器把 stat / list 经新消息请主进程代读，调度器对远程目录只做 P0 与「建立索引」的后台读取。渲染端新 feature `features/connections`，资源管理器增加「添加远程文件夹…」。

**Tech Stack：** Electron 45、`ssh2` 1.17.0（新依赖，需求方随设计批准）、`@types/ssh2`、node:sqlite + Kysely、zod 4、React + TanStack Query + zustand、shadcn（Base UI）、vitest、Playwright。

**Spec：** [devDoc/2026-11-22-37-m4-sftp-design.md](./2026-11-22-37-m4-sftp-design.md)（已批准）。执行者同时读设计与本计划；两者矛盾时以设计为准并记入台账。

## Global Constraints

- **只读**：不向服务器写入；SFTP 只发 OPEN（只读）/ READ / CLOSE / OPENDIR / READDIR / STAT / LSTAT / REALPATH / READLINK，本次实际只用 OPENDIR / READDIR / CLOSE / STAT / LSTAT / REALPATH；身份切换后执行 `sftp-server -R`。
- **账号锁定**（反目标）：登录密码一次连接只提交一次、只用一种认证方式；sudo 密码只在出现提示时写一次，再次出现提示即失败；认证失败（登录 / sudo）绝不自动重试，锁定写入 `connections.auth_state` 并跨重启保留，只有编辑连接、「重新连接」或「测试连接」（见本计划的控制者决定 D3）才解除。
- **机密**：密码 / 私钥口令 / sudo 密码只在主进程解密；不进渲染端、日志、URI、命令行参数、错误的 `detail`；`safeStorage.isEncryptionAvailable()` 为 false 时拒绝保存机密（`CONN_SECRET_UNAVAILABLE`）。
- **主机密钥**：必须设置 `hostVerifier`；首次连接由用户确认；已保存的指纹不一致即拒绝（`CONN_HOST_KEY_CHANGED`），不弹确认。
- **命令行**：身份（目标用户）按 `^[a-z_][a-z0-9_.-]{0,31}$` 校验；sftp-server 路径按 `^/[A-Za-z0-9._/+-]{1,254}$` 校验；不拼接其他任何数据。
- **数值**（设计 5.3 / 5.4 / 5.9）：保活 `remote.keepaliveSec` 15（5–120）× `keepaliveCountMax` 3；空闲断开 `remote.idleDisconnectMin` 5（1–60）；`vfs.timeoutSec.remote` 20（5–120）；`cache.backgroundGapMs.remote` 500（min 100）；`cache.remoteIndexIntervalMin` 30（5–1440）；进程表轮询约 150 ms；身份切换超时 15 000 ms；离线探测退避沿用扫描进程现有的 30 秒起翻倍、最长 5 分钟。
- **sftp-server 探测顺序**：`/usr/libexec/openssh/sftp-server`、`/usr/lib/openssh/sftp-server`、`/usr/libexec/ssh/sftp-server`、`/usr/lib/ssh/sftp-server`；连接设置可指定（覆盖探测）。
- **URI**：`sftp://<connectionId>/<路径>`、`sftp://<身份>@<connectionId>/<路径>`；每段 `encodeURIComponent`；根规范化为 `sftp://<id>`（无结尾 `/`）；shareKey = hostKey = `sftp://<connectionId>`（不含身份）。
- **分层**（`eslint.config.mjs`）：`modules/connection` 只依赖 `main-vfs`、`main-infra`、`main-core`、`shared`；`main-vfs` 不 import `main-module`（连接池以接口注入）；扫描进程只 import `vfs-portable` 文件与 `shared`；`ssh2` 内部类的借用只在 `modules/connection/sftp-bridge.ts` 一个文件。
- **依赖**：`ssh2` 固定精确版本 `1.17.0`；`@types/ssh2` 固定精确版本（Task 1 选定）；`pnpm-workspace.yaml` 的 `allowBuilds` 中 `ssh2: false`、`cpu-features: false`（不放行安装脚本）。
- 界面文案 ja / zh-CN / en 同时添加（ja 为类型基准）；shadcn 组件不改样式，`className` 只做布局；用户可见文案不在主进程拼接。
- 迁移文件发布后不得修改；改表 = 新迁移 + `infra/db/schema.ts` 类型。扫描缓存 `index.db` 改结构 = 递增 `CACHE_VERSION`（不迁移）。
- 测试范围：每个任务只跑本任务的单元测试文件 + `pnpm typecheck` + `pnpm lint` + `pnpm exec prettier --check .`；动到界面的任务加 `pnpm build` 与相关 e2e。全量只在 Task 14。

## 控制者决定（本计划新增，设计未写或留给实施者的部分）

- **D1** 扫描进程 ↔ 主进程的远程消息名沿用现有消息的驼峰写法：`remoteOp` / `remoteCancel`（扫描进程 → 主进程）、`remoteResult`（主进程 → 扫描进程）（设计写作 `remote.op` 等）。
- **D2** 进程表轮询用**一个长寿命的轮询通道**：`while :; do ps -eo pid=,ppid=,comm=; echo PCHEND; sleep 0.15; done`，判定后关闭（每次切换身份最多多占 1 个会话，不受 `MaxSessions` 频繁开关影响）。
- **D3** 「测试连接」是用户的明确动作：即使连接处于锁定状态也尝试一次；成功则解除锁定（`auth_state = ok`），失败则写入对应的锁定状态。
- **D4** sftp-server 探测与「能否看到 root 进程」的检查在**第一次使用切换身份时**执行（每条 SSH 连接一次），不使用切换身份的连接不执行命令。
- **D5** 新增错误码 `CONN_KEY_INVALID`：私钥文件读不了 / 格式不支持（含 `.ppk` 不支持时）/ 口令错误。属于本机错误，不连接服务器，**不进入**认证锁定。
- **D6** 编辑连接时 `host` 或 `port` 变化 → 清除已信任的主机密钥（需重新确认）。编辑连接一律解除认证锁定。
- **D7** 远程资源不经 `vfs.sniff`、不打开 `doc.*`：渲染端对非 `file:` 资源不 sniff，`SftpProvider.read` / `createReadStream` 以 `FS_UNSUPPORTED_SCHEME` 拒绝且不连接服务器。
- **D8** 「添加远程文件夹」对话框的默认路径经新通道 `connection.home`（登录用户为 `realpath('.')`，其他身份为 `/`）。
- **D9** 远程目录的「属主」（「无权限」提示用）随列表进入缓存：`RawEntry` / `FileEntry` 增加可选的 `owner`，缓存表 `entries` 加列 `owner`，`CACHE_VERSION` 5 → 6。
- **D10** 主进程访问范围（设计 5.7）的检查放在 IPC handler 与扫描进程远程请求的入口（`RemoteAccess`），不放在 `VfsService`：`entry.add` 校验新条目时需要对尚不是条目的 `sftp:` URI 调用 `vfs.stat`。

## Review Focus

1. **sudo 密码输错**（或过期）→ 服务器上只记 1 次失败；之后后台索引、恢复的标签、展开的树、重启后的应用都不再尝试 sudo，直到用户编辑 / 重新连接 / 测试。测试：Task 6「第二次提示即关闭、不写第二次」、Task 8「sudo 失败锁住该连接的全部身份」「锁定跨连接池重建保留」、Task 14 实机数 sudo 日志。
2. **服务器静默断线**（网线拔掉、VPN 断开，TCP 不报错）→ 约 1 分钟内（保活 15 秒 × 3）发现，进行中的请求以 `FS_UNAVAILABLE` 结束，树显示断开，恢复后由退避探测自动重连。测试：Task 5「冻结的服务器在保活超时后关闭会话」、Task 11「远程 `FS_UNAVAILABLE` 使 `sftp://<id>` 断开，探测成功后恢复」。
3. **特殊文件名**（空格、`%`、`#`、`?`、日文、以 `.` 开头、结尾空格、`+`）→ provider、扫描进程缓存、渲染端拼接得到逐字符相同的 URI，且 `new URL(u).href === u`。测试：Task 2 往返测试、Task 4「list 的子项 URI 等于 `sftpChildUri`」、Task 10 缓存与搜索的子项 URI。
4. **首次连接时多个请求同时到达**（恢复的标签 + 展开的树 + 后台索引）→ 只弹 1 个主机密钥确认框，回答后所有请求继续；主机密钥变化时不弹框、不连接。测试：Task 8「并发的首次连接只询问一次」「密钥变化时以 CONN_HOST_KEY_CHANGED 失败且不询问」。
5. **密码含特殊字符**（`'`、`"`、`$`、`\`、空格、日文）→ 认证照常；密码不出现在命令行、错误的 `detail` 与日志中。测试：Task 6「执行的命令不含密码」「失败的 detail 中密码被替换为 `***`」、Task 9「保存失败的错误不含机密」。
