# M5 完善与发布：设计

- 日期：2026-11-23
- 状态：草案（待需求方审核）
- 依据：doc v1.27 第 14、16、18 节；[遗留事项分拣 30](./2026-11-21-30-open-items-triage.md)；[M4 合并总结 41](./2026-11-22-41-m4-summary.md)；UI/UX 设计师子代理的方案与原型 [`assets/2026-11-23-m5-design/`](./assets/2026-11-23-m5-design/)（以下简称「设计稿」）

## 1. 意图

把 M0–M4 做出来的原型推进到**可以分发给同事试用的 beta**：补上一直标着「即将推出」的入口（命令面板、设置），让应用有自己的面貌（logo、主题、带颜色的文件图标、更好的工作区切换），并清掉 beta 前已知的小缺陷。对应产品目标：第 3 条（工作区隔离案件，切换要快、不出错）、第 4 条（在一个应用里完成工作，键盘可达）、第 7 条（看起来酷）。

**非目标**：代码签名（beta 用未签名 zip；只在文档中写明签名的接入点）；自动更新（维持「解压覆盖程序目录」）；多窗口 / 应用内会话；第三方插件；FTP / 远程编辑。

**反目标**（做了也算失败）：动效抢走对文件内容的注意力、拖慢操作（任何动效都不能让用户等待才能进行下一步）；工作区切换比现在更容易误点；为了主题把插件或网页视图的可读性弄坏。

## 3. 约束

- 选型：官方推荐 / 默认优先（CLAUDE.md）；新依赖须需求方同意（`motion`、`cmdk` 均已同意）。
- 安全：CSP 不允许内联脚本（`style-src 'unsafe-inline'` 已有，motion 经 CSSOM 写样式不受影响）；不新增向页面暴露路径的通道，打开文件夹由主进程固定路径。
- shadcn 组件保持 CLI 生成的原样；新组件用 CLI 添加（用户目录含 `.`，需 `subst` 临时盘符，见 `knowledge/libraries.md`）。
- 模块边界：feature 之间不互相 import，跨 feature 的组合放在 `app/`；新目录先在 `eslint.config.mjs` 登记。
- i18n：ja / zh-CN / en 同时添加。
- 文件系统原则不变（只读）。

## 4. 方案比较

### 4.1 动效（需求方已选 A）

| 方案                                                                                            | 取舍                                                                                                                                    |
| ----------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| **A. `motion` 14.14.0（MIT，依赖 `framer-motion` 同版本与 `tslib`）**                           | 弹簧、退出动画（`AnimatePresence`）、布局动画、拖拽与惯性、`MotionConfig reducedMotion`；以后新增动效有统一手段。代价：新增依赖与包体积 |
| B. 自写（CSS 过渡 + Base UI 的 `data-starting-style` / `data-ending-style` + View Transitions） | 无依赖；圆环的拖拽 / 惯性 / 弹簧要手写，每种新动效都重新造                                                                              |
| C. react-spring 10                                                                              | MIT，物理动画好，但生态与维护势头不如 motion                                                                                            |
| GSAP                                                                                            | 非 MIT 许可（Standard no-charge license），排除                                                                                         |

做法：简单的进出场（菜单、对话框）继续用现有 `tw-animate-css`；需要物理手感、退出动画、布局变化的地方用 motion。动效 token（时长、缓动、弹簧）集中在 `packages/ui/src/motion/`，所有动效从这里取。根上用 `MotionConfig` 接「减少动效」设置（见 5.A）。

### 4.2 命令面板组件（采用 A，需求方 2026-11-23 同意引入 `cmdk`）

| 方案                                                                | 取舍                                                                                                                                                                                                                                                                                                |
| ------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **A. shadcn 官方 base-nova 的 `command`（依赖 `cmdk` 1.1.1，MIT）** | 已用 `shadcn view command` 核实：base-nova 版本基于 `cmdk`，配合本项目已有的 `dialog` / `input-group`。官方默认，样式与其他组件一致。代价：`cmdk` 依赖 4 个 Radix 小包（`react-id` / `react-dialog` / `react-primitive` / `react-compose-refs`），与 Base UI 并存；`cmdk` 最近一次发布较早（1.1.1） |
| B. 用 Base UI 的 `Autocomplete` / `Combobox` + `Dialog` 自己组      | 无新依赖、与 Base UI 一致；但不是 shadcn 的现成组件，过滤 / 分组 / 键盘要自己接，偏离「官方默认」                                                                                                                                                                                                   |

推荐 A（官方推荐优先）。`CommandDialog` 用的是项目的 Base UI `Dialog`（`role=dialog`），能被 `overlay-tracker` 识别并冻结网页视图。

### 4.3 图标文件生成（推荐 A）

| 方案                                                                                                        | 取舍                                                                                  |
| ----------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------- |
| **A. 脚本用 Electron 自身把 SVG 渲染成各尺寸 PNG（离屏窗口 `capturePage`），自写 ICO 打包（PNG 内嵌格式）** | 无新依赖；ICO 格式简单（6 字节头 + 16 字节目录项 + PNG 数据）                         |
| B. `sharp` + `png-to-ico` 等开发依赖                                                                        | 现成，但 `sharp` 带原生二进制（需 `allowBuilds`，TVM 风险），为一次性的资源生成不值得 |

生成的 `icon.ico` / `icon.png` 提交进仓库，平时构建不运行脚本，只在 logo 变化时运行。

### 4.4 主题的实现（推荐 A）

| 方案                                                                                                   | 取舍                                                            |
| ------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------- |
| **A. `<html data-theme="x">` + 每套主题一组完整变量（`[data-theme='x']` 与 `[data-theme='x'].dark`）** | 与现有 `data-accent` / `data-density` 同一机制；shadcn 组件不改 |
| B. 扩展强调色（只换 primary）                                                                          | 达不到「完整配色」的要求                                        |

强调色与主题的关系见 5.A。

### 4.5 设置页 / 关于页的承载（推荐 A，偏离 doc 14.1）

| 方案                                                                                                                   | 取舍                                                       |
| ---------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------- |
| **A. 应用内置页面标签（与工作区一览、桌面快照页同一方式：`pch-settings:` / `pch-about:`，新的 `LayoutLocationKind`）** | 与现有内置页面一致，地址栏、标签、后退前进自然可用         |
| B. doc 14.1 原写的 `internal://settings` 内部插件                                                                      | 现有内置页面都没走插件，单独为设置引入「内部插件」没有收益 |
| C. 模态对话框                                                                                                          | 设置项多（约 35 个），对话框太挤；打开时网页视图要冻结     |

采用 A 后修正 doc 14.1。

## 5. 设计

### 5.A 主题与动效基础

**主题**（需求方 2026-11-23：三套全上）。配色与可粘贴的 CSS 以设计稿 `themes.html` 为准，说明见设计稿 2 节。

| id        | ja   | zh-CN | en           | 概念                                        |
| --------- | ---- | ----- | ------------ | ------------------------------------------- |
| `default` | 標準 | 默认  | Default      | 现有 shadcn neutral                         |
| `aitetsu` | 藍鉄 | 蓝铁  | Indigo Steel | 偏「酷」：深蓝铁色底 + 冷青强调，暗色为主打 |
| `washi`   | 和紙 | 和纸  | Washi        | 护眼：纸色底 + 藍墨字，暗色为暖墨色         |
| `matsuba` | 松葉 | 松针  | Pine         | 沉静：带绿意的灰 + 松叶绿，低饱和           |

- 设置：`appearance.theme: 'default' | 'aitetsu' | 'washi' | 'matsuba'`（默认 `default`）；`appearance.reduceMotion: 'system' | 'on' | 'off'`（默认 `system`）。
- CSS：每套主题完整的 shadcn 变量（31 个），按 `[data-theme='x']` 与 `[data-theme='x'].dark` 组织，`data-theme` 放在 `<html>`；默认主题不设属性。另加扩展令牌：日志级别 `--log-*`（每主题一组）、工作区颜色 `--ws-*`、文件图标颜色 `--fi-*`（只分明暗）、标志颜色 `--logo-*`（每主题一组），并映射为 Tailwind 颜色。
- **强调色覆盖主题**（控制者决定，采纳设计稿建议）：强调色选择器改为 `:root[data-accent=y]` 并放在主题规则之后；`neutral` 表示「使用主题自己的 primary」，界面文案改为「テーマの既定」。
- **默认主题的两处对比度**（控制者决定）：亮色 `muted-foreground` 在 `muted` 上 4.34、`ring` 在白底上 2.59（shadcn 原值）——微调到 4.5 / 3.0 以上，只改这两个变量。
- 首帧：`BootstrapData` 增加 `theme`；`theme-init.js` 首帧写 `data-theme`；`window-factory.ts` 的窗口底色表按主题 × 明暗取值（避免启动闪烁）。
- `ThemeProvider` 写 `data-theme`。
- 网页视图内的 Markdown：外壳页按主题取一组颜色（主题名经 `markdown-shell.ts` 传入，`markdown.css` 按 `[data-theme]` 组织）；mermaid 用 `base` 主题 + `themeVariables`。HTML / PDF 是文件本身，不改。
- 文本预览的日志级别着色（若已有）与两处写死的琥珀色（`text/status-bar.tsx`、`web-page-preview.tsx`）改用 `--log-*` / 主题令牌。
- 插件 SDK 的 `theme` 保持 `{ mode }`，本次不扩展（插件用的是 CSS 变量，自然跟随）。

**动效**：令牌放在 `packages/ui/src/lib/motion.ts`，取值见设计稿 5 节（时长 fast 0.12s / base 0.2s / slow 0.28s，上限 0.3s；缓动 standard / enter / exit；弹簧 ring / snappy / emphasized）。根部 `<MotionConfig reducedMotion>` 按设置传入（`system` → 跟随系统、`on` → 总是减少、`off` → 不减少；具体取值名安装后按类型定义核实）。减少时取消位移，只保留 0.12s 透明度变化。

### 5.B 文件图标

完整类别表、扩展名映射、字形与 oklch 值以设计稿 `file-icons.html` 为准（页内有可替换的 `BY_EXTENSION` / `ICONS` 草稿），说明见设计稿 3 节。

- **A 级（大众认知，饱和）**：Word 蓝、Excel 绿、PowerPoint 橙、PDF 红、邮件天蓝、文件夹黄、压缩包茶色。**B 级（只区分，降饱和）**：日志（刻意低饱和青灰）、脚本、代码、配置、数据库、证书、Markdown、图片、音视频、可执行。**中性**：纯文本、未知、文件链接用 `muted-foreground`；失效链接 `destructive`。
- 类别 19 → 27：新增 `csv`、`mail`、`markdown`、`script`、`sql`、`database`、`cert`、`package`；PDF 改用 `file-type` 字形（不只靠颜色区分）；`xml` 归 config、`rtf` 归 document；轮转日志（`*.log.1`、`*.log.gz` 等）归 log；`Dockerfile` / `Makefile` / `.env` 等按全名映射。
- 颜色只分明暗、不随主题（文件类型的颜色是外部约定）；四套主题各背景上最低 3.03:1。只给描边着色，文件夹另加同色半透明填充。
- `FileIcon` 的映射改为 `{ Icon, color }`，默认带 `text-fi-*`；需要单色时（如选中行）传 `monochrome`。调用方去掉 `text-muted-foreground`。
- 统一使用 `@pch/ui/file-icon`：资源树、目录视图、工作区总览（已用），加上标签头、搜索结果、fallback 预览、命令面板、选择器详细卡片。
- 不提供「图标单色」设置（控制者决定：没有需求，以后需要再加）。
- 「打开前需确认」的可执行清单（`features/preview/executable.ts`）与图标的 `script` 类别仍是两份独立清单。

### 5.C 工作区选择器

交互规格以设计稿 1 节与原型 `workspace-picker.html` 为准（状态流程、键盘表、鼠标、筛选、无障碍都在那里），这里只写结论与对设计稿的改动。

已确定的框架：

- **两种形式由用户在设置中选择**（需求方 2026-11-23）：新的圆环轮播（默认）与现在的下拉菜单。设置键 `workspace.pickerStyle: 'carousel' | 'menu'`，默认 `carousel`。
- 标题栏的工作区切换器改为单纯按钮（显示当前工作区名与颜色标识），地址框左端的工作区按钮与它打开同一个选择器（按设置决定是哪一种）；两个入口原来各自的下拉菜单合并为一个「菜单式」组件。
- 选择器是一个 Base UI `Dialog`（`role=dialog`，网页视图随之冻结），固定在标题栏下方居中，内容为 3D 圆环轮播的卡片；圆环任何时候只显示正面 ±2 共 5 张，首尾相接。头部有「リング / リスト」视图切换（记住上次选择，不按数量自动切换；超过 12 个时提示可筛选或用列表）。
- 打开方式：标题栏按钮、地址框按钮、`Alt+W`（加入 `web/shortcuts.ts` 的 `APP_SHORTCUTS`）。打开时当前工作区在正面、焦点在筛选框；关闭后焦点回到触发按钮。
- 简要（默认）：颜色带、编号、名称、「使用中」、条目数、相对时间。详细：再加说明、前 4 个根级条目（带文件图标颜色）、绝对时间。简要 / 详细的状态记在设置 `workspace.pickerDetail`（布尔）。
- 编辑开关（琥珀色，不记忆）：正面卡片变为表单（名称、说明、颜色），即时保存；圆环末尾多一张「+」卡片用于新建；`Alt+←/→` 调整顺序；删除时卡片翻到背面确认，默认焦点在「キャンセル」；编辑模式下点击 / Enter 不切换。
- 误操作防护：只有正面卡片能切换（点击或 Enter）；点侧面卡片只转到正面；卡片刚转到正面 250ms 内点击无效；滚轮只转动；IME 变换中的按键不处理，筛选在 `compositionend` 后执行。
- **直选改为 `Alt+1–9`**（控制者决定，改设计稿的单键 1–9）：单按数字键输入筛选词，案件名常以编号开头（如「2026…」「#4128」）。编号按 sortOrder 固定。
- Esc 两级：有筛选词时先清空，再按关闭。筛选匹配名称与说明，NFKC + 小写 + 平假名视同片假名。
- 工作区 `color` 存颜色键（9 个，如 `blue`）而不是色值，色值由 `--ws-*` 令牌给出；颜色同时显示在标题栏按钮（名称前的圆点）。现有库中 `color` 列一直为空，无需迁移。
- 详细信息的数据：新增只读 IPC `workspace.summaries` → `{ id, entryCount, topEntries: { kind, label, uri? }[] }[]`，只查 `pch.db`，选择器打开时取一次。
- 菜单式（`pickerStyle: 'menu'`）：两份菜单合并为一个组件；每项加颜色圆点与相对时间；菜单打开时 `Alt+1–9` 直选；超过约 8 个时顶部加筛选框；新建 / 重命名 / 删除仍作用于当前工作区（现状，控制者决定）。
- 工作区一览页（`kind: 'workspaces'`）保留，作为完整管理页；卡片也显示颜色与描述。

### 5.D 命令面板与最近使用

**入口**：`Ctrl+K`（也接受 `Ctrl+Shift+P`），标题栏中间的搜索按钮。焦点在网页视图中时，`Ctrl+K` 与 `Ctrl+,` 也转发给应用（`web/shortcuts.ts` 的 `APP_SHORTCUTS`；本地文档很少自己用这两个键，控制者决定）。

**内容**（一个输入框，结果分组显示）：

1. 最近使用：当前工作区最近打开的文件 / 目录（最多 8 条）
2. 工作区：切换到其他工作区（按最近打开排序）
3. 命令：切换侧栏视图、新建工作区、打开设置 / 关于、切换主题与明暗、切换语言、刷新、关闭标签、全部折叠、定位到当前项……每条显示快捷键
4. 文件：输入 2 个字符以上时，用现有 `search.query`（`index.db`，只读缓存）查当前工作区的文件名，最多 20 条；选中后在资源树定位并打开（复用搜索视图的定位）

**命令注册表**：渲染端新增统一的命令注册（id、i18n 标题、快捷键、分组、`run`、可用条件）。现有分散在 `use-shell-shortcuts.ts`、`address-bar/commands.ts`、`tabs-area.tsx` 的快捷键改为从注册表分发（行为不变：有模态对话框时不处理导航键、跳过 `defaultPrevented`）。feature 通过 hook 注册自己的命令，面板只读注册表，不 import 其他 feature。

**最近使用的数据**：

- 迁移 0008 新建 `recent_items`（`workspace_id` 外键级联删除、`uri`、`kind`（file / directory）、`title`、`opened_at`；`(workspace_id, uri)` 唯一），每个工作区最多保留 100 条。
- **只记录明确的打开动作**（控制者决定）：双击 / Enter / Ctrl+单击 / 中键 / 新标签打开、地址栏输入、命令面板、搜索结果、工作区总览中的打开。资源树单击或 ↑↓ 停留的浏览式导航、目录视图里逐级经过的目录都不记录（否则键盘浏览一遍就把真正打开过的挤掉）。实现上给导航动作带来源标记（例如 `source: 'browse' | 'open'`），在 tabs-store 统一判断，不在各入口分别写记录。同一 URI 只更新时间。
- IPC：`recent.list { workspaceId, limit }`、`recent.record`、`recent.clear { workspaceId? }`；设置页提供「清除最近使用」。
- 只存本机数据库，不导出。

### 5.E 设置页

- 位置：内置页面标签 `pch-settings:`（`kind: 'settings'`），入口：活动栏齿轮、`Ctrl+,`、命令面板。

- 分区与键：
  - 一般：语言
  - 外观：主题（四套带色板预览）、明暗、强调色（「テーマの既定」+ 现有四色）、密度、减少动效（`appearance.reduceMotion`）
  - 工作区：选择器形式（`workspace.pickerStyle`：リング / メニュー）、默认显示详细信息（`workspace.pickerDetail`）
  - 资源管理器：显示隐藏文件、单击即打开（`explorer.singleClickPreview`，M1-D22 的文案在此改为易懂的说法）、文件关联（`preview.associations` 列表，可删除单条）
  - 预览：`preview.maxTextSizeMB`
  - 缓存与扫描：`cache.strategy.local/network`、`cache.activeDepth`、三层定期确认间隔、后台休息、`vfs.timeoutSec.local/network`；缓存占用与「清空缓存」（`vfs.cacheInfo` / `vfs.clearCache`，已有 IPC）
  - 远程连接：`remote.keepaliveSec`、`remote.idleDisconnectMin`、`vfs.timeoutSec.remote`、`cache.backgroundGapMs.remote`、`cache.remoteIndexIntervalMin`
  - 桌面记录：`desktop.askOnExit`
  - 隐私：清除最近使用
- 不显示：`session.restoreOnStartup`、`window.onDetachedClose`、`launcher.autoUploadRemoteEdits`、`remote.cacheSizeMB`（没有代码读取；是否删除留到 beta 前统一确认）。
- 连接池的 `keepaliveSec` / `idleDisconnectMin` / 超时经 `settings: () => ({...})` 在每次使用时读取（`container.ts:136-140`，已核实），无需改动；保活间隔在建立连接时传给 `ssh2`，已建立的连接保持原值，界面注明「新しい接続から有効」（只对保活一项）。
- 数值项用输入框 + 单位，按 schema 的 min / max 校验（与 zod 同源）。

## 8. 需求方的决定与待确认

已决定（2026-11-23）：范围（第 2 节）、不签名、不做自动更新、动效用 `motion`、选择器两种形式由设置选择（默认圆环）、logo 选 D「環」、三套主题全上。

控制者的决定（随本设计一起审核，beta 前统一确认）：

- 选择器：快捷键 `Alt+W`；直选改为 `Alt+1–9`；不按数量自动切换列表；删除用卡片翻面确认；菜单式的编辑作用于当前工作区。
- 主题：强调色覆盖主题（`neutral` → 「テーマの既定」）；默认主题两处对比度微调。
- 图标：日志低饱和、PDF 换字形；不提供「图标单色」设置。
- Logo：窗口 / 任务栏用静态版；接受中心琥珀点在浅色背景上的对比度。
- 关于页：标题栏应用标记不加菜单；标记用随主题的多色版。
- 最近使用：只记录明确的打开动作，不记录资源树的浏览式导航。
- M1-K17：只限制 UNC 路径，范围为任一工作区的条目（含 file 条目所在目录），`entry.add` 例外。
- 设置页 / 关于页用内置页面标签（偏离 doc 14.1 的 `internal://settings`，实现后修正 doc）。

已确认（2026-11-23）：4.2 引入 `cmdk`（shadcn 官方 command 组件的依赖，连带 4 个 Radix 小包）。
