## 1. 目的与背景

需求方的日常（对日保守）中，在应用里**最常需要查看或打开**的是：**Office 文件、Markdown、本地 HTML**（需求方 2026-11-20 原话）；后两者要注意**链接引用**（相对路径的图片 / 样式 / 脚本、页面之间的跳转）。本地 HTML 包括同事做的**小工具、原型**，需要执行脚本。

对应产品目标（memory「product goals」）：2「集中查看常用文件，有时要启动各种应用」、4「大部分工作在一个应用里完成」。

M1 已经完成了插件体系的骨架（`packages/plugin-sdk`、注册表与计分 `features/preview/registry.ts`、带错误隔离的 `PreviewContainer`）与 folder / fallback / text 三个插件，因此 M2 不再重建插件体系，而是在其上增加：**查看器切换、浏览器视图（HTML / Markdown）、Office 启动面板**。

## 2. 目标、非目标、反目标

### 目标

1. **查看器切换**（需求方提出）：同一文件可在多个查看器之间切换（HTML：页面 / 文本；Markdown：页面 / 文本；将来的代码查看器也能加入），候选由插件匹配规则自动得出；可设为「此扩展名总是用这个」。
2. **本地 HTML**：嵌入的真浏览器显示（需求方决定用 `WebContentsView`），脚本照常执行，相对路径的资源与页面间链接可用；允许访问外网，但本地文件只能读到所在范围内（需求方决定，5.3）。
3. **Markdown**：渲染后显示，相对路径图片 / 链接与 HTML 同一套规则；GFM 表格、任务列表、代码块、**脚注、mermaid 图**（需求方要求）。
4. **Office**：在标签中显示启动面板，按本机文件关联检测到的方式提供「只读 / 编辑 / 新建」打开（需求方决定：单击、双击都先显示面板，不直接启动）。
5. 页面中的链接与应用的标签历史一致：HTML 之间跳转进入标签历史，应用的「后退」可回到上一页。

### 非目标（本次不做，记录）

- 独立的 PDF / 图片 / 音视频插件、`pcfs://` 的通用形态（`PreviewHost.fs.readBinary` / `toResourceUrl`）：推迟。附带：若先行验证（7 节 S3）表明浏览器视图能直接显示 PDF / 图片，则把 HTML 查看器的匹配扩展到它们（几乎零成本）；否则留待以后。
- Office 的命令行开关：M2 只对 Excel 的只读使用 `/r`（5.6.1；实测 `OpenAsReadOnly` verb 以编辑模式打开，故不用）；其余开关推迟。
- 未挂载 SMB（`net use`）、FTP / SFTP 上的 Office 与远程编辑会话：M4。
- 目录视图的右键菜单「用 {appName} 打开 ▸」（doc 10.6 第 1 条）：推迟（启动面板已覆盖需求）。
- 浏览器视图的页内查找（Ctrl+F）、缩放、打印：推迟（5.3.9）。DevTools 与下载：禁用（需求方决定）。
- Markdown 的代码高亮、数学公式：不做。
- 第三方插件加载：仍为「后续」。

### 反目标（即使能用也算失败）

- 本地 HTML 的脚本能读到范围外的本地文件，或能访问应用的数据 / IPC / Node。
- 保活上限（8 个，5.3.1）之内，切换标签后原型页面被重新加载、页面状态丢失。
- 应用的菜单、对话框、提示被浏览器视图挡住而无法操作或看不到。
- 浏览器视图或 Office 联动长期持有文件句柄，妨碍用户改名 / 移动（文件系统原则）。
- 单击文件就弹出外部程序（Office 只在面板中按按钮启动）。

## 3. 约束

- **文件系统原则**（CLAUDE.md）：只读，不写不建不删不移不改名；不长期持有句柄。浏览器视图的协议处理器每次请求打开 → 读 → 关闭；Office 由用户在面板上明确操作后启动（Office 自己写文件不受本应用约束）。
- **安全**（CLAUDE.md、doc 第 15 节）：应用窗口的 `sandbox`、`contextIsolation`、CSP 不放宽；浏览器视图是独立的 webContents，单独设定（5.3.3），不加载 preload、不暴露 `window.pch`。
- **分层**（`eslint.config.mjs`）：主进程新增 `modules/web`、`modules/launcher`，模块之间不互相 import，经组合根接线；渲染端插件只经 `PreviewHost` 与外界交互（拿不到 `window.pch`）；新目录先在 `eslint.config.mjs` 登记。
- **IPC**：契约在 `packages/shared/src/ipc/contract.ts`（zod 校验），只用 `pch:invoke` / `pch:event`。
- **i18n**：新增文案 ja / zh-CN / en 同时添加；插件文案放插件自带的语言资源。
- **依赖**：新增依赖须经需求方确认（第 9 节 Q1）。
- **Windows / 企业终端**：需求方确认实际使用者的终端可以运行 PowerShell（2026-11-20）；不引入会下载可执行程序的工具。

### 5.1 查看器切换

**候选**：`registry.ts` 新增 `candidatesFor(plugins, resource): AnyPreviewPlugin[]`——所有 `scoreResource` 非 null 的插件按得分降序（同分按注册顺序），之后追加：文件时追加文本插件（若尚未在列表中；即现在的「作为文本查看」，对二进制也可用）、最后追加 fallback（文件信息）。目录：folder + fallback。工作区总览没有候选（不显示下拉）。

**选择**（`resolvePlugin` 改写）：

1. 当前位置记录了 `viewer`（插件 id）且该插件在候选中 → 用它；
2. 否则 `preview.associations[扩展名]`（小写、不带点；多段扩展名取最长匹配）指向的插件在候选中 → 用它；
3. 否则得分最高者（现有 `pickPlugin`，含 sniff 后的 textLike）；没有 → fallback。

**状态**（`packages/shared/src/layout/types.ts`）：`TabState` 与 `TabHistoryEntry` 增加可选的 `viewer?: string`；新增动作 `{ type: 'tab/viewer'; id: string; viewer: string | null }`——设置当前位置的查看器，**同时清除当前 viewState**（不同插件的 viewState 不兼容）。`tab/navigate` 到新位置时 `viewer` 不沿用；`tab/back` / `tab/forward` 恢复历史项中的 `viewer`。

**界面**：地址栏（`features/address-bar/address-bar.tsx`）右端增加下拉按钮「表示: <当前查看器名>」（shadcn `DropdownMenu` 单选），列出候选（插件的 `manifest.name` 经插件语言资源翻译），分隔线下为「.<ext> は常にこれで開く」（勾选写入 `preview.associations`，再次点击取消；无扩展名的文件不显示此项）。下拉只在候选 ≥ 2 时可用。地址栏需要知道当前标签的候选与当前查看器：由 `PreviewContainer` 计算后写入一个小的 store（例如 `stores/viewer-store.ts`：`tabId → { candidates: {id, name}[], current }`），地址栏读取并经 `tabs-store` 派发 `tab/viewer`。具体放置由实现者按现有地址栏的组合方式决定。

**SDK**：删除 `ViewAsMode`、`tabs.viewAs` / `canViewAs`，改为 `tabs.viewWith(pluginId: string): void` 与 `tabs.candidates(): Array<{ id: string; name: string }>`（fallback 插件的「作为文本查看」按钮、错误面板的「以文件信息显示」改用它们）。`TEXT_PLUGIN_ID`、`FALLBACK_PLUGIN_ID` 保留。

**优先级**：text 插件的扩展名表含 `md` / `html` / `htm`（现状），与新插件同为扩展名 3 分；markdown / html 插件以 `priority: 1` 胜出，text 仍在候选中（这正是「切换到文本」）。

### 5.2 SDK：`PreviewHost.web`

插件不直接接触原生视图。新增（`packages/plugin-sdk/src/web.ts`）：

```ts
export interface PreviewWebApi {
  /**
   * 让本标签的浏览器视图显示 uri（view：'page' 原样、'markdown' 渲染后），并贴在 element 的位置上。
   * 同一标签已有视图时复用（切换标签回来不重新加载）。返回解除函数（插件卸载时调用：只隐藏，不销毁）
   */
  attach(element: HTMLElement, uri: string, opts: { view: 'page' | 'markdown' }): () => void
  /** 页面状态（标题、加载中、加载失败、范围外被阻止等），用于插件的状态行 */
  onState(cb: (state: WebViewState) => void): () => void
  /** 在系统默认浏览器中打开（出口） */
  openExternal(uri: string): Promise<void>
}
```

宿主实现（`features/preview/web-session.ts` 一类）负责：`ResizeObserver` + 窗口缩放时把 element 的位置（`getBoundingClientRect` 的 CSS 像素；`setBounds` 的单位是 DIP——Electron 45 的 `electron.d.ts` 未写明单位，以实测为准：125% / 150% 缩放下直接用这些值，视图与占位元素逐像素对齐（台账 [24](./2026-11-20-24-m2-ledger.md) 先行验证）；宿主页面缩放为 1 时与 CSS 像素相同，**不乘 `devicePixelRatio`**；`Rectangle` 要求整数，传小数时 Electron 四舍五入，宿主应自行取整）发给主进程；监听弹出层计数切换截图（5.3.7）；地址栏刷新 / F5 → `web.reload`。

### 5.3 浏览器视图（主进程 `modules/web`）

#### 5.3.1 生命周期：每标签一个视图

- `WebViewManager` 以 **(窗口, 标签 id)** 为键持有 `WebContentsView`。插件 `attach` → 不存在则创建并加入窗口的 `contentView`，存在则更新位置并显示（URL 不同时才 `loadURL`）；插件卸载（切换到其他标签、切换查看器、导航到非网页位置）→ **隐藏**（`setVisible(false)`），不销毁。
- **保活上限 8 个（需求方决定）**：每个窗口同时存在的视图超过 8 个时，销毁最久未显示的那个（LRU，当前显示中的不参与）；该标签再次显示时重新加载（页面内的输入等状态丢失；Javadoc 一类静态页几乎无影响）。上限用常量定义，不做设置项。
- 销毁时机（控制者决定）：超出上限时（见上）；标签关闭时；标签的当前位置不再使用网页查看器时（只有当前位置的页面需要保活）；窗口关闭时全部销毁；工作区切换时与标签内容的现行处理一致（标签随工作区保留则只隐藏）。
- 渲染端通知主进程「标签已关闭 / 当前位置改用非网页查看器」：经 `web.release({ tabId })`。

#### 5.3.2 会话、协议与范围

- 会话：`session.fromPartition('persist:pch-web')`（持久化：原型的 localStorage / IndexedDB 在重启后保留）。只在这个会话上 `session.protocol.handle('pch-web', …)`；`pch-web` 在 `registerSchemesAsPrivileged` 中登记为 `standard`、`secure`、`supportFetchAPI`、`corsEnabled`、`stream: true`（与 `app` 一起，在 ready 之前）；Markdown 查看脚本用的 `pch-asset`（5.4）同样只在该会话注册。
- **范围（scope）**：`rootOf(uri)`（包含它的工作区 folder 条目中最内层的根）；不在任何 folder 条目之下（file 条目、旧数据）→ 该文件所在目录。范围编号 = `sha256(范围根 URI)` 的前 16 个十六进制字符（同一目录的源在重启后不变 → localStorage 稳定；不用条目 id：条目删掉重加 id 会变）。
- **地址**：`pch-web://<范围编号>/<相对范围根的路径，逐段 encodeURIComponent>`。例：范围根 `file://nas/案件A`，文件 `file://nas/案件A/proto/index.html` → `pch-web://3f2a…/proto/index.html`。相对路径由浏览器按层级自然解析；`..` 在 URL 规范化时不会越过主机部分，因此**天然出不了范围**。
- 主进程维护 `范围编号 → 范围根 URI` 表：`attach` 时由渲染端随 uri 一起给出范围根（渲染端已有 `rootOf`），主进程校验 uri 确在范围根之下后登记（表只在内存；M3 会话恢复时随 `attach` 重新登记）。处理器收到未登记的编号 → 404。
- 范围的已知取舍：条目若是驱动器根（`C:\`），范围就是整个驱动器（记录）。

#### 5.3.3 视图的 webPreferences 与安全

- `sandbox: true`、`contextIsolation: true`、`nodeIntegration: false`、**无 preload**、`webSecurity: true`、`session` 为上述分区、`spellcheck: false`、**`devTools: false`**（需求方决定：禁用 DevTools）。
- **下载禁用**（需求方决定）：该会话的 `will-download` 一律 `preventDefault()` 取消，状态行提示「ダウンロードには対応していません」。
- 权限请求（摄像头、通知、地理位置……）：该会话 `setPermissionRequestHandler` 一律拒绝（与默认会话相同）；剪贴板写入（原型的「复制」按钮）是否放行由实现者按 Chromium 行为核实后决定并记录。
- **全局策略的调整**：现有 `windows/security.ts` 在 `web-contents-created` 上对所有 webContents 施加「导航只允许 `rendererUrl`」与「拒绝 window.open」——会把浏览器视图的导航全部拦掉。改为：浏览器视图的 webContents 由 `modules/web` 登记并施加自己的处理（5.3.6），全局处理跳过已登记者（或按 `contents.session` 判断）。`will-attach-webview` 的拒绝保留。
- **外网**：允许（需求方决定）。子资源、子框架可加载 `http(s)`；主框架导航到外部地址则交给系统浏览器（5.3.6），视图本身不离开本地页面。
- 不为页面设置 CSP（页面原样运行）；Markdown 的响应带 CSP（5.4）。

#### 5.3.4 协议处理器（读取）

- 编号 → 范围根，路径逐段解码后拼成资源 URI，再确认仍在范围根之下（防御 `%2e%2e`、`\` 等），否则 403。
- 读取经 `VfsService`（统一超时、错误码映射、断开判定）。新增 provider 能力 `createReadStream(uri, range?)`（doc 7.1 目标接口已有，「M2 增加」）：支持 `Range`（页面里的视频 / 音频需要），流结束或请求中止时关闭句柄。**已知取舍**：页面播放视频期间持有该文件的句柄（与 D31「读取进行中」同类，记录）。
- 响应头：`Content-Type` 按扩展名查内置表（html / htm / css / js / mjs / json / map / svg / png / jpg / jpeg / gif / webp / ico / bmp / woff / woff2 / ttf / otf / mp4 / webm / ogg / mp3 / wav / pdf / txt / csv / xml / wasm 等约 30 项；未知为 `application/octet-stream`；控制者决定不引入 `mime` 包，见 Q1）；`Cache-Control: no-store`（F5 总能看到最新内容）；`Accept-Ranges: bytes`。
- 目录 → 404（目录链接在导航阶段已转给应用，5.3.6）；不存在 → 404；断开 / 超时 → 502 / 504（页面自己显示加载失败）。

#### 5.3.5 加载、刷新、失败

- `attach` 的 uri 变化 → `loadURL`；地址栏刷新 / F5 → `reload()`。
- 文件变化不自动重新加载（控制者决定：原型可能有输入中的状态），由 F5 刷新。
- 主框架加载失败（`did-fail-load`）→ 状态 `failed`（插件显示错误文案与「重试」，视图隐藏）；文件已被删除时同样显示「找不到」。

#### 5.3.6 导航与链接

主框架 `will-navigate`（以及 `will-redirect`）与 `setWindowOpenHandler` 统一经一个纯函数 `decideNavigation(url, scope, disposition)` 判定（单元测试覆盖）：

| 目标                                         | 主框架点击                                                                                                                                                                         | 中键 / Ctrl+点击 / `target=_blank` / `window.open` |
| -------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------- |
| 同范围 `pch-web://` 的文件或目录             | 阻止，向渲染端发 `web.navigate { tabId, uri }` → `tabs.navigate(uri)`（宿主 stat 判定类型，按查看器规则显示：HTML 继续在本视图、Markdown / 文本 / Office 面板 / 目录视图各自显示） | `web.openTab { uri }` → `tabs.open(uri)`           |
| 同一文档内的锚点 / `history.pushState`       | 不触发 `will-navigate`，页面自己处理（SPA 原型可用）                                                                                                                               | —                                                  |
| `file://` 绝对地址                           | 换算为资源 URI：在范围内同上；范围外阻止并提示「範囲外のファイルは開けません」                                                                                                     | 同左                                               |
| 其他范围的 `pch-web://`                      | 阻止并提示（不应出现）                                                                                                                                                             | 同左                                               |
| `http:` / `https:` / `mailto:`               | 阻止，`shell.openExternal`（视图的白名单比全局多 `http:`：内网系统常是 http，控制者决定）                                                                                          | 同左                                               |
| 其他协议（`javascript:` 以外的自定义协议等） | 阻止并记录日志                                                                                                                                                                     | 同左                                               |

子框架导航（`will-frame-navigate` 的非主框架）不拦截：页面内的 iframe 可在范围内或外网加载。

**代价（A8）**：HTML 之间跳转后视图重新加载新页面，「后退」回到上一页时同样重新加载（不保留表单输入等页面内状态；浏览器的往返缓存不可用）。滚动位置不恢复（记录）。

#### 5.3.7 遮挡：弹出层打开时换成截图

- 渲染端维护「打开中的弹出层」计数：shadcn / Base UI 的弹出层都渲染到 `document.body` 下的 portal。实现方式由实现者选择（例如 `MutationObserver` 观察 body 下带 `data-open` 的 popup / dialog 节点，或在 `packages/ui` 外层包一层计数——注意 shadcn 组件不手改样式，见 CLAUDE.md）。**显示中的 toast 也计入**（需求方决定，5.9）。
- 计数从 0 变 1：宿主 `web.freeze({ tabId })` → 主进程 `capturePage()` → 返回 PNG（data URL）→ 宿主把占位元素的背景设为该图 → 主进程隐藏视图。计数回到 0：显示视图、清除背景。截图期间约一帧的延迟可接受。
- **只因 toast 而处于截图状态时，用户点击预览区（截图）**：收起全部 toast（收纳到状态栏，5.9）并恢复视图；这次点击不转发给页面（控制者决定：截图上的点击位置与页面状态可能已不一致）。因菜单 / 对话框而处于截图状态时，点击预览区按弹出层自己的规则处理（通常是关闭菜单），关闭后计数归零即恢复。
- 拖动分栏 / 窗口缩放期间不需要截图（视图随位置同步移动即可，5.2）；若实测位置同步有明显抖动，可在拖动期间同样换成截图（实现者按实测决定并记录）。

#### 5.3.8 键盘与焦点

- 焦点在浏览器视图中时，应用的快捷键收不到。视图的 `before-input-event` 中，按应用的快捷键表（F5、Ctrl+W、Ctrl+Tab / Ctrl+Shift+Tab、Alt+← / Alt+→、Alt+↑、Ctrl+Shift+F 等，以 `use-navigation-shortcuts.ts` 等现有注册为准）匹配的按键 → `event.preventDefault()` 并作为 `web.shortcut { tabId, key }` 转给应用窗口执行；其余按键交给页面。F12 / Ctrl+Shift+I 不打开 DevTools（`devTools: false`，需求方决定）。
- 鼠标侧键（后退 / 前进）：应用已在窗口级处理（V8）；视图内的侧键经 `app-command` / `input-event` 转发——实现者核实 Electron 在 `WebContentsView` 上的行为后实现，至少保证不在视图内发生页面自己的历史导航。

#### 5.3.9 推迟的浏览器功能（记录）

页内查找、缩放（Ctrl+滚轮）、打印、右键菜单（Electron 默认无；先不提供，需要时用 `Menu.popup` 加「复制 / 全选」）。下载与 DevTools 不是推迟而是**禁用**（需求方决定，5.3.3）。

### 5.4 Markdown

- 插件 `pch.preview.markdown`：`match = { kinds: ['file'], extensions: ['md', 'markdown', 'mdown', 'mkd'], maxSize: 5 MB }`、`priority: 1`；超过 5 MB 不参与匹配（落到文本）。插件界面与 HTML 插件相同（占位元素 + 细状态行），不提供「在系统浏览器中打开」（`.md` 在浏览器中无意义）。
- **渲染位置（A6b）**：在浏览器视图中用**应用自带的可信脚本**（下称「Markdown 查看脚本」）渲染。
  1. 视图加载 `pch-web://<范围>/<路径>.md?pch-view=markdown`。协议处理器见到该查询时，返回一个固定的外壳 HTML（`<meta charset="utf-8">`、内置样式、`<script type="module" src="pch-asset://viewer/markdown.js">`），并带 CSP 响应头（见下）。文档的 URL 就是 `.md` 文件本身的位置，相对路径的图片与链接按它解析。
  2. 查看脚本以同源 `fetch` 取 `?pch-raw=1`（处理器返回原始字节，上限同 maxSize）→ 用 `@pch/text-engine` 的编码判断解码（Shift_JIS 的 Markdown 也能显示，复用 M1 成果）→ unified 管线 → 插入页面 → 若有 mermaid 代码块再渲染图。
  3. `pch-asset://` 是只在浏览器视图的会话中注册的第二个协议，只提供应用打包产物中的查看脚本及其分块（只读、固定目录、白名单路径），与用户文件完全分开。
- **依赖（需求方决定 A6）**：`unified`、`remark-parse`、`remark-gfm`（表格、删除线、任务列表、自动链接、**脚注**）、`remark-rehype`、`rehype-slug`（标题锚点，GitHub 风格 slug，日文标题可用，保证 `[見出し](#見出し)` 一类页内链接）、`rehype-stringify`、`mermaid`。均为 MIT、ESM。Markdown 中的原始 HTML 照样显示（`remark-rehype` 与 `rehype-stringify` 的 `allowDangerousHtml`；是否需要 `rehype-raw` 由实现者按输出核实）。
- **mermaid**：` ```mermaid ` 代码块渲染为图（`securityLevel: 'strict'`，主题按浅色 / 深色）；mermaid 分块只在页面含 mermaid 代码块时才加载（体积大：npm 上 v12.3.0 解压后约 124MB，含多种发行格式；打进安装包的实际增量未验证，7 节 S8）。单个图渲染失败 → 显示源码与错误信息，不影响其他内容。
- **安全**：外壳的 CSP 响应头大致为 `default-src 'self' https: data:; script-src pch-asset:; style-src 'self' 'unsafe-inline' https: pch-asset:; img-src 'self' https: data: blob:; object-src 'none'`（具体值由实现者按 mermaid 的实际需要调整并记录）。**实现（Task 8，控制者裁定）**：img-src 与 style-src 追加 `http:`（内网系统常为 http），script-src 保持只允许 `pch-asset:`；追加 `frame-src 'none'; base-uri 'none'; form-action 'none'`（不限制 frame 时 Markdown 中的 iframe 能加载并运行同源本地 HTML，违反「Markdown 中的脚本不执行」）；mermaid 不需要其他调整，见 doc 9.4 节 markdown 与台账 Task 8。效果：**只执行应用自带的查看脚本**；用户 Markdown 中的 `<script>`、`onerror=` 等内联脚本一律不执行（Markdown 是文档）。
- 主题：样式用 `prefers-color-scheme` 切换浅色 / 深色（视图跟随 `nativeTheme.themeSource`——**未验证**，7 节 S2；不成立时在查询中带 `&theme=` 并在主题变化时重新加载）。
- 链接规则与 HTML 完全相同（5.3.6）：Markdown 里的 `./other.md`、`./spec.xlsx`、`../`、外部 URL 都按表处理；脚注的回跳链接是页内锚点，页面自己处理。
- 构建：查看脚本是独立于应用渲染端的浏览器入口（建议目录 `apps/desktop/src/web-assets/markdown/`，在 `eslint.config.mjs` 登记，不得 import 应用渲染端代码；可依赖 `@pch/text-engine`）。electron-vite 增加该入口的方式由实现者核实（7 节 S9）。

### 5.6 Office（主进程 `modules/launcher` + 插件 `pch.preview.office`）

#### 5.6.1 能力检测

- 本机实测（2026-11-20）：`HKCR\.xlsx` = `Excel.Sheet.12`；`HKCR\Excel.Sheet.12\shell` 默认值 `Open`，子键 `Edit`、`New`、`Open`、`OpenAsReadOnly`、`Print`、`Printto`、`ViewProtected`；`Word.Document.12` 同样有 `Open` / `Edit` / `New` / `OpenAsReadOnly` / `ViewProtected`。`HKCU\…\FileExts\.xlsx` 下本机**没有** `UserChoice`（只有 `OpenWithList` / `OpenWithProgids`）。

- 模式 ↔ 手段（Task 9 依据先行验证 S4 的实测修订，覆盖原「`readOnly` ← `OpenAsReadOnly`」）：`edit` ← 默认 verb（存在于 verbs 时，通常 `Open`）；`newFromFile` ← `New`（实测以原文件为蓝本新建）；`protectedView` ← `ViewProtected`（实测只读，无条件显示，标注「保護ビュー」）；**`readOnly` 不再从 `OpenAsReadOnly` 推导**（实测它以编辑模式打开，出现 `~$` 文件），只有关联程序是 `EXCEL.EXE` 时经官方文档记载的 `/r` 开关提供（实测标题 `Read-Only`、无 `~$` 文件）。`LaunchOption` 用 `via: { type: 'verb'; verb } | { type: 'switch'; exe; args }` 表达（与 doc 10.3 一致）。
- **`New` verb 对 `.xlsx`（非模板）的实际行为未验证**（7 节 S4）：若不是「以该文件为蓝本新建」，则不显示「新規作成」或改标签文字，结果记录。

- **显示**：toast 保持现在的位置（右下角）；浏览器视图显示中出现 toast 时，按 5.3.7 换成截图，toast 显示在截图上方。
- **点击预览区**：只因 toast 而处于截图状态时，点击预览区 → 所有显示中的 toast 收起并**收纳到状态栏**，视图恢复（5.3.7）。
- **收纳**：状态栏（`features/shell/components/status-bar.tsx`，窗口底部、不会被视图遮挡）增加消息按钮，显示未确认消息的件数（0 件时不显示）；点击 → 把收纳的消息重新作为 toast 展开显示（此时同样换截图），再次点击预览区又收起。
- **丢弃**：toast 展开后，单条消息可向任意方向拖拽丢弃——sonner 2.0.8（现有依赖）的 `swipeDirections={['top','right','bottom','left']}`，内置最小拖动距离 45px（`SWIPE_THRESHOLD`）防误操作；关闭按钮同样丢弃。丢弃 = 已确认，从收纳中移除。
- **「未确认」的范围（控制者决定）**：被「点击预览区」收起的消息；以及 `error` / `warning` 级别、到时自动消失、用户没有拖拽或关闭过的消息。`info` / `success` 到时消失即视为已看过，不收纳。收纳只在内存中（重启清空），最多 50 条（超出丢最旧的）。
- 这套规则对整个应用生效（不只在浏览器视图显示时），实现集中在渲染端的一个消息 store 包装 `toast`（`notify`），各处现有的 `toast[type](…)` 调用改经它。阈值 45px 若需求方觉得太灵敏 / 太迟钝，sonner 不提供配置项，届时再定（记录）。
