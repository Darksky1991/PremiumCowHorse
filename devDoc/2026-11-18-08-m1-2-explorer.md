## 关键决定（执行中的裁定）

- **拖放只管理条目**：dragstart 只设自定义 MIME `application/x-pch-node`；真实节点、状态行不接受放置；系统拖入的 `dropEffect` 只用 copy / link（move 会让资源管理器移走原文件）。主进程没有任何写文件的 API。
- **监听的重建由渲染端负责**（Task 3）：监听自行失效后主进程只删除记录；渲染端收到属于当前集合的 `vfs.changed` 后重发完整集合。代价：重发时目录尚不存在则不会再自动重建（见「遗留事项」）。
- **`refetchOnWindowFocus: 'always'`**（Task 5）：全局默认 `staleTime: Infinity` 下计划写的 `true` 不会触发。
- **`app/` 不依赖 `data/`**（Task 5，lint 规则）：需要数据的组件放在 feature 中；Task 5 的占位工作区名称放在 shell feature，Task 9 用 `features/workspace` 替换。中间状态（Task 5–8）暂时没有「新建工作区」入口，已接受。
- **失效链接**（Task 2 → 6）：lstat 失败的降级链接没有 `target`，资源树按失效链接处理（不可展开）。
- **添加条目的类型**（Task 7）：真实子项的类型取自节点（目录与指向目录的链接为 folder）；系统文件先按 folder 添加，`ENTRY_KIND_MISMATCH` 时改按 file，不新增 IPC。
- **状态行**（Task 6 → 7 / 8）：不可拖动、不接受放置、没有右键菜单、F2 / Delete 无效；可被选中（错误行上 Enter = 重试）。
- **空状态的放置在范围内**（Task 7）：界面文案写着「拖到这里」，因此空状态也接受系统拖入。
- **虚拟文件拖入**（Task 7 审查 I1）：可能固定 %TEMP% 副本，需要真机验证与需求方决定，不在修复循环中处理，记入 doc 8.2 / 19 节的已知限制。
- **删除当前工作区**（Task 9）：主进程删除不改变「当前工作区」，渲染端先 `activate('default')`、成功后再删除；新建后切换失败也关闭对话框，避免重复创建。
- **重新获取失败时错误优先**（Task 10）：e2e 发现展开中被删除的目录一直显示旧列表（TanStack Query 在重新获取失败时保留旧 data，`useDirectories` 先看 data）。改为错误优先（`data/vfs.ts` 的 `directoryState`，先写失败的单元测试）。这改动了 Task 5 的代码，单独提交。

## 遗留事项

- **待需求方决定**：是否拒绝临时目录（%TEMP%）下的路径作为拖入条目——拒绝可避免固定虚拟文件的临时副本，但也会阻止把 %TEMP% 下的目录固定为条目（例如查看日志）。
- 监听：目录被删除后在原路径重建，若重建发生在渲染端重发监听集合之后，之后不再自动监听（「重试」/ F5 / 聚焦能恢复列表，但不恢复监听，直到折叠再展开）；监听在列目录请求发出约 200ms 后才建立，这段时间内的变化会漏掉。可考虑：目录查询由错误恢复为成功时重发集合。
- 审查暂缓的 minor（按主题归纳，原文见计划工作区的台账）：
  - 主进程监听：纯尾部防抖没有最长等待（持续写入时一直不通知）；防抖回调未 try/catch；以原始 URI 字符串为键（大小写不同会建两个监听）；`dispose` 后仍可建立监听、失效条目的防抖定时器未在 dispose 时清除；`vfs.changed` 广播给所有窗口；rename 后 `fs.stat` 因任何原因失败都视为失效。
  - 路径与 URI：`toFileUri` 接受 `\foo`（相对于当前驱动器）；`file://localhost/C:/x` 被当作 UNC；`fileUriToWindowsPath` 对未编码的 `#` / `?`、`localhost`、主机名大小写的处理；链接目标 stat 的任何失败都显示为失效链接。
  - 资源树：`estimateSize` 固定 28（紧凑密度下切换后未重新测量）、`getItemKey` 每次渲染新建函数、`resolveDirectoryUris` 每轮拍平整棵树；状态行 id `<id>#status` 理论上可能与名为 `x#status` 的文件冲突；无选中项时没有可见的焦点指示、没有 `aria-setsize` / `aria-posinset`；条目查询出错时视图为空；错误文案在窄侧栏中被截断（悬停显示全文）。
  - 拖放：`dragSourceRef` 只在 dragend 清除；新增条目总是追加到末尾（before / after 的画线会误导）；同一批多个文件失败时逐个提示；把选中的条目拖进折叠的分组后选择落到无关节点；`positionFromOffset` 阈值等缺少测试。
  - 菜单与对话框：Menu 键 / Shift+F10 不打开所选节点的菜单；移除按钮不是 destructive 样式（默认焦点在「取消」，安全）；对话框的目标是实时的 `active` 而非锁定的 id；删除进行中仍可取消 / Esc；`maxLength` 会静默截断粘贴；`openPath` 会直接执行 `.exe` / `.bat` / `.lnk`（计划如此，可考虑确认）。
  - 测试覆盖：资源树 store、`useWatchDirectories` 的接线无单元测试；e2e 缺少 ↑ / 边界 / F5 / 删除分组 / 固定到根部（菜单）/ 子分组 / 100 字符上限等。
  - 其他：`@renderer` 别名在 vitest 与 electron-vite 配置中重复；`SidebarEmptyState` 的 explorer 分支已无用；`explorer:title` 与 common 的键重复；欢迎页在当前工作区加载中时标题为空。
- 计划 Task 1 的「并发 move」测试不能证明事务内读取（旧代码也通过）；可补「remove 与 move 竞争」的用例。
