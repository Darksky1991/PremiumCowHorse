# M1-3 标签页与目录视图（MVP）：实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use subagent-driven-development (recommended) or executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 单窗口标签页（含预览模式）+ 最小插件体系 + folder / fallback 两个内置插件，完成「资源树 → 打开 → 查看」的最小闭环。

**Architecture:** `packages/shared` 中的纯函数 `layoutReducer` 由渲染端 zustand store 持有；`features/tabs` 负责标签栏与打开逻辑，`features/preview` 负责插件注册表、`PreviewContainer` 与 `PreviewHost` 实现；内置插件在 `plugins/builtin` 包（只依赖 `@pch/plugin-sdk` 与 `@pch/ui`）。

**Tech Stack:** React 19、zustand、TanStack Query / react-virtual、Base UI（shadcn）、Vitest、Playwright。

**Spec:** [`devDoc/2026-11-19-12-m1-3-design.md`](./2026-11-19-12-m1-3-design.md)（MVP 范围与控制者决定）；`doc/` v1.14 第 9、11、12 节。

## Global Constraints

- 原型优先（需求方 2026-11-19）：只做设计第 2 节「做」的内容；发现的问题中只有明显 / 重要的当即修，其余记录。
- 测试范围按改动判断（`CLAUDE.md`）：每个任务只跑受影响的单元测试 + typecheck / lint / prettier；动到界面时加 build 与相关 e2e 用例；全量在 M1-3 收尾时由控制者兜底。
- 文件系统原则：应用不变动文件和目录的数据；`system.openPath` 只由 fallback 插件经用户点击触发，对可执行类扩展名（设计 3.3 的列表）先确认。
- 分层（lint 强制）：feature 之间不互相 import（跨 feature 经 `stores/`）；插件只能 import `@pch/plugin-sdk` 与 `@pch/ui`；新目录 / 新包先在 `eslint.config.mjs` 登记。
- 三语文案（ja / zh-CN / en）同时添加；shadcn 组件保持 CLI 原样；Base UI 用 `render`。
- 结构变化同一提交更新 `doc/`；版本号在最后一个任务升为 v1.15。

## Review Focus

1. 预览标签复用：单击 A（预览）→ 单击 B 应替换为 B；若 A 已转常驻则 B 新开预览标签；同一 URI 已打开（常驻或预览）时只激活。→ Task 1 单元测试。
2. 关闭激活标签后激活相邻标签（右侧优先，没有则左侧），关闭最后一个显示欢迎页。→ Task 1 单元测试与 e2e。
3. 插件崩溃（组件抛错 / 懒加载失败）只影响该标签，显示错误面板并提供 fallback 出口。→ Task 2 测试。
4. 1 万项目录在目录视图中滚动流畅（虚拟滚动，DOM 行数有上限）。→ Task 3 测试。
5. 目录在标签打开期间被删除 / 断开：目录视图显示错误或断开状态，不崩溃。→ Task 3 测试。

### Task 1: 标签模型、标签栏与打开入口

**Files:** `packages/shared/src/layout/{types.ts, layout-reducer.ts}` 与测试（从 shared 的 index 导出）、渲染端 `stores/tabs-store.ts`、`features/tabs/*`（标签栏）、`features/shell`（主区域：有标签时显示标签栏 + 内容区占位，无标签时欢迎页）、`features/explorer`（单击 / 双击 / Enter 打开，经 `stores/tabs-store.ts`）、三语资源、`eslint.config.mjs`（如有新目录）、doc 11 / 12 节、`e2e/tabs.spec.ts`

**Interfaces（Produces）:**

```ts
// packages/shared/src/layout/types.ts
export interface TabState {
  id: string
  uri: string
  kind: 'file' | 'directory'
  title: string
  preview: boolean
  viewState?: unknown
}
export interface TabsState {
  tabs: TabState[]
  activeId: string | null
}
export type TabsAction =
  | { type: 'tab/open'; uri: string; kind: 'file' | 'directory'; title: string; preview: boolean }
  | { type: 'tab/close'; id: string }
  | { type: 'tab/activate'; id: string }
  | { type: 'tab/promote'; id: string }
  | { type: 'tab/navigate'; id: string; uri: string; kind: 'file' | 'directory'; title: string }
  | { type: 'tab/viewState'; id: string; viewState: unknown }
export function layoutReducer(state: TabsState, action: TabsAction, newId: () => string): TabsState
```

- `tab/open`：同 URI 已存在 → 只激活（若新请求 `preview: false` 则顺带转常驻）；`preview: true` 且已有预览标签 → 替换该预览标签（位置不变）；否则在激活标签右侧插入。`tab/navigate` 后标签转常驻。
- 渲染端 `stores/tabs-store.ts`：`useTabsStore` 包装 reducer（`open(…)`、`close(id)`、`activate(id)`、`promote(id)`、`navigate(…)`），按工作区区分（切换工作区时显示该工作区的标签集合，内存中保留，不持久化）。
- 标签栏：标题（预览标签斜体）、× 按钮、中键关闭、双击标签头转常驻、`Ctrl+W` 关闭激活标签；溢出时横向滚动；`role="tablist"` / `tab`。内容区暂为占位（显示 URI），Task 2 替换。

- [ ] **Step 1: 写失败的测试**：reducer 覆盖 Review Focus 1、2 与 navigate / promote；e2e：树单击预览复用、双击常驻、Enter 打开、× / 中键 / `Ctrl+W` 关闭、关闭最后一个回到欢迎页、`explorer.singleClickPreview` 关闭时单击只选中。
- [ ] **Step 2–4:** 失败 → 实现 → 通过（受影响的单元测试 + typecheck / lint / prettier + build + `e2e/tabs.spec.ts`）。
- [ ] **Step 5: 提交** `feat(tabs): open resources in tabs with a preview mode`

### Task 2: 插件注册表、PreviewContainer 与 fallback 插件

**Files:** `packages/plugin-sdk/src/index.ts`（补全 MVP 契约）、`plugins/builtin/`（新包：`package.json`、`tsconfig.json`、`src/index.ts` 导出内置插件列表、`src/fallback/*`）、`pnpm-workspace.yaml`（如需）、渲染端 `features/preview/*`（`registry.ts` 纯函数、`preview-container.tsx`、`host.ts`）、主区域接入、主进程 `modules/system`（恢复 `system.openPath`）、契约、三语资源、`eslint.config.mjs`、doc 9 节、e2e

**Interfaces:**

- `PreviewHost`（plugin-sdk）新增：`fs.stat(uri): Promise<FileStat>`、`fs.list(uri): Promise<DirectoryListing>`、`fs.subscribe(uri, onChange): () => void`（`vfs.changed` 时回调）、`tabs.open(uri, { preview?: boolean })`、`tabs.navigate(uri)`（替换当前标签）、`system.revealInOs(uri)`、`system.copyPath(uri)`、`system.openWithSystem(uri): Promise<void>`（宿主负责可执行类扩展名的确认）、`settings.get('explorer.showHiddenFiles')` 等只读。类型需要的 `FileStat` / `FileEntry` / `DirectoryListing` 由 plugin-sdk 自行声明或从 `@pch/shared` 类型导入（插件不能 import shared 的运行时代码；若边界规则不允许，plugin-sdk 内重新声明结构相同的类型）。
- `scoreResource(manifest, resource): number | null`（`features/preview/registry.ts`，doc 9.3 的计分：扩展名 3、MIME 精确 2、通配 1，加 priority；不匹配 null）；`pickPlugin(plugins, resource)`，无匹配 → `pch.preview.fallback`。
- `isExecutableExtension(name: string): boolean`（设计 3.3 的列表，大小写不敏感）。
- IPC `system.openPath { uri } → void`（主进程 `shell.openPath`，失败映射为错误码）。

- [ ] **Step 1: 写失败的测试**：`scoreResource` / `pickPlugin`；`isExecutableExtension`；`PreviewContainer` 中插件抛错只显示该标签的错误面板（Review Focus 3，可用 vitest + 最小 DOM 环境或抽纯逻辑测试；没有 DOM 测试工具时用 e2e 注入一个会抛错的测试插件——以不新增依赖为准）；e2e：双击文件 → fallback 显示名称 / 大小 / 时间与三个动作；对 `.bat` 点「用系统应用打开」弹确认，取消后不调用（主进程替换 `shell.openPath` 计数）。
- [ ] **Step 2–4:** 失败 → 实现 → 通过（范围同 Task 1 规则）。

### Task 3: folder 插件与扫描联动
