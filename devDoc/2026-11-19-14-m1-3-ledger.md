# M1-3 最终审查修复波（控制者裁定后）

测试范围按改动判断：受影响的单元测试 + typecheck / lint / prettier + build + 相关 e2e（folder / preview / tabs）。全量由控制者兜底。

1. **I-1 目录标签被主进程 `vfs.stat` 卡住**（`features/preview/preview-container.tsx:215-233`、`data/vfs.ts:92-97`、`main/vfs/vfs.ipc.ts:49`、`features/preview/host.ts:67-70`）。共享断开 / 无响应时，打开目录标签要等最多 10 秒后显示错误页，folder 插件的缓存优先与「已断开」状态基本到不了；每次切换标签都在主进程 stat 一次（主进程线程池风险，见 knowledge/electron.md）。裁定：
   - 目录标签不等 stat：直接用标签的 `kind` / `title` 构造 `ResourceInfo` 交给 folder 插件，由 `fs.list`（缓存优先）的错误 / offline 状态表现；
   - 目录被删除的检测不再依赖 stat：folder 视图在 `fs.list` 返回 `FS_NOT_FOUND` 时显示「找不到」；并确认目录被删除时视图能收到通知（例如扫描进程在 NOT_FOUND 时也对该目录发 `changed(uri)`，或 folder 视图订阅父目录）——选最小改动，报告说明；
   - 文件标签保留 stat，但所在共享在 reachability-store 中为 offline 时不发 stat（显示「已断开」提示与文件名），`staleTime` 改为有限值（例如 5 秒）；
   - `host.tabs.navigate(uri, hint?)` 可接受插件已有的类型提示（`'directory' | 'file'`）以省掉一次 stat；
   - e2e：模拟共享断开（沿用现有注入 `vfs.reachability` 与让 stat 超时的方式）打开目录标签，立即看到缓存列表与「已断开」；目录被删除后显示「找不到」。
   - 改正 doc 9.4 与 devDoc 14 试用说明中关于「已断开」的描述，使之与实际一致。
2. **folder 视图的刷新入口**：folder 视图不响应查询失效（恢复在线、降级模式、越过条目根的目录都不会自动更新）。加一个工具栏「刷新」按钮与 `F5`（焦点在目录视图时），调用宿主重新 `fs.list` 并发 `vfs.refresh`；doc 9.4 注明越过条目根的目录不进缓存、不自动更新。补 e2e。
3. **doc 写错**：`doc/PremiumCowHorse-架构设计方案.md:228` 仍写 folder 的 `format.ts` 有「『N 前』格式化」，改正。
4. **可执行类扩展名补充**（只增加确认，不阻止打开；需求方仍可裁剪）：追加 `.url .website .application .inf .chm .settingcontent-ms .psm1 .psd1 .ps1xml .ws .wsc .sct .vb .appinstaller .msix .appx .xll .diagcab .library-ms .search-ms .gadget`；测试同步。
