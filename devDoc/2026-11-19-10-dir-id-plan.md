# 缓存目录编号：实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use subagent-driven-development (recommended) or executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把缓存中 `entries` 对目录的引用从完整 URI 改为整数编号，缩小 `index.db`；顺带修正上一计划遗留的两个小问题。

**Architecture:** 只改扫描进程的缓存层（`scanner/cache/`）与搜索查询（`scanner/search/`）；`Cache` 的对外接口不变。遗留问题的修正在调度器内部。

**Tech Stack:** `node:sqlite`（SQLite 3.54，FTS5 trigram）、Vitest。

**Spec:** [`devDoc/2026-11-19-01-refresh-cache-design.md`](./2026-11-19-01-refresh-cache-design.md) 第 8.6 节；遗留问题见 [`devDoc/2026-11-19-09-cache-strategy-ledger.md`](./2026-11-19-09-cache-strategy-ledger.md) 末尾的 `Final: Ruling: residual` 两行。现状：`doc/` v1.13。

## Global Constraints

- 文件系统原则（`CLAUDE.md`）：应用不变动文件和目录的数据；读取时由系统自动更新的元数据不在此列。
- 缓存可丢弃：不写迁移，`CACHE_VERSION` 加 1（当前为 4）。
- `Cache` 的公开方法签名（以 URI 为参数 / 返回 URI）不变；调度器、主进程、渲染端无需改动（Task 2 的调度器修正除外）。
- `entries_fts` 的 external content / trigram / 触发器机制不变；搜索结果（`SearchHit`）字段与语义不变。
- 既有的队列查询性能测试（`EXPLAIN QUERY PLAN` 与 5 万行耗时上限）必须继续通过。
- 结构变化同一提交更新 `doc/`；最后升为 v1.14。

## Review Focus

1. 删除子树（`removeSubtree` / `removeMissing` / `prune`）后，`entries` 与 `entries_fts` 中不残留属于被删目录的行（级联删除与 FTS 触发器都要生效）。→ Task 1 测试。
2. 父目录被删后又以同一 URI 重建：新目录得到新编号，旧条目不会串到新目录下。→ Task 1 测试。
3. 搜索的范围筛选、`relativePath`、去重结果与改动前完全一致。→ Task 1 用同一组数据对比改动前后的结果。
