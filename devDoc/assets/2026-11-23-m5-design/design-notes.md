## 1. 工作区选择器

### 1.1 对控制者建议的评估

| 建议                                               | 结论       | 说明                                                                                                                                                                                                                                                                                                                              |
| -------------------------------------------------- | ---------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 点侧面卡片只转到正面，点正面 / Enter 才切换        | 采纳       | 并加一条「正面保护期」（1.5 节）：卡片刚转到正面 250ms 内点击不生效，防止「卡片滑到光标下」被连带点中。双击侧面卡片因此只会转过来、不会切换。                                                                                                                                                                                     |
| 滚轮只转动                                         | 采纳       | 累积 50px（鼠标一格 = 100px）转一格，两次之间至少 70ms；触控板的小增量会累积。滚轮永远不切换。                                                                                                                                                                                                                                    |
| 打开时当前工作区在正面                             | 采纳       | 筛选框为空、焦点在筛选框。                                                                                                                                                                                                                                                                                                        |
| ←/→ 转动、打字即筛选、1–9 直选、Esc 关闭           | 采纳并细化 | ←/→ 在筛选框里也转动（筛选词很短，不需要用方向键移动光标；Home/End/Backspace 足够）。1–9 只在筛选框为空且非编辑模式时生效，编号按 sortOrder 固定（「案件 3 永远是 3」，有肌肉记忆），卡片左上角显示编号。Esc 分两级：有筛选词时先清空，再按才关闭。IME 变换中（`isComposing` / keyCode 229）的任何按键都不处理。                  |
| 约 12 张以内最好用，更多时靠筛选、提供列表视图兜底 | 采纳并修改 | 圆环任何时候只显示正面 ±2 共 5 张（数量多也不会挤），所以「12 张」的上限不是显示问题而是**导航成本**：超过 12 张时位置指示从圆点改为「5 / 20」并提示「文字入力で絞り込み、またはリスト表示へ」。列表视图是并列的另一个视图（头部切换「リング / リスト」，记住上次选择），**不自动切换**——数量跨过阈值时界面突然变样会破坏熟悉感。 |
| 动画 200–300ms、无光晕粒子                         | 采纳       | 旋转 260ms 弹簧（无回弹），面板打开 280ms / 关闭 120ms；唯一的装饰是卡片下方一层很淡的椭圆「地面」阴影，让 3D 有落脚点。                                                                                                                                                                                                          |
| 尊重 prefers-reduced-motion 与应用内开关           | 采纳       | 应用内目前没有该开关，建议新增设置（1.9、5 节）。                                                                                                                                                                                                                                                                                 |
| 用工作区 color 作卡片标识，编辑模式可设颜色与描述  | 采纳并修改 | `color` 存**颜色键**（`blue` 等 9 个 + null），不存色值：色值随明暗变化（`--ws-*` 令牌），以后换配色也不用迁移数据。颜色同时出现在标题栏按钮（名称前的圆点）和地址框，作为「我现在在哪个案件」的提示。                                                                                                                            |
| 删除仍需确认                                       | 采纳       | 不弹出对话框，而是正面卡片翻到背面显示确认（保持上下文）；默认焦点在「キャンセル」。文案沿用现有 `workspace:deleteTitle` / `deleteDescription`。                                                                                                                                                                                  |

追加的建议：

- **快捷键 `Alt+W`** 打开 / 关闭选择器（W = Workspace）。不选 `Ctrl+Shift+W`：它紧挨 `Ctrl+W`（关闭标签），浏览器里还是「关闭窗口」，误按代价高。`Alt+W` 需加入 `modules/web/shortcuts.ts` 的 `APP_SHORTCUTS`，否则焦点在网页视图中时无效。
- **编辑模式下点击 / Enter 不切换**，页脚常驻「編集中：クリックや Enter では切り替わりません」。编辑和切换在同一界面里混用是误操作的主要来源。
- **编辑模式可排序**：`Alt+←/→` 移动正面卡片（改 sortOrder）；筛选中禁用（筛选结果的相邻关系不是真实顺序）。
- 页脚保留「ワークスペース一覧を開く」：进入现有的一览页，一览页仍是完整管理的地方。

### 1.2 两个入口、两种样式

- 标题栏的工作区按钮改为单纯按钮：`[颜色圆点] 名称`，去掉 ▼（`aria-haspopup="dialog"`、`aria-expanded`）；悬停提示「ワークスペースを選択（Alt+W）」。
- 地址框左端的工作区图标按钮打开**同一个**选择器（同一组件、同一位置：标题栏下方居中），不再各自维护一份菜单。
- 关闭后焦点回到打开它的那个按钮。

### 1.3 卡片内容：简要 / 详细

|                    | 简要（默认，204×176）                                                  | 详细（244×304）                                   |
| ------------------ | ---------------------------------------------------------------------- | ------------------------------------------------- |
| 顶部色带           | 工作区颜色（无颜色时用 border 色）                                     | 同左                                              |
| 编号               | 1–9（筛选中 / 编辑中不显示）                                           | 同左                                              |
| 使用中标记         | 「使用中」胶囊（沿用 `workspace:current`）                             | 同左                                              |
| 名称               | 16px 粗体，最多 3 行                                                   | 15px，最多 2 行                                   |
| 说明               | —                                                                      | 最多 3 行；没有时显示淡色「説明なし」             |
| 条目               | 条目数「14 項目」                                                      | 前 4 个根级条目（带文件图标颜色）+「ほか N 項目」 |
| 时间               | 相对时间「2 時間前」                                                   | 绝对时间「最終使用 2026/11/23 7:41」              |
| 底部提示（仅正面） | 「Enter / クリックで切り替え」，当前工作区为「使用中のワークスペース」 | 同左                                              |

简要模式只放「认出是哪个案件」所需的信息（颜色、名称、最近何时用过），详细模式回答「这个案件里有什么」。

**需要新增的数据**：条目数与前几个条目名需要一个只读数据库查询，例如 `workspace.summaries` → `{ id, entryCount, topEntries: { kind, label }[] }[]`（根级、按 sortOrder 取前 4）。只查 `pch.db`，不访问文件系统；选择器打开时取一次。

### 1.4 状态与流程

```
关闭 ──(按钮 / 地址框按钮 / Alt+W)──▶ 打开：浏览（圆环或列表）
  浏览 ──打字──▶ 筛选中 ──Esc──▶ 浏览 ──Esc──▶ 关闭
  浏览 ──Enter / 点正面 / 1–9──▶ 切换：正面卡片按压反馈 140ms → 面板关闭 → 标题栏更新 → toast「『x』に切り替えました」
  浏览 ──编辑开关──▶ 编辑（同一圆环，正面卡片变为表单，末尾多一张「新しいワークスペース」卡片）
     编辑 ──正面「削除…」──▶ 卡片翻面确认 ──削除──▶ 卡片收缩消失、圆环合拢、toast
                                         └─キャンセル / Esc──▶ 翻回
     编辑 ──「+」卡片 Enter / 点击──▶ 新建并转到正面，名称输入框全选
```

- 选当前工作区 = 只关闭，不做任何事。
- 编辑内容即时保存（失焦 / 名称框 Enter）；非默认工作区名称清空时还原为原名；默认工作区名称可清空（= 显示本地化默认名），保留「既定の名前に戻す」。
- 默认工作区没有删除按钮（与现状一致）。删除当前工作区后切到哪个工作区，沿用现有删除流程。

### 1.5 误操作防护（汇总）

1. 侧面卡片单击只转动，永不切换。
2. 正面保护期 250ms：卡片刚到正面（不论被点击、方向键还是滚轮转来）时点击无效。
3. 滚轮只转动。
4. 编辑模式下不切换；编辑和浏览由显式开关分开，开关为琥珀色以示「现在是另一种模式」。
5. 删除二次确认，默认焦点在取消。
6. 输入框（名称 / 说明）中的 ←→、数字、Enter 不传给圆环；Esc 只撤销该字段并把焦点还给筛选框，不关闭面板。
7. IME 变换中按键不处理；筛选在 `compositionend` 后才执行（日语输入中途不会跳动）。
8. 3D 命中测试：卡片在 z<0，会被 z=0 的容器挡住点击——原型中已踩到并修正（容器 `pointer-events: none`，卡片 `auto`），实现时注意。

### 1.7 鼠标

- 点击侧面卡片：转到正面。点击正面卡片：切换（保护期内无效）。点击位置圆点：转到该位置。
- 滚轮 / 触控板横纵滑动：转动。
- 点击面板外（遮罩）：关闭。标题栏按钮在打开时再点一次：关闭。
- 列表视图：单击行即切换（列表没有「转动」，不存在滑到光标下的问题）。

### 1.8 筛选、空状态、大量工作区

- 匹配名称与说明；规范化为 NFKC + 小写 + 平假名→片假名（全角 / 半角、ひらがな / カタカナ 视为相同）。
- 结果保持原顺序（保留位置感），最佳匹配转到正面：名称前缀 > 名称包含 > 说明包含。名称中的命中部分加下划线。
- 计数显示「3 / 20」。
- 无结果：「『xyz』に一致するワークスペースはありません」+「名前と説明を検索しています。Esc で絞り込みを解除」。
- 只有 1 个工作区（只有默认）时圆环只有一张卡，←→ 无效；仍可进入编辑模式新建。
- 大量（>12）：见 1.1；列表视图最大高度与圆环区域相同，可滚动。

### 1.9 无障碍

- 面板 `role="dialog"`、`aria-modal`、隐藏标题「ワークスペースを選択」；关闭时焦点还原到触发按钮。
- 筛选框 `role="combobox"`，`aria-controls` 指向圆环（`role="listbox"`、`aria-orientation="horizontal"`）或列表（`listbox` 纵向），`aria-activedescendant` = 正面卡片 / 选中行；卡片 `role="option"`、`aria-selected`，`aria-label` 含编号、名称、「使用中」、最终使用时间。
- 转动时 `aria-live="polite"` 播报「3 / 8、物流WMS 障害対応 #4128（使用中）」。
- 侧面（±1、±2）卡片 `aria-hidden="false"`，其余 `true`。
- 焦点环：`ring` 变量，2px；颜色开关、视图切换都可用键盘操作。
- 减少动效：`prefers-reduced-motion: reduce` 或应用内设置开启时，旋转与翻面取消（瞬间到位），只保留 120ms 透明度过渡；建议新增设置 `appearance.reduceMotion: 'system' | 'on' | 'off'`（默认 `system`）。

### 1.10 选择器样式设置：圆环 / 菜单（第 2 版追加）

**设置**：`workspace.pickerStyle: z.enum(['carousel', 'menu']).default('carousel')`，放在设置页「外観」或「ワークスペース」分组；三语名称：

| 值         | ja       | zh-CN | en       |
| ---------- | -------- | ----- | -------- |
| `carousel` | リング   | 圆环  | Carousel |
| `menu`     | メニュー | 菜单  | Menu     |

**入口行为一致**：标题栏按钮、地址框按钮、`Alt+W` 三个入口都打开**当前设置所选**的那一种；两种样式共用同一份数据与操作（切换、新建、重命名、删除、颜色），只是呈现不同。菜单式锚定在触发它的按钮下方（下拉菜单的惯例），圆环固定在标题栏下方居中。

**菜单式的小改进（建议，未做原型）**：

1. **合并两份菜单**：现在标题栏菜单有新建 / 重命名 / 删除、地址框菜单只有「管理…」，两者内容不同。合并为同一个组件，两个入口内容一致。
2. **颜色圆点**：每项名称前显示工作区颜色（与标题栏按钮一致），无颜色显示空心圆。
3. **次要信息**：每项右侧淡色显示相对时间「2 時間前」（与圆环的简要信息一致）；详细信息不放进菜单，菜单要保持一行一项。
4. **1–9 直选**：菜单打开时数字键直接切换，项右侧显示编号（Kbd）。
5. **筛选**：工作区超过约 8 个时，菜单顶部加一个筛选框（行为同 1.8，含 IME 处理）。Base UI Menu 自带的按首字母跳转（typeahead）对日文名不实用；是否与筛选框冲突需对照 Base UI 文档核实（未验证）。
6. **编辑操作**：保留在菜单底部（新規 / 名前の変更 / 削除…），但作用对象改为「当前选中项」而不是「当前工作区」更直观——需要子菜单或每项右侧的「…」按钮；若改动过大，保持现状（只对当前工作区操作）即可。
7. 颜色与说明的编辑仍在一览页（菜单里不放表单）。

## 2. 配色主题

### 2.1 方案

| id        | ja   | zh-CN | en           | 概念                                                                                                                            |
| --------- | ---- | ----- | ------------ | ------------------------------------------------------------------------------------------------------------------------------- |
| `default` | 標準 | 默认  | Default      | 现有 shadcn neutral，不改                                                                                                       |
| `aitetsu` | 藍鉄 | 蓝铁  | Indigo Steel | **偏「酷」**：深蓝铁色底（hue≈256）+ 冷青强调（暗色 primary `oklch(0.8 0.12 212)`）。暗色为主打，侧栏比正文更深一级，给出层次。 |
| `washi`   | 和紙 | 和纸  | Washi        | **护眼**：生成色纸底（hue≈85）+ 藍色墨字与强调；暗色是暖墨色（不是蓝黑），降低蓝光与眩光。强调色故意用藍而不是赤陶色。          |
| `matsuba` | 松葉 | 松针  | Pine         | **沉静**：带绿意的灰 + 松叶绿，低饱和；暗色深苔灰。                                                                             |

命名取日本传统色名：对日运维人员熟悉，三语都容易念。

### 2.2 结构与接入

- 每套主题提供完整的 shadcn 变量集（background … sidebar-ring，共 31 个），按 `[data-theme='x']` 与 `[data-theme='x'].dark` 组织；`data-theme` 与 `.dark` 都放在 `<html>` 上。默认主题不设属性。
- 设置：`appearance.theme: z.enum(['default', 'aitetsu', 'washi', 'matsuba']).default('default')`，ThemeProvider 设置 `data-theme`。
- **与强调色的关系**：`[data-theme=x].dark`（0,2,0）优先级高于现有的 `[data-accent=y]`（0,1,0），暗色下主题的 primary 会盖过强调色。建议：强调色选择器改为 `:root[data-accent=y]`（0,2,0）并放在主题之后——用户显式选了强调色就覆盖主题；`neutral`（默认）表示「使用主题自己的 primary」。界面上把强调色的 neutral 选项文案改为「テーマの既定」。
- **扩展令牌**（themes.html 的 CSS 中一并给出，并映射为 Tailwind 颜色）：
  - `--log-error / --log-warn / --log-info / --log-time`：日志级别着色，每套主题各一组，文字对比度 ≥ 4.5。
  - `--ws-*`：工作区颜色 9 个（只分明暗）。
  - `--fi-*`：文件图标颜色（只分明暗，第 3 节）。
  - `--logo-*`：标志颜色（每套主题一组，第 4 节）。

### 2.3 对比度（页内实算）

## 3. 文件图标

### 3.1 原则

- **A 级（饱和，大众认知）**：Word 蓝、Excel 绿、PowerPoint 橙、PDF 红、Outlook 天蓝（邮件）、黄色文件夹、茶色压缩包。
- **B 级（降饱和，仅区分）**：没有共识的类别（日志、脚本、代码、配置、数据库、证书、Markdown、图片、音视频、可执行），色相避开 A 级。日志刻意低饱和——它是运维最常见的文件，饱和色会让整棵树花掉。
- **中性**：纯文本、未知、文件链接 = 主题 `muted-foreground`；失效链接 = `destructive`。
- 颜色**只分明暗、不随主题**：文件类型的颜色是外部世界的约定，换主题不该变；已逐一核对四套主题的背景 / 侧栏 / 选中行 / 卡片，最低 3.03:1（文件夹在和紙亮色的选中行上）。
- 只着色描边；**文件夹额外加同色半透明填充**（lucide folder 是单一闭合路径）。其他 file-* 图标外形被拆成多段路径，填充会残缺，不加。

### 3.2 类别变化（19 → 27）

| 变化 | 类别                                                                                                                                                                            |
| ---- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 新增 | `csv`（由 spreadsheet 拆出）、`mail`、`markdown`（由 text 拆出）、`script`（由 code / executable 拆出）、`sql`、`database`、`cert`、`package`、`audio` / `video` 保持分开但同色 |
| 调整 | `pdf` 字形改为 `file-type`（现状与 text 同为 file-text，只靠颜色不够）；`xml` 由 code 移到 config；`rtf` 由 text 移到 document；`js` 留在 code；`reg` 留在 executable           |
| 规则 | 轮转日志（`*.log.1`、`*.log.2026-11-01`、`*.log.gz`）归 log；`Dockerfile` / `Makefile` / `.env` / `.gitignore` 等无扩展名文件按全名映射                                         |

完整扩展名、颜色（oklch 明 / 暗）、字形与对比度见 `file-icons.html`，页内有可直接替换的 `BY_EXTENSION` 与 `ICONS` 草稿。`script` 与渲染端的「打开前需确认」清单（`features/preview/executable.ts`）仍是两份独立清单，本次只决定图标。

### 3.3 实现建议

- `FileIcon` 的 `ICONS` 改为 `{ Icon, color }`，默认带颜色类（`text-fi-*`）；调用方需要单色时（例如选中行用前景色）传 `monochrome`。
- 失效链接的 `cn(className, 'text-destructive')` 逻辑保留。

### 4.2 随主题自适应的规则

每个 SVG 的颜色写成 `style="fill: var(--logo-xxx, #静态色)"`：

- **内联到页面**（标题栏标记、关于页）时取主题令牌 `--logo-*`，随主题与明暗变化；
- **作为文件单独使用**（`<img>`、栅格化为 .ico / .png）时外部变量不存在，取逗号后的静态色 = 静态版。

一个文件同时是自适应版和静态版，不需要维护两份。令牌（每套主题明暗各一组，`logo.html` 底部有完整 CSS）：

| 令牌                                                | 规则                                                                  |
| --------------------------------------------------- | --------------------------------------------------------------------- |
| `--logo-base`                                       | 主色 ≈ 主题 primary（暗色取 primary 的亮色版）；默认主题为墨黑 / 近白 |
| `--logo-base-2`                                     | 主色深一级（渐变终点、交叠处）                                        |
| `--logo-mid`                                        | 主色与背景之间（次要笔画 / 色块）                                     |
| `--logo-soft`                                       | 靠近背景的浅色（后层卡片、飞白）                                      |
| `--logo-ink`                                        | 主色上的反白                                                          |
| `--logo-accent`                                     | 焦点色：琥珀；**和紙主题改为朱色**（印章）                            |
| `--logo-deep` / `--logo-rim` / `--logo-ink-on-deep` | 方案 C 的深色底板、内描边、底板上的笔画                               |

自适应版的主色在各主题侧栏底色上 ≥ 3:1。焦点色（琥珀）在亮色侧栏上约 2.5:1，低于 3:1：它是小面积点缀，标志的轮廓由主色承担，判断可接受（列为开放问题）。

### 4.3 静态版与系统图标

| 位置                                   | 能否随主题                          | 建议                                                                                                                                                                                                                                                                                      |
| -------------------------------------- | ----------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| exe 文件图标（资源管理器、任务管理器） | 不能（打包时写入的 ico）            | 静态版。ico 需含 16 / 20 / 24 / 32 / 40 / 48 / 64 / 256；印象派方案 16–24 用简化版。                                                                                                                                                                                                      |

### 4.4 牛头系列（第 3 轮）

需求方反馈：围绕「牛马」，用更形象的简约牛头。六个方案都满足「角 + 耳 + 口鼻」三个特征，沿用第 4.2 节的令牌机制（内联随主题、文件即静态版），无文字。共用的幽默点是**琥珀色耳标**：牛的耳标 = 打工人的工牌（J、K、L、N 带耳标；M 用金色马蹄铁，O 本身就是工牌）。

| 方案        | 方向          | 寓意（一句）                                                            | 适用场景                                       | 16px 处理                                                             |
| ----------- | ------------- | ----------------------------------------------------------------------- | ---------------------------------------------- | --------------------------------------------------------------------- |
| J「牛面」   | 正面对称几何  | 弯角、平伸的耳、宽口鼻，右耳挂耳标                                      | 标题栏、关于页（无底板，随主题最自然）         | 原图；眼睛只剩 1px，靠角 + 耳 + 口鼻轮廓辨认                          |
| K「一筆牛」 | 单线 / 一笔画 | 一笔从左角画到右角，顺势勾出脸与口鼻                                    | 标题栏（与 lucide 线性图标同一语言）、单色场合 | 原图；线宽 2.6/32 ≈ 1.3px，可读但偏细                                 |

| M「牛馬」   | 马的暗示      | 牛角由一只马蹄铁充当（臂上有钉孔、末端有踵），金色马蹄铁 = 「高级」牛马 | 关于页、宣传场合（故事性最强）                 | 原图；16px 下马蹄铁读作「金色的角」，马蹄铁的细节要 32px 以上才看得出 |
| N「文牛」   | 工作区意象    | 文件夹就是牛脸：文件夹长出角和耳                                        | 想强调「文件管理器」身份时                     | 原图；文件夹标签与角在 16px 可辨                                      |
| O「社員証」 | 自嘲          | 挂绳上的工牌，照片是一头牛，头衔行是琥珀色（= 高级）                    | 关于页、启动画面等有空间的地方                 | **`logo-o-16.svg`**：去掉照片栏与姓名行，牛头直接反白画在工牌上       |

静态版在深 / 浅任务栏上：L、O 有底板，轮廓最稳；J、K、N 主体取中等明度蓝，两种任务栏上都在 3:1 以上；M 的马蹄铁用较深的琥珀（#e8a21f），在浅色任务栏上偏弱，轮廓主要靠蓝色牛脸。

**推荐**：

1. **L「影牛」+ J「牛面」作为一套**（首选）。两者是同一个几何牛头：L 带底板，用于 exe、窗口 / 任务栏图标和关于页（底板在任何任务栏上都有完整轮廓，16px 最清楚）；J 去掉底板，用于标题栏左端（内联、随主题变色，和标题栏背景融为一体）。一个造型、两种用法，品牌一致。
2. **N「文牛」**（备选）：如果更想突出「这是一个文件管理器」，文件夹 + 牛角把产品功能和「牛马」放在一个图形里；幽默感比 O 收敛，放在公司电脑上更稳妥。

O「社員証」幽默感最强，但细节多、需要两套图（大图 / 16px 简化版），更适合关于页或启动画面里的插画，而不是应用图标本身。

### 4.5 制作注意

- 颜色用十六进制作为静态色，便于栅格化工具处理（oklch 支持不一）。
- **SVG 注释里不能出现两个连续的连字符**（XML 规则）：浏览器内联时宽容，但作为 `<img>` 或交给转换工具会整个解析失败。本次已踩到并修正。

## 5. 动效令牌（motion/react）

| 令牌                | 值                                                     | 用途                                          |
| ------------------- | ------------------------------------------------------ | --------------------------------------------- |
| `duration.instant`  | 0                                                      | 减少动效时的位移                              |
| `duration.fast`     | 0.12s                                                  | 悬停、按压、开关、小元素淡入淡出              |
| `duration.base`     | 0.2s                                                   | 菜单 / 弹出层 / 提示 / toast、交叉淡入        |
| `duration.slow`     | 0.28s                                                  | 对话框、选择器面板进入、卡片翻面（上限 0.3s） |
| `ease.standard`     | `[0.2, 0, 0, 1]`                                       | 屏幕内的状态变化                              |
| `ease.enter`        | `[0.05, 0.7, 0.1, 1]`                                  | 进入（减速）                                  |
| `ease.exit`         | `[0.3, 0, 0.8, 0.15]`                                  | 退出（加速），时长取进入的 0.6–0.7 倍         |
| `spring.ring`       | `{ type: 'spring', visualDuration: 0.26, bounce: 0 }`  | 圆环旋转                                      |
| `spring.snappy`     | `{ type: 'spring', visualDuration: 0.18, bounce: 0 }`  | 列表重排、布局变化                            |
| `spring.emphasized` | `{ type: 'spring', visualDuration: 0.3, bounce: 0.1 }` | 仅用于「一个时刻」（选择器打开时卡片展开）    |

- 放在 `packages/ui/src/lib/motion.ts`，全部动效从这里取。
- 减少动效：根部 `<MotionConfig reducedMotion=...>` 按设置传入（`system` → `'user'`、`on` → `'always'`、`off` → `'never'`）；减少时 fast = 0、base / slow = 0.12s，只保留透明度。
- **未验证**：`motion` 尚未安装，`visualDuration` / `bounce` 弹簧参数与 `MotionConfig` 的 `reducedMotion` 取值来自记忆，安装后须对照 `node_modules/motion` 的类型定义核实。原型用 CSS `cubic-bezier(0.22, 0.9, 0.24, 1)` 260ms 近似 `spring.ring`。
